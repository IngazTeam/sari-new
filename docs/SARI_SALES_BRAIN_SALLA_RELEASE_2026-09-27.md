# حماية تحديث سلة والتراجع عن الإصدار

استكمال B070 من خطة مخ ساري والمبيعات، 27 سبتمبر 2026، فوق `68bc76b7` وعلى `main`. أصبح البند **جزئيًا**: أُنجز حارس التوافق وتمرين فشل محلي، وبقي تمرين التشغيل الفعلي والتسوية الشاملة للعمليات غير المحسومة. حالة الخطة: **4 مكتملة / 62 جزئية / 5 مفتوحة**؛ لا اعتماد 10/10.

## المشكلة والإصلاح

تربط الإصلاحات السابقة طلبات سلة ومنتجاتها بالمتجر، وتحفظ محاولة إنشاء الطلب قبل POST. حارس النشر السابق كان يتحقق من عقود زد والصوت فقط؛ لذلك كان يمكنه إعادة تشغيل كود قديم يقرأ معرفات سلة الرقمية أو ينشئ طلبًا دون سجل المحاولة الدائم. وجود جداول إضافية وحده لا يجعل هذا التراجع متوافقًا.

أُضيفت ثلاث قدرات إلزامية إلى العلامة القائمة `scripts/zid-order-store-capability.json`، مع إبقاء اسمها ومسار الحارس لتوافق أدوات النشر:

| القدرة | العقد الذي يجب أن يفهمه الإصدار |
|---|---|
| `salla-order-store-identity-0137` | هوية الطلب بحسب النشاط والمتجر، ومرجعية الاتصال قبل تحديثه أو الإشعار عنه |
| `salla-order-creation-0138` | محاولة إنشاء دائمة تمنع إعادة POST عند إعادة الطلب أو غموض النتيجة |
| `salla-catalog-store-identity-0139` | كتالوج موثق بحسب المتجر، والتحقق من اختيار المنتجات قبل الإرسال |

1. **فحص المرشح أولًا:** غياب قدرات الإصدار الجديد يوقف المسار قبل إيقاف PM2 أو تشغيل الترحيل.
2. **فحص العمليات الفعلية:** مسارا التحديث والنشر يفحصان مجلدات الويب والعامل وملفات تشغيلهما من PM2. وجود ويب حديث مع عامل قديم، أو مسار تنفيذ مختلف، يستلزم إيقاف الزوج قبل DDL؛ لا يكفي رابط الإصدار أو مجلد محفوظ سابقًا.
3. **إيقاف مؤكد ومحفوظ:** لا يبدأ الترحيل حتى يصبح كل كاتب مُدار متوقفًا دون PID حي، وتنجح `pm2 save`. فشل الإيقاف أو قراءة الحالة أو حفظها يمنع الترحيل. الخدمات الأخرى لا تُوقف.
4. **حارس من النسخة المعدّة:** تفعيل الإصدار والتراجع يقرآن الحارس من نسخة النشر التي بُنيت وفُحصت، وليس من checkout قد يتغير أو من الإصدار السابق الذي يريد السماح لنفسه.
5. **عدم إخفاء فشل PM2:** صار مسار النشر العام يعيد الفشل صراحةً عند تعطل إعداد مجلد logs أو `startOrReload` أو حذف الويب أو إعادة إنشائه. هذا ضروري لأن Bash يعطل بعض آثار `errexit` داخل دالة مستدعاة في شرط التراجع؛ نجاح فحص لاحق لا يمحو فشل الأمر السابق.
6. **استمرار مسار التعافي المتوافق:** يمكن استكمال التحديث من الإصدار القديم المتوقف، ويمكن الرجوع إلى إصدار يملك جميع العقود المطلوبة. يبقى رمز فشل النشر الأصلي محفوظًا حتى بعد استعادة إصدار متوافق؛ لا يُطبع `DEPLOY_OK` للتراجع.

أُدرجت اختبارات الانتقال في المُحدّث الحالي وفي `test:tooling` الذي تستخدمه بوابة النشر العامة.

## التحقق المحفوظ

نجحت [بوابة الأدلة](./audits/sales-brain-implementation-2026-09-23/salla-release-transition-verification.json) على نسخة مستقلة وثابتة، تضم الكوميت السابق وهذه التعديلات فقط. تعديلات الواجهة المتزامنة في مساحة العمل بقيت خارج النسخة المختبرة والكوميت.

| الفحص | النتيجة |
|---|---|
| أدوات النشر وحراس التوافق وتمارين Bash | 116 ناجحة |
| انحدار سلة والأمن وعقد المخطط والنشر | 131 ناجحة |
| المجموع | **247**، دون فشل أو تخطٍّ |
| TypeScript | ناجح |
| مفاتيح الترجمة | 7,657 استدعاء و248 مفتاحًا ديناميكيًا؛ بلا أخطاء |
| بناء الويب والعامل وحد حزمة المتصفح | ناجح |
| بصمات المصدر قبل الفحص وبعده | متطابقة |

شغّلت الاختبارات دوال Bash المشحونة فعلًا، وحارس Node الفعلي، مع بدائل محلية لـPM2 والترحيل والجاهزية. تشمل حذف كل قدرة منفردة، مستند علامة تالفًا، مسار تشغيل مزورًا، عاملًا قديمًا مخفيًا خلف ويب حديث، مسارات فيها مسافات ومحارف shell، تعطل الإيقاف والحفظ وإعادة التشغيل، PID يبقى حيًا، فشل الترحيل، استكمال إصدار متوقف، وفشل التراجع إلى إصدار غير متوافق. فُحص استمرار التراجع المتوافق أيضًا. ملف بيانات صناعي ظل محفوظًا أثناء تمرين رفض التراجع؛ هذا ليس تمرين استعادة قاعدة بيانات.

الأداة: `node scripts/testing/verify-salla-release-transition.cjs` باستخدام Node `22.23.2` وpnpm `10.4.1` الخاصين بالمشروع. تحفظ أسماء الحالات والبصمات والسجلات، وتزيل إعدادات الإنتاج وتحجب الشبكة الخارجية. لا قاعدة إنتاج أو PM2 فعلي أو API للمزوّد في هذا الفحص. أُصلح خطأ صياغة في مشغّل الاختبارات واختلاف مسافة في قارئ سجلها أثناء التطوير؛ الدليل المنشور هو الجولة النهائية الناجحة.

## التشغيل وحدود التراجع

- لا مهاجرة جديدة؛ يبقى السجل 140 ترحيلًا. لا تغيير لأسعار أو بيانات سلة أو مفاتيح الترجمة أو اختيار OpenAI/ZahyPi أو سقف 100 دولار يوميًا.
- أول انتقال من إصدار يفتقد العلامات الجديدة، بما فيه `68bc76b7`، يوقف الويب والعامل بعد التحضير والنسخ الاحتياطي وقبل الترحيل. يتضمن ذلك انقطاعًا خلال الترحيل والفحوص والتفعيل. النشرات اللاحقة بين نسختين متوافقتين لا تحتاج هذا الإيقاف الإضافي.
- عند فشل الترحيل بعد الإيقاف، احتفظ بالبيانات والعمليات المتوقفة واستكمل بإصدار متوافق. عند فشل تفعيل جزئي قد تبقى عمليات من الإصدار الجديد؛ افحص حالتها قبل الاستكمال، ولا تفترض أن الزوج كله متوقف أو مستعاد.
- لا تُعدّل علامة إصدار قديم لتمرير الحارس، ولا تحوّل معرفات `salla:<store>:<id>` إلى أرقام قديمة، ولا تحذف سجلات محاولات الإنشاء أو تسوّي `review` بإعادة POST. العلامة تصريح توافق داخل إصدار موثوق، وليست توقيعًا أمنيًا ضد مشغل يملك تعديل ملفات السيرفر.
- الحارس يغطي زوج PM2 المدارين في ملف التشغيل فقط. أي كاتب مستقل أو خادم إضافي يحتاج إيقافًا وتحققًا ضمن نافذة الانتقال؛ لا يُفترض اكتشافه تلقائيًا.
- تبقى «المزامنة الكاملة» لسلة بعد النشر لازمة لتوثيق المنتجات التاريخية. حارس النشر لا يجريها ولا يمنح البيانات القديمة هوية بالتخمين.

أمر السيرفر الحالي محفوظ كما هو في [دليل النشر](./PRODUCTION_RELEASE_RUNBOOK.md). لا push ولا نشر ضمن هذه الدفعة.

## المتبقي

تمرين تحديث وتراجع على ملف السيرفر الفعلي، وتسوية العمليات الخارجية غير المحسومة بأدلة المزوّد، وحماية بقية عقود الإصدارات غير المتوافقة عند ظهورها. وفي مسار بيع سلة: الاتفاق النهائي وموافقة العميل، الضرائب والشحن والخيارات، منع معرفَي عملية لموافقة واحدة، صندوق إشعارات إنشاء دائم، وإسناد النتيجة المالية. القبول الحي والتقييم التجاري للمخ يظلان مطلوبين.
