# استبدال الاختيار بعد حسم محاولة سلة معلّقة

استكمال B036 وB037 وB041 فوق `5b9477c9`، في 28 سبتمبر 2026.

## المشكلة والسلوك الناتج

كان اتفاق سلة بحالة `unknown` يمنع عرض اختيار جديد إلى أجل غير محدد، حتى بعد استعادة سلته والتحقق منها، أو رفض تجهيزها قبل الاتصال بالمزوّد. انتهاء صلاحية الاختيار أو رفضه لاحقًا لم يرفع هذا التعطيل. مسار استئناف الرابط السابق يعالج إعادة رابط الاختيار نفسه فقط، ولا يعالج تغيير المنتجات أو الكميات.

أصبح طلب شراء أو تعديل صريح جديد يستطيع استبدال الاتفاق محليًا عندما يثبت سجل العملية أنها انتهت إلى `ready`، أو رُفضت قبل بدء التنفيذ الخارجي `rejected`. يُعرض ملخص جديد ويحتاج إلى التسليم وموافقة جديدة قبل تجهيز أي سلة جديدة. لا تُستعار الموافقة السابقة لتنفيذ الاختيار الجديد.

لا يتصل تجهيز الملخص البديل بسلة: لا GET ولا POST ولا حذف. تبقى السلة القديمة وسجلها كما هما؛ إنهاء الاتفاق محليًا لا يلغي رابطًا داخل سلة ولا طلبًا أو دفعة. يبقى `execution_state='unknown'` في الاتفاق القديم بوصفه سجلًا تاريخيًا، مع `status='expired'` ودليل الاستبدال، وليس ادعاء نجاح بيع أو إلغاء خارجي.

## شروط قبول الاستبدال

- أحدث اتفاق يخص النشاط والمحادثة ورقم العميل نفسه، ومزوّده `salla_cart` وحالته `unknown`. العملية `processing` تبقى ممنوعة ولو ظهر سجل سلة جاهز.
- رسالة جديدة محفوظة وحديثة من العميل، تحمل طلب شراء صريحًا أو تعديلًا للاختيار. «نعم»، وطلب الرابط، والاستفسار، والرفض لا تُنهي اتفاقًا معلّقًا عبر هذا المسار.
- تطابق المالك وإصدار انتقال المحادثة للموظف، والمصدر والموافقة ومحاولة التنفيذ، وهوية اتصال سلة ومتجرها. انتقال الملكية أو تدخل الموظف أو ظهور رسالة أحدث يمنع الاعتماد.
- سلامة الاختيار الأصلي وإيصالات تسليم ملخصه الكامل قبل الموافقة الأصلية. لا تكفي علامة `[SC-id]` أو وجود رقم سلة.
- غياب نتيجة مالية أو رقم طلب خارجي أو تسوية سابقة عن الاتفاق المجهول. لا يعيد هذا المسار تفسير أدلة مالية أو تسوية قائمة.
- سجل عملية بنفس النشاط والمالك ومعرّف الطلب وبصمة المنتجات، ومحاولة تنفيذ صحيحة. السجل المفقود أو `preparing` أو `dispatching` أو `review` لا يفوّض الاستبدال.
- إذا كانت العملية `ready`، تتطابق لقطة السلة ونقطة حفظ مرجعها ودليل استعادتها عند وجودهما، وتُفحص النتيجة المخزنة والرابط والمتجر والمنتجات والكميات والعملة والمبلغ. لا تُقبل نتيجة أُعيد حساب بصمتها لكنها تخالف الاختيار أو نطاق رابط المتجر.
- إذا كانت `rejected`، يجب غياب اللقطة والنتيجة تمامًا؛ الكود لا يسجل الرفض إلا قبل بدء التنفيذ. وجود دليل خارجي يناقض هذا الحد يمنع الاستبدال، كما يرفض قيد قاعدة البيانات نتيجة مكتملة داخل عملية مرفوضة.

الكتالوج الحالي يفوّض الاختيار الجديد بصورة مستقلة. لا يُشترط استمرار سعر الاختيار القديم أو توافره، لأن الدليل القديم تاريخي ولا يُعاد إرساله أو تنفيذه. انتهاء صلاحية الاتفاق القديم أو وجود رفض بعد موافقته الأصلية لا يمنع عرضًا جديدًا عندما تكون العملية قد حُسمت وطلب العميل اختيارًا جديدًا صراحة.

## الحفظ والتزامن والإرسال

قفل الاتفاق وصلاحيات المصدر والكتالوج وسجل العملية يستمر خلال المعاملة المحلية التي تنشئ الملخص الجديد وتُنهي الاتفاق القديم. يحفظ `external_reconciliation` سجلًا بإصدار `salla-cart-supersede.v1` يربط الاتفاقين ورسالة الطلب الجديدة والمصدر والموافقة الأصليين والمالك وإصدار المحادثة وبصمات الاختيارين ودليل التسليم وسجل السلة وتوقيت الاستبدال. يتضمن صراحة أن الإلغاء الخارجي لم يُنفذ. لا ترحيل قاعدة بيانات جديد.

إذا فشلت كتابة دليل الاستبدال تتراجع المعاملة كلها. وإذا نجح commit وضاع تأكيده، فإن تكرار معالجة رسالة العميل نفسها يعيد الملخص المحفوظ، دون عرض إضافي أو سلة إضافية. تتقارب الطلبات المتزامنة لنفس الرسالة على ملخص واحد. مصدر الموافقة القديم أو رد قديم في outbox لا يستطيع تشغيل الملخص الجديد أو إرسال الرابط القديم.

تستمر بوابات التسليم والموافقة المعتادة للملخص الجديد، بما فيها اشتراط إيصالات تسليم نصه الكامل. لا يكفي إيصال العرض الأول لتفويض الاختيار المعدل. بعد التسليم والموافقة الجديدة فقط يبدأ تجهيز سلة أخرى بهوية طلب مستقلة.

## التحقق

نجح **2047 اختبارًا**: 120 لأدوات النشر، و982 للوحدات والأمن في 31 ملفًا، و945 على MySQL في 16 ملفًا، دون فشل أو تخطٍّ.

نجح **168 سيناريو متصفح** لانحدار واجهات سلة القائمة بالعربية والإنجليزية وأحجام الهاتف وسطح المكتب، والأنواع والمخطط والبناء والترحيلات الـ147 على قاعدة جديدة وترقية وإعادة تشغيل. فحص الترجمة: 7996 استدعاءً و311 مفتاحًا ديناميكيًا، دون نقص أو أخطاء. [نتائج الفحص وبصمات المصدر](./audits/sales-brain-implementation-2026-09-23/salla-cart-supersede-verification.json).

الحزمة المستهدفة اجتازت **220 حالة**: 163 اختبار SQL للمحادثة و57 لاختيار العميل وحدود الموافقة والتعديل والاستئناف. أضيفت 61 حالة إلى الحزمة السابقة. تشمل رحلة تعديل مكتملة حتى إرسال الرابط الجديد، والحفاظ على السجل القديم، واستبدال الاختيار المنتهي والمرفوض وفقدان إسقاط النتيجة، وتغيّر السعر، وغياب التسليم، وعزل الأنشطة والمستلمين، وفساد الأدلة وإعادة حساب بصماتها، وفقد commit والتراجع والتزامن وتغيّر الرسالة والمخزون وتدخل الموظف.

في التشغيل الأول حاول اختبار فساد إدخال نتيجة في عملية مرفوضة، فرفضها قيد `chk_salla_cart_state` قبل وصولها للكود. عُدّل الاختبار ليثبت رفض قاعدة البيانات وعدم تغيير السجل؛ ثم نجحت الحالات المستهدفة كلها.

يستخدم الفحص قاعدة MySQL محلية ببيانات مصطنعة، ومسار الرد وoutbox الفعليين مع محاكاة سلة وواتساب وحجب الشبكة الخارجية. لا وصول إلى حساب إنتاجي أو إرسال لعميل حقيقي. لم تتغير واجهات الإنتاج أو مفاتيح الترجمة في هذه الدفعة.

## المتبقي

تبقى العمليات ذات الأثر الخارجي غير المحسوم أو المرجع المفقود، والعمال الذين قد يكونون قيد التنفيذ، والإلغاء أو التعديل الفعلي لسلة قديمة داخل المزوّد. لا يحل مرور الوقت أو رفض العميل وحدهما محل دليل انتهاء التنفيذ.

يبقى ربط cart/checkout/transaction بالطلب والقبض المالي وصاحب المحادثة، والتعلم من نتائج بيع مثبتة، والقبول الحي للتكاملات، وبقية بوابات الخطة. حالة المصفوفة **4 مكتملة / 62 جزئية / 5 مفتوحة**. هذا إصلاح لمسار الاتفاق، وليس اعتماد 10/10 أو نشرًا للإنتاج.
