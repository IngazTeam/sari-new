# تسوية محاولات دفع الحجوزات الغامضة ومراجعتها

التاريخ: 24 سبتمبر 2026. أساس الدفعة `1e69ece`. استكمال B035 وB037 وB057 وB064 وB065، بعد حماية إنشاء جلسة الحجز بسجل دائم. النطاق هو المحاولات التي أُنشئت بالمسار المحمي وتملك مرجعًا وبصمة محفوظين.

**الخطة مستمرة: 4 بنود مكتملة، 55 جزئية، 12 غير مغلقة.** لا اعتماد 10/10 أو ادعاء جودة بيع فعلية. [الخطة](./SARI_SALES_BRAIN_10_OF_10_PLAN_2026-09-23.md)، [مصفوفة القبول](./audits/sales-brain-implementation-2026-09-23/acceptance-matrix.md)، [أدلة النسخة المختبرة](./audits/sales-brain-implementation-2026-09-23/evidence.json).

## ما أُصلح

كان فقد رد إنشاء جلسة Tap للحجز يترك محاولة محجوزة دون وسيلة داخل التطبيق لاستعادة نتيجتها. أضيفت مراجعة صريحة من تفاصيل الحجز: يعرض النظام المرجع والمبلغ والحالة، ويدخل الموظف معرف charge من لوحة Tap ويؤكد مراجعة المرجع. يرسل الخادم GET واحدًا إلى Tap ثم يطابق السجلات ويحدّثها. لا تنشئ المراجعة جلسة جديدة ولا ترسل رسالة للعميل.

الصلاحية `orders.manage` من العضوية الحالية؛ معرف التاجر والمراجع من الجلسة. المدخلات تقبل معرف الحجز والمحاولة وcharge وبصمة الدليل وتأكيد المراجعة فقط. حقن التاجر أو المراجع أو الطلب أو المبلغ أو العملة أو الحالة مرفوض. عمليات GET مقيدة بنطاق Tap الثابت، دون body أو اتباع تحويلات، بمهلة وحجم رد محدودين عبر العميل المشترك الحالي.

## مطابقة الدليل

- الحجز والخدمة والرابط والمحاولة والدفع الموجود مملوكة للتاجر نفسه، ولا يرتبط الدفع أو الرابط بطلب بالتوازي مع الحجز.
- الإصدار المحمي للرابط 1، والرابط ثابت لاستخدام واحد، والعملة SAR، والسعر النهائي يساوي الأساسي ناقص الخصم وبالهللة. تتطابق قيمة المحاولة والرابط مع الحجز.
- نوع الكائن charge ومعرفه، ومرجع transaction وorder وmetadata.udf1، وحساب Tap ونمطه والمبلغ دون تقريب، واسم الدافع وهاتفه وبريده، تطابق بصمة المحاولة الأصلية. لا تتحول مطابقة مبلغ وحده إلى إثبات هوية.
- استخراج دالة البصمة المشتركة يحافظ على ترتيب الحقول وإصدار 1 للمحاولات السابقة؛ اختُبرت المطابقة البايتية مع الصيغة السابقة.
- تقبل مراجعة unknown وcreated، أو dispatching بعد دقيقتين من وقت قاعدة البيانات. هذا يتيح التحقق من أثر عامل متعطل؛ مرور الدقيقتين لا يمنح إذن إنشاء دفعة جديدة.
- يعاد فحص الدليل بعد GET تحت الأقفال. تغيير الحجز أو الرابط أو الدفع أو المراجعة أثناء الشبكة يرفض النتيجة القديمة ويحتاج تحديث الدليل.

| نتيجة التحقق | التصرف |
|---|---|
| CAPTURED مثبت ومتطابق | حفظ الدفع والتحصيل في الحجز والعدادات وذاكرة الشراء |
| INITIATED أو AUTHORIZED | حفظ الحالة دون تعلم بيع أو ادعاء تحصيل |
| جلسة INITIATED صالحة بعمر مثبت | حفظ رابط Tap بوقت الانتهاء الأصلي، دون تمديد من وقت المراجعة |
| انتهاء الجلسة أو عدم معرفة عمرها | لا يعاد رابط قابل للاستخدام ولا يسمح POST جديد اعتمادًا على الانتهاء |
| FAILED/DECLINED/RESTRICTED/CANCELLED/ABANDONED/VOID متطابقة | حفظ النهاية الموثقة؛ محاولة دفع لاحقة تحتاج طلبًا صريحًا جديدًا وأهلية الحجز والرابط |
| REFUNDED مع تحصيل محلي سابق | تسوية الاسترداد مرة واحدة دون إحياء دفع مسترد عند وصول capture متأخر |
| REFUNDED بلا تحصيل سابق، UNKNOWN، TIMEDOUT أو حالة غير مدعومة | لا تخمين لتاريخ مالي مفقود؛ تبقى للمراجعة |
| 404 أو تعطل المزوّد أو عدم تطابق الهوية | مراجعة unverified موثقة مع إبقاء الحاجز ومنع إعادة الخصم |

## المعاملة والتزامن

الحجز ثم الخدمة ثم الروابط ثم المحاولة والدفع تُقفل بترتيب متسق، ولا تحتفظ المراجعة بقفل أثناء GET. تستخدم الخدمة قفل تحديث مطابقًا للتسوية المالية؛ قفل قراءة مشترك هنا كان يمكن أن يتعارض عند محاولة مراجعتين لحجزين مختلفين ترقية القفل نفسه. اختُبرت تسوية حجزين للخدمة نفسها بالتزامن.

عند المطابقة، ينشأ الدفع المحلي المفقود وتستعمل التسوية المالية المشتركة لتحديث الحجز والعدادات وذاكرة الشراء، ثم تحدث المحاولة ويسجل رقم المراجعة والمراجع ومعرف العملية ونتيجتها وبصمة الدليل، في معاملة واحدة. لا تحفظ أسرار أو استجابة المزوّد الكاملة في المراجعة.

قيد charge الفريد يمنع ربط عملية تاجر آخر، وقيد المراجعة يمنع تكرار الإصدار نفسه. سباق مراجعتين للدليل نفسه يعتمد واحدة فقط. سباق webhook أو رد POST متأخر لا يكرر الدفع أو يخفض الحالة الموثقة. فشل أي كتابة يتراجع عن جميع الآثار. فقد تأكيد commit يغلق اتصال SQL، وإعادة المراجعة بدليل جديد لا تكرر التحصيل أو الذاكرة.

يمكن تسجيل تحصيل حقيقي متأخر لحجز ملغى دون إعادته إلى confirmed أو فتح الرابط المعطل. معلومات الخدمة في ذاكرة المشتريات مشتقة من الحجز المثبت؛ لا تسند إشارة نجاح إلى محادثة أو استراتيجية بيع بمجرد وجود metadata قديمة غير مثبتة.

## الواجهة وحدود الصلاحيات

داخل تفاصيل الحجز يظهر سجل آخر 10 محاولات، المرجع والمبلغ والتوقيت والحالة وآخر نتيجة مراجعة، مع إدخال charge وتأكيد صريح وزر واحد. تغيير المعرف أو بصمة الدليل يمسح التأكيد. أثناء الحفظ تتعطل بقية نماذج المراجعة، والتكرار يتطلب تحديثًا ومراجعة جديدة. تظهر الأخطاء برسائل عامة دون تفاصيل داخلية. تعاد قراءة الحجز والدليل والإحصاءات بعد العملية كي لا تعرض النافذة حالة دفع قديمة.

النص عربي وإنجليزي، المراجع الطويلة تلتف، نافذة التفاصيل قابلة للتمرير ضمن ارتفاع الشاشة، وعناصر اللمس لا تقل عن 44 بكسل. المراجعة متاحة عبر API للمالك والمدير ومشرف المبيعات، وتحجب عن المشاهد والعضوية الملغاة. **صفحة إدارة الحجوزات القديمة ما زالت تعتمد على مسارات قائمة خاصة بمالك النشاط؛ تعميم الصفحة كاملة على أعضاء الفريق ليس جزءًا مكتملًا من هذه الدفعة.**

## الاختبارات والترحيل

تستخدم الاختبارات MySQL محليًا وعملاء مصطنعين وناقل Tap مصطنعًا، مع حجب الشبكة الخارجية. النسخة المعتمدة مستقلة من Git index وتستبعد التعديلات الأخرى الجارية في مساحة العمل. النتائج النهائية وبصمات المصادر في ملف الأدلة المشار إليه أعلى التقرير.

- 65 اختبار تسوية حجز على MySQL، بما فيها البصمة السابقة والتحصيل والاسترداد والذاكرة والسباقات وتبديل الخدمة والهوية والتراجع وفقد تأكيد commit.
- 16 حالة إضافية لمسارات الفريق الفعلية، و12 حالة إضافية لعقد المدخلات وحدود المراجعة وربط الواجهة. فحوص الأمان المحلية لا تعادل اختبار اختراق إنتاجي مستقل.
- **4,301 حالة فريدة ناجحة، دون فشل أو تخطٍّ**؛ مجموع النتائج الخام **5,279** مع التكرار بين المجموعات. Unit: 701، MySQL: 902، Regression: 988، Legacy sales: 229، Budget: 11، Security: 2,448.
- TypeScript والبناء وDrizzle check نجحت. الترجمة: **6,124 استدعاء و234 مفتاحًا ديناميكيًا** دون مفقود أو خطأ interpolation أو تعبير غير محلول. حزمة الدخول 334,327 بايت و102,269 بعد gzip، ضمن السقف.
- أعيد تشغيل **241 حالة واجهة و30 صورة** للمكونات الفعلية باستخدام API مصطنع في Chromium بالعربية والإنجليزية وعروض 320 و375 و390 و768 و1440، دون أخطاء JavaScript. الحالات الجديدة تشمل تغير الدليل ولوحة المفاتيح ومنع الإرسال المتكرر وتحديث الحجز والفشل والحجب وXSS؛ راجعت [صورة عرض 375](./audits/sales-brain-implementation-2026-09-23/ui/booking-checkout-review-375.png). لا اعتماد Safari أو جهاز iPhone فعلي.
- **237 ملف مصدر** موثق ببصمات SHA-256 وGit blob، ومطابق للفهرس والنسخة المختبرة. بعد إصلاح قفل الخدمة أُعيدت حزم الوحدة وMySQL والبناء والأنواع؛ بقيت مصادر الواجهة كما اختبرت. لم يدخل العمل الآخر الجاري في مساحة العمل هذا الاعتماد.

ترحيل `0082_booking_checkout_reviews` طُبق على قاعدتي اختبار محليتين؛ رقم المراجعة يبدأ بصفر والسجل فريد لكل محاولة ورقم مراجعة. طابقت بصمة SQL المطبق وسجل القاعدتين والقيد الفريد والقيمة الافتراضية؛ البصمة بنهايات LF هي `ff67128ffb09c3a596eb1e9b7a4b7665cd0f0ea6eca0fd89eb76c32ac7bf1733`. نسخة Git على Windows تحمل CRLF لملفات SQL؛ طابقت محتواها بعد توحيد نهايات الأسطر وهوية Git المفلترة. لا إعادة كتابة لبصمات المحاولات القائمة ولا رفع لإصدار الروابط القديمة ولا تعديل لسجلات ترحيلات سابقة. قبل الإنتاج يلزم تطبيق الترحيل وتحديث الويب والعمال. لم تنفذ هذه الدفعة نشرًا أو ترحيل إنتاج أو تحصيلًا أو استردادًا لدى Tap أو إشعارًا لعميل. اختيار OpenAI/ZahyPi وسقف المنصة اليومي 100 دولار لم يتغيرا.

المتبقي: تسوية الروابط والتاريخ القديم اللذين لا يملكان محاولة محمية، سياسة استبدال روابط الحجوزات المنتهية، الروابط العامة والموصلات الأخرى، اتفاق الحجز وإسناد استراتيجية البيع داخل المحادثة، واعتماد العقود الحية وجودة النموذج. هذه الدفعة تغلق فجوة استرجاع نتيجة محاولة الحجز المحمية فقط.
