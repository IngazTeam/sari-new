## مجموعة تقييم النموذج

أصبحت المجموعة 30 محادثة اصطناعية: موافقة الشرح مقابل العرض، اختيار موعد بالإشارة، شرط وتراجع، نفي الاعتراض، السعر مقابل القيمة والثقة، طلب الكتالوج مقابل سعر منتج محدد، طلب موظف ونفيه، سؤال عن المدرب، مشكلة بعد الدفع، تصحيح ذاكرة قديمة، منتج غائب وحقن معرّف عرض آخر.

المقياس يرفض النجاح الزائف من نموذج يجيب دائمًا «وضّح». كذلك لا يجتاز حالة الموافقة الصحيحة إذا اختار `confirm_offer` ثم أبقى الغموض أو الثقة دون عتبة التنفيذ. تُفحص معرّفات المنتجات كمصفوفات، ويُحتسب التعديل والرفض والتصعيد ضمن الإجراءات التي يجب مراقبتها، إضافة إلى الشراء والحجز. رفض عرض طلبه العميل صراحة نجاح مطلوب، وليس «أثرًا ممنوعًا».

التقييم لا يرسل محادثات عملاء. لا ينفذ دوال الطلب أو الحجز أو التصعيد أو واتساب؛ الاتصالات الحية، عند توافرها، تُحتسب عبر دفتر الميزانية المشترك والمزوّد المحدد مركزيًا.

### التشغيل

الفحص الجاف لا يقرأ `.env` ولا قاعدة البيانات ولا يستدعي المزوّد:

```bash
node --import tsx scripts/testing/evaluate-conversation-understanding.ts
```

فحص الإعدادات للقراءة فقط، بمعرّف تيننت الاختبار الموجود:

```bash
node --import tsx scripts/testing/evaluate-conversation-understanding.ts --preflight --merchant-id TEST_MERCHANT_ID
```

التقييم المدفوع على الاختيار المركزي الحالي:

```bash
node --import tsx scripts/testing/evaluate-conversation-understanding.ts --live --merchant-id TEST_MERCHANT_ID
```

يقرأ وضعا الفحص/التقييم ملف `SARI_ENV_FILE` عند تعيينه، وإلا `.env`، دون طباعة القيم السرية. يمكن إضافة `--repeat 2` أو `--repeat 3` لقياس تباين النتائج ضمن الميزانية القائمة. هذا تكرار كامل للمجموعة، وليس إعادة محاولة تلقائية لطلب فاشل.

يُحفظ تقرير بعد كل حالة في `.tmp/conversation-understanding-evaluations`، مع بصمة مجموعة الحالات والمطالبات وإعداد المزوّد والنموذج. التوقف أو تعطل المزوّد/الميزانية لا يحوّل الحالات المتبقية إلى نجاح؛ تظهر كحالات لم تُشغّل ويخرج الأمر بحالة فشل. تغيّر الإعداد المركزي قبل الاستدعاء أو بعده يوقف الجولة بدل دمج نتائج إعدادات مختلفة. التقرير يصف النموذج المُعدّ، ولا يدعي رصد معرّف النموذج من استجابة المزوّد.
