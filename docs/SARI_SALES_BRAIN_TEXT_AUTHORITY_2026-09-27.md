# تثبيت الحساب والصلاحية لرد النص في مسارات التوافق

التاريخ: 27 سبتمبر 2026. أساس الدفعة: `e5a67dab`. تتبع [خطة الإصلاح](./SARI_SALES_BRAIN_10_OF_10_PLAN_2026-09-23.md) وتكمل [حجز محاولات التوافق النصي](./SARI_SALES_BRAIN_TEXT_COMPATIBILITY_2026-09-27.md).

## المشكلة والإصلاح

كان حجز UUID يمنع تكرار إرسال الرد للمجموعات والاتصال القديم، لكن مساري API كانا يختاران حساب واتساب بعد الحجز داخل callback مستقل. لم يكن الحجز يثبت الحساب أو إصدار ملكية المحادثة. كان مسار المجموعات يستطيع الرجوع إلى بيانات الاتصال القديم عند تعطل الحساب المسجل، وكانت دالة النقل العامة تبحث عن الحساب بمعرف المزوّد دون تقييد ذلك البحث بالتاجر.

أصبح مسارا API يستدعيان خدمة رد واحدة. يثبت عقد `staff-text-compatibility.v2` مرجع حساب التاجر وبصمة إعداداته ووقت الحجز وإصدار الملكية، في المعاملة نفسها التي تحجز UUID وتوقف رد الروبوت مؤقتًا. لا يحفظ العقد مفتاح المزوّد الخام. الخطأ قبل التزام المعاملة يعيد الملكية والحجز معًا؛ فقد إقرار التزام نجح فعليًا يبقي المحاولة معلقة دون إعادة نقل.

## قواعد الحساب والصلاحية

- وجود أي حساب مسجل للتاجر يتطلب حسابًا رئيسيًا نشطًا واحدًا. لا رجوع إلى الاتصال القديم عند تعطيله أو إلغاء اختياره أو عدم دعم مزوّده في مسار التوافق.
- إذا لم توجد حسابات مسجلة، يختار أحدث طلب اتصال للتاجر بترتيب `createdAt,id`، ويقبل حالتي `approved/connected` فقط مع إعدادات صالحة. لا يبحث عن حساب تاجر آخر بمعرف المزوّد.
- يستخدم مسار التوافق محول Green API الموجود في التطبيق. يتحقق من أصل HTTPS المسموح وعنوان الجذر ومعرف الحساب الرقمي ومفتاح خالٍ من محارف تغيير مسار URL. يرفض روابط الشبكة المحلية والمنافذ غير الافتراضية والاستعلامات وبيانات المستخدم داخل URL قبل الحجز. دعم الحسابات الفردية المسجلة بمزوّد Meta في المسار الموثق لم يتغير.
- يعاد فحص عضوية الموظف وحالته وحالة التاجر ووجهة المحادثة وملكيته الحالية وانتهاء التفويض وبصمة الحساب قبل النقل. في المجموعة المسجلة يعاد الفحص عند حارس قناة واتساب، بعد تحميل بيانات حساب النقل.
- يستخدم النقل المسجل مفتاح `staff_compat_text:<merchant>:<reply>` وحارسًا محفوظًا في outbox. لا يسمح `retryFailed` بتجريد الحارس أو تغيير المفتاح لإعادة محاولة السجل نفسه. يرفض الحارس تبديل النص أو الوجهة أو نوع الرسالة أو الحساب أو خلط حراس عمليات أخرى.
- يستخدم الاتصال القديم بيانات التاجر المثبتة مباشرة مع محول المزوّد؛ لا يستعمل `sendMessageWithCredentials` أو البحث العام بمعرف الحساب. مهلة المحول 12 ثانية وإعادة توجيه HTTP معطلة.

التحقق من الصلاحية يقع قبل بدء النقل. لا يمكنه إلغاء رسالة قبلها المزوّد بالفعل أو ضمان أن صلاحية الموظف لن تتغير أثناء طلب HTTP الجاري. تدوير المفتاح أو تغيير الملكية قبل هذا الحد يمنع النقل في الحالات المختبرة.

## حفظ النتيجة ومنع إعادة الإرسال

يلزم رد قبول صريح وإيصال بصيغة صالحة وحالة إرسال مقبولة. الرد المرفوض أو الغامض أو غير الصالح يبقي المحاولة `pending` دون إعادة إرسالها، حتى بعد إعادة فتح اتصال قاعدة البيانات أو تسجيل حساب جديد. لا يعني هذا أن كل حالة معلقة أرسلت؛ تحتاج الحالات غير المحسومة إلى مراجعة.

إسقاط الرسالة في المحادثة وحفظ نتيجة التوافق يحدثان في معاملة واحدة. يعاد التحقق من هوية التاجر ووجهة المحادثة قبل الإسقاط؛ حذف المحادثة أو تغيير العميل بعد قبول النقل يرجع `persisted:false`. إعادة استخدام رسالة موجودة بالإيصال نفسه تتطلب تطابق الاتجاه والنوع والكاتب والنص. التعارض أو فشل SQL يتراجع عن إسقاط هذه المعاملة ولا يعيد النقل. لا يعيد الاستعلام اللاحق إنشاء إسقاط حذف بعد نجاح سابق.

تحتفظ التنقية بطلب النقل المسجل للمحاولة غير المحسومة حتى بعد مرور 30 يومًا. يسمح بحذف محتواه بعد حفظ نجاح التوافق، مع بقاء هوية outbox ومحاولة الرد لمنع التكرار. الاتصال القديم لا يملك outbox مستقلًا في هذه الدفعة.

## التاريخ وأدلة المبيعات

تبقى سجلات `v1` مقروءة بنتيجتها المحفوظة أو حالتها المعلقة. لا يرقّي النظام سجلًا قديمًا باختراع حساب أو ملكية، ولا يعيد إرساله. عقد `v2` الجديد لا يتحول إلى `dashboard_text` موثق أو إلى سجل `ai_sales_staff_acceptances`، ولا يدخل عامل استعادة الرد الموثق. نتيجة التوافق لا تثبت التسليم أو القراءة أو التأليف البشري أو أثرًا في المبيعات.

البصمات تتحقق من الاتساق وليست توقيعًا ضد مسؤول يعيد كتابة قاعدة البيانات كاملة. منع الإرسال يخص UUID المحفوظ نفسه؛ إنشاء طلب بهوية مختلفة عملية أخرى.

## التحقق

نجحت **327 رحلة متصفح**: 113 لتقرير التجربة و48 لأدلة الطلبات و118 للرد النصي والمسودات و48 للصوت. تشمل العربية والإنجليزية والجوال ولوحة المفاتيح واحتفاظ المحاولة عند الغموض. الواجهة لم تتغير في هذه الدفعة، وواجهات API في اختبارات المتصفح محاكاة.

## التراجع والمتبقي

لا ترحيل SQL جديد أو تعديل في مدخلات العميل أو مفاتيح الترجمة أو سقف المنصة اليومي 100 دولار. تبقى آخر ترقية للمخطط `0132`. الإصدار السابق الذي يعرف `v1` فقط يرفض سجل `v2` بدل إعادة تشغيله؛ الاحتفاظ بجداول المحاولات لازم عند التراجع. لا تحمي هذه الدفعة طلبًا قد بدأ بالفعل عبر callback في نسخة قديمة؛ يجب تحديث عمليات الويب والعمال وفق دليل النشر.

تبقى مصفوفة الخطة **4 مكتملة / 59 جزئية / 8 مفتوحة**. المتبقي المباشر: تثبيت الحساب والصلاحية في توافق الرد الصوتي، وتسوية نتائج التوافق المعلقة دون إعادة النقل مع تجربة مزوّد فعلية بحساب اختبار مخصص. ما زال اعتماد التغطية البشرية والفاعلية التجارية والتجارب المقارنة مفتوحًا. لا يمنح هذا الإصلاح تقييم 10/10 للمخ أو المبيعات.

لم يجر إرسال لعملاء أو اتصال بإنتاج مسجل الدخول أو اختبار جهاز iPhone فعلي. فحوص التلاعب والصلاحيات محلية، وليست اختبار اختراق مستقلًا شاملًا. لم تُدفع التغييرات أو يُنشر الإنتاج.
