5. فشل الشبكة أو غياب usage يبقي المبلغ محجوزًا بحالة unknown. لا يُحرر بالوقت أو بإعادة تشغيل العامل.
6. تعود تسوية الطلب إلى يوم حجزه حتى لو انتهى بعد منتصف الليل. تخفيض السياسة يسري على الحجوزات الجديدة؛ زيادة سقف الفترة لا ترفع حد فترة بدأت بالفعل تلقائيًا.
7. الحجز والتسوية على وحدات صحيحة micro-USD، مع التقريب للأعلى، وفحص الحدود العددية.
8. تشمل البوابة مساري النص OpenAI وZahyPi، و`invokeLLM`، وRAG embeddings، ومسارات Whisper الثلاثة. الاستدعاء بلا هوية أو سعر معتمد يُرفض قبل الاتصال المدفوع.
9. إزالة عدّاد التكلفة الموجود في الذاكرة، وإزالة التحويل إلى نموذج مدفوع أرخص عند تجاوز السقف. الرسالة عند تعذر الخدمة لا تدّعي أن موظفًا أُبلغ إذا لم يحدث ذلك.
10. إضافة بطاقة الميزانية في صفحة AI للسوبر أدمن: سقف اليوم، المسوّى، المحجوز، أسعار النماذج، والحجوزات المحتاجة إلى مطابقة.
11. المطابقة اليدوية تسجل المبلغ المثبت ومرجع المزوّد وحساب المسؤول، وتمنع التسوية المزدوجة أو المتناقضة. إثبات عدم الاحتساب يسمح بتسوية صفرية؛ لا يعيد تنفيذ الطلب.
12. `preflight:ai-budget` يفشل قبل تفعيل الإصدار إذا غابت السياسة أو الأسعار المطلوبة. جداول الدفتر ضمن مخطط الجاهزية الحرج.

**حدود مالية مهمة للتشغيل:** السقف يمنع الحجوزات الزائدة بحسب بطاقة السعر، وليس ضمانًا من المزوّد أن الفاتورة لن تتجاوزها إذا كان السعر المدخل أو تقدير الاستهلاك أقل من الحقيقة. تسجل التسوية الاستخدام الحقيقي حتى إن تجاوز الحجز، بدل إخفائه. للصوت حجز ثابت محافظ لكل ملف، ويبقى حتى مطابقة الفاتورة؛ لم يُنفذ قياس مدة الصوت قبل الإرسال وتسعيره بالثانية. يلزم إنهاء ذلك وقياس هامش الأمان لتقوية S09.

**الأسعار غير مضبوطة في الإنتاج:** لم يقدّم المالك أسعار ZahyPi ولم نقرأ إعدادات الإنتاج. يجب تعبئة الأسعار المعتمدة للنموذج الفعلي، والنموذج البديل، والتضمين، وWhisper. النسخة تمنع الاستدعاءات غير المسعّرة عمدًا؛ نشرها دون هذا الإعداد سيوقف هذه المسارات.

### سلامة إرسال واتساب — جزء من S10

- حالات فقد الاتصال وHTTP 5xx و408 والقبول دون معرّف رسالة تُعامل كحصيلة غير معروفة، وتبقى queued للمراجعة. لا تعاد تلقائيًا بمجرد `retryFailed`.
- حماية السجلات القديمة التي خزنت الحصيلة المجهولة بوصفها failed من إعادة الإرسال العمياء.
- فشل حفظ النتيجة بعد قبول المزوّد لا يحرر مفتاح الأثر ولا يسمح بإرساله مجددًا.
- إضافة مفاتيح ثابتة تتضمن التاجر، وinstance، ومعرف الوارد، ونوع الأثر. تمر المفاتيح عبر wrappers بدل توليد UUID جديد لكل محاولة.
- ربط آثار polling، بما فيها الردود والوسائط والترحيب، وربط الرد الرئيسي والصوت وخارج الدوام وبعض الآثار المبكرة في webhook.
- الرد ذو الهوية الثابتة لا يسقط إلى اعتماد بيئة عام إذا لم يوجد instance مسجل.
- أثبت MySQL أن 16 محاولة متزامنة للرد نفسه تستدعي المزوّد مرة واحدة، وأن الحصيلة المجهولة تبقى ممنوعة من إعادة الإرسال بعد إعادة إنشاء الاتصال.

**ما لم يُغلق:** لا يوجد بعد مخطط رد كامل محفوظ قبل أول أثر لكل القنوات. بعض إشعارات webhook الثانوية وعمليات legacy ما زالت بلا مفتاح حدث ثابت، وتوقيت mark processed بالنسبة للوسائط يحتاج إعادة تنظيم. لذلك لا يوجد ادعاء exactly-once أو عدم فقد كل المرفقات عند سقوط العامل. S10/S11 ما زالا جزئيين.

## 3. تشغيل آمن لهذا التغيير

1. اعتمد نسخة المصدر المحددة، وثبت Node من `.node-version` وpnpm من `packageManager`. شغّل `pnpm install --frozen-lockfile` و`pnpm check:runtime`.
2. شغّل `test:tooling` و`test:remediation` و`test:zahypi` و`test:release` و`check` و`audit:production` و`audit:locales` و`db:check` و`build`، ثم job تكامل MySQL ببيانات معزولة.
3. اختبر الهجرة 0051 على staging بعد نسخة احتياطية مثبتة الاستعادة. الهجرة إضافية ولا تعيد كتابة بيانات العملاء.
4. أدخل بطاقة السعر من العقد/الفاتورة. يمكن الإعداد قبل تفعيل الكود بواسطة `pnpm ai:configure-price --file <approved-price.json>` للتحقق فقط، ثم إضافة `--apply` للكتابة إلى قاعدة البيئة المحددة في `DATABASE_URL`. لا تضع مفتاح API في هذا الملف.
5. حقول الملف: `provider`، `model`، `version`، `inputUsdPerMillion`، `outputUsdPerMillion`، `flatUsd`، `maxInputTokens`، `enabled`. لا تستعمل قيم الاختبارات كأسعار حقيقية. Whisper يحتاج `flatUsd` محافظًا؛ الأسعار الصفرية غير المعتمدة لا تتجاوز الحماية.
6. شغّل `pnpm preflight:ai-budget`. راجع أيضًا عدد المتاجر النشطة دون اشتراك canonical مؤهل؛ لا تمنح اشتراكًا اصطناعيًا لمجرد تمرير الفحص.
7. اختبر اختيار المزوّدين وتعطيل AI من السوبر أدمن، ونفاد الميزانية، وسحب اشتراك/عضوية، ومطابقة الحجز المجهول، على حسابات اختبار وبميزانية معلومة.
8. قارن توقيت القاعدة قبل النشر وأثر UTC على البيانات القديمة، وسجل أي معالجة لازمة. لا تنفذ تعديلًا عامًا لتواريخ العملاء.
9. انشر canary وفق S32، ثم راقب الميزانية والحجوزات المجهولة والتسليم وجودة الرد. لا يُوسّع التشغيل على أساس نجاح اختبارات المصدر فقط.

**التراجع:** جداول 0051 تبقى عند التراجع للكود السابق؛ لا تُحذف حجوزات أو أدلة مطابقة. لكن الكود السابق لا ينفذ حد AI الجديد، لذلك يجب تعطيل AI أو تقييد الإرسال على مستوى المزوّد قبل التراجع إذا كان السقف شرط التشغيل. لم يُنفذ نشر أو rollback حي في هذه الجلسة.

|---|---|---|
| S01 | بيئة محلية موحدة وبوابة إصدارات | CI على SHA المرشح وبيئة staging |
| S02 | إصلاح منجز ومختبر | استمرار البوابة في الإصدار |
| S03 | اعتماديات الإنتاج عولجت محليًا | CI وcanary ومراقبة دورية |
| S04 | بوابات المصدر أصلحت ونجحت | تشغيل Linux النهائي وتوسيع الاختبارات السلوكية |
| S05 | عرض البيتا والتجربة والتذييل صححت | تدقيق كامل لكل الصفحات والباقات ووحدة القياس |
| S06 | هوية العضوية ووحدة المنتجات والصوت أصلحت | مصفوفة كل المسارات واختيار متعدد المتاجر |
| S07 | تحسينات SSRF والتوقيت والخصوصية | تدقيق الأسرار والاحتفاظ وDSR والسجلات شاملًا |
| S08 | دفتر ذري وأسعار ومطابقة مع اختبارات MySQL | اختبار عمليات منفصلة وقت السقوط ومطابقة فواتير فعلية |
| S09 | بوابات المسارات المدفوعة وحد المنصة مضافة | أسعار فعلية، تسعير مدة الصوت، وتدقيق هوية كل caller |
| S10 | قبول/unknown ومفاتيح آثار رئيسية أصلحت | مخطط آثار كامل محفوظ وكل callers وواجهة معالجة التسليم |
| S11 | لم يُغلق | توحيد ingress والسياق وملكية المعالجة بين العمال |
| S12 | العقود الحالية شغلت دون تعديل منطق الدفع | اختبارات مزود دفع حي وترتيب الأحداث والاسترداد |
| S13 | عقود الاعتماديات وتحسين حدود الشبكة | عقود التكاملات المباعة وfixtures حديثة واعتماد حي |
| S14 | حفظ حقيقة المخزون ورسالة تعذر صادقة | truth/action ledger وإثبات مخرجات الإجراءات |
| S15 | لم يُنفذ تقييم جودة قطاعي | مجموعة حالات معتمدة وتشغيل نموذج وتحليل النتائج |
| S16 | فصل ملكية الاتصال منجز محليًا | تحقق سلوك المجمع تحت حمل staging وتعافي الموارد |
| S17 | وحدات هوية وميزانية جديدة فقط | فصل بقية المجالات من db.ts/routers.ts |
| S18 | لم يُغلق | فصل مراحل AI مع اختبارات سلوك ثابتة |
| S19 | لم يُنفذ عامل دائم موحد | leases/heartbeat/retry/DLQ واختبار crash |
| S20 | مراقبة ميزانية وجاهزية مخطط أضيفت | SLO وتنبيهات trace/queue وتعيين مسؤول الاستجابة |
| S21 | اختبارات تنافس محدودة فقط | حمل واقعي لمدة وعينة وتوبولوجيا محددة |
| S22 | لم يُنفذ تمرين استعادة | دليل RPO/RTO واستعادة أسرار وoutbox بلا إرسال |
| S23 | بوابات النشر توسعت | release manifest وrollback حي مثبت |
| S24 | إصلاح روابط التسجيل فقط | رحلة تفعيل كاملة ومقاييس وقت أول قيمة |
| S25 | فحص بصري عام مكتبي وهاتف | تدقيق إتاحة وأداء كل الرحلات الأساسية |
| S26 | لم يُنفذ E2E كامل | signup → أول رد → دفع → إلغاء/تعافٍ |
| S27 | لم يُنفذ فحص مستقل | جهة/مراجع مستقل وretest |
| S28 | سجل تكلفة جزئي أضيف | أحداث المنتج وتسوية التحويلات التجارية |
| S29 | قرار سقف 100 دولار موثق | تكاليف ومبيعات ودعم فعلية لكل عميل/باقة |
| S30 | لم يُحسم اختيار قطاع أول | تقييم العملاء الـ12 بمقاييس نتائج ودعم وتجديد |
| S31 | الادعاءات العامة صححت | دراستان بدليل وموافقة نشر من أصحابها |
| S32 | لم يبدأ نشر تدريجي | staging ناجح ثم canary مع معايير توقف |
| S33 | لم تُنفذ تجربة نمو | نافذة اكتساب واحتفاظ وميزانية وقياس فعلي |
| S34 | غير معتمد 10/10 | إغلاق بوابات الخطة على الإصدار المنشور نفسه |

الأولوية الهندسية التالية: إكمال خطة آثار الرد الدائمة S10/S11، ثم توحيد صلاحيات بقية المسارات، ثم مراحل AI والعامل الخلفي وE2E. الأولوية التشغيلية قبل ذلك: أسعار المزوّدين، مراجعة UTC، وتشغيل CI/staging. الأعمال التجارية ذات نافذة 30–90 يومًا لا يمكن استنتاج اكتمالها من تعديل الكود.
