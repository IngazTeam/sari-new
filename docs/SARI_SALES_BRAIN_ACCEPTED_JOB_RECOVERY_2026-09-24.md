# استرجاع نتائج مهام ZahyPi المقبولة — 24 سبتمبر 2026

استكمال بعد الكوميت 9092bc8d. كان الرد الذي لم يصل إلى SQL يضيع عند توقف العامل، حتى لو قبل ZahyPi المهمة وأكملها. أصبح سجل التحليل يحفظ إيصال القبول قبل انتظار النتيجة، ويتيح لعامل آخر قراءة المهمة الأصلية من المزوّد.

## التنفيذ

- يحفظ إيصالًا محدودًا: معرّف المهمة والتتبع والنشاط والعقد وبصمة المسار. لا مفاتيح API أو نصوص محادثة أو نسخة من مدخلات التحليل. لا يستبدل إيصالًا سابقًا بهوية مختلفة.
- يربط الإيصال بمحاولة الميزانية الأصلية والمصادر ومالك المهمة داخل معاملة. فشل حفظه يمنع متابعة polling ولا يعيد POST، ويبقي الحجز المالي حتى تتضح النتيجة.
- عامل مستقل يبدأ ويتوقف مع عمال الرسائل. ينتظر ثلاث دقائق بعد القبول كي ينتهي المسار الأمامي، ثم يحجز حتى خمس مهام بحجز ثلاث دقائق وSKIP LOCKED. مؤقته كل دقيقة، دون تداخل الدورات، وتأجيل متدرج حتى ساعة.
- يعيد بناء الهوية من SQL بعد إعادة التشغيل. يقرأ إعداد السوبر أدمن حديثًا قبل HTTP، دون الاعتماد على cache أو اختيار مثبت في تفاعل سابق. تعطيل AI أو اختيار OpenAI أو اختلاف المسار والنموذج وإصدار الموصل يؤجل الاسترجاع.
- ينفذ GET واحدًا للمهمة المحفوظة، بمهلة 20 ثانية، ومنع redirects وحد استجابة 1MiB. يتحقق من المهمة والنشاط والمشروع والعقد والتتبع وrun manifest والاستهلاك وعقد المخرجات. لا طلب توليد ولا fallback ولا حجز تكلفة جديد.
- يعيد فحص المصادر وحجز العامل عند حفظ النتيجة. انتهاء الحجز أو استبداله أثناء الشبكة لا يسمح للعامل القديم بالحفظ أو تأجيل مهمة بديلة. استعادة SQL المعتادة تحفظ المقترحات والأدلة بعد ذلك، دون إشعارات أو تفعيل سياسة تلقائيًا.
- تسوية الاستهلاك تستخدم الحجز والسعر الأصليين بعد حفظ الرد. إذا فشلت، يبقى المبلغ محجوزًا وتستمر استعادة الرد؛ التسوية المالية المنفصلة ما زالت مطلوبة لهذه الحالة. لا تغيير لسقف المنصة البالغ 100 دولار يوميًا.

## الترحيل وحدود القبول

يلزم تطبيق 0103 قبل تشغيل الكود الجديد وتحديث الويب والعمال معًا. الإيصالات القديمة تبقى NULL، فلا تخمين لمعرّفات مدفوعة أو تحويل السجلات القديمة إلى مهام جديدة. المخطط يتحقق منه runtime قبل العمل.

- يغطي الاسترجاع مهام تحليل التعلم الجديدة التي حُفظ لها إيصال ZahyPi فعلي. الانقطاع قبل استلام معرّف المهمة أو قبل commit الإيصال، وطلبات OpenAI المفقودة، ما زالت تحتاج تسوية منفصلة. لا إعادة توليد تلقائية لهذه الحالات.
- يعتمد GET على عقد المزوّد المستخدم أصلًا في عميل المشروع. الاختبارات تستخدم نقلًا محاكى؛ لم يُعتمد زمن احتفاظ ZahyPi بالنتائج أو صلاحيات قراءتها من خدمة حية. 404 أو فشل المهمة يؤجل الاسترجاع ولا يطلق الميزانية.
- الدورات محدودة إلى خمسة طلبات، وكل GET محدود إلى 20 ثانية؛ عمليات SQL تخضع لمهل قاعدة البيانات. التأجيل المتكرر لا يمثل ضمان إنجاز عند تعطل المزوّد أو تغير إعداداته.
- خانة التحليل تحتفظ بآخر دورة للنشاط فقط. تعارض التسوية أو تعطلها بعد حفظ الرد يبقى ضمن التسوية المالية القائمة، وليس عاملًا ماليًا جديدًا متكاملًا.
- لا واجهة جديدة ولا مفاتيح ترجمة جديدة. الحالة العامة غير المحسومة لا تصبح نجاحًا حتى تُحفظ النتيجة ويُنجز إسقاطها.
- التحقق محلي ببيانات مصطنعة؛ لا اتصال مدفوع ولا رسالة عميل ولا رفع أو نشر. فحص الأمان انحدار سلوكي محلي، وليس بنتريشن مستقلًا على الإنتاج.
- الخطة تبقى **4 مكتملة / 57 جزئية / 10 مفتوحة**. اعتماد سياسات التعلم وتقييمها والتراجع عنها وقياس الأثر البيعي، وقبول المزوّدين الحقيقيين، لم تُغلق بهذه الدفعة.
