# فهم المحادثة قبل قرار المبيعات

تحديث لاحق في اليوم نفسه: [إغلاق اختصارات الرد والتصعيد وتوسيع التقييم إلى 30 محادثة](SARI_CONTEXTUAL_AI_FOLLOWUP_2026-09-28.md). الأرقام والنطاق أدناه توثق المراجعة الأولى؛ نتائج المتابعة في تقريرها المنفصل.

طلب المستخدم: فهم سياقي عبر GPT أو ZahyPi من إعداد السوبر أدمن لجميع التيننت، بدل تقرير الشراء والرفض والاعتراض من كلمة أو جملة محفوظة.

## التغيير

دخلت مرحلة `understandConversation` قبل مسارات المبيعات الخاصة في `chatWithSari`. تستخدم نقطة المزوّد المشتركة `callGPT4` ومهمة `sari.customer.intent` الموجودة في حوكمة ZahyPi. اختيار المزوّد وتفعيله مركزيان؛ تعطيل المزوّد أو انتهاء الميزانية لا يشغّلان مزوّدًا آخر لتجاوز القرار. نموذج OpenAI المستخدم في التحليل وبقية الدور يأتي من إعداد السوبر أدمن، ونموذج ZahyPi من إعداد موصله المركزي. سقف المنصة المشترك 100 دولار يوميًا يظل تحت دفتر الميزانية القائم، ويشمل استدعاء التحليل الإضافي.

يقرأ التحليل:

- آخر 21 رسالة، بما فيها الرسالة الحالية وكلام المساعد؛ بعد حد حذف الذاكرة.
- ذاكرة عميل موثقة المصدر، وملخص التحليل السابق وأسئلته غير المحسومة بعد إعادة التحقق منه.
- كتالوج التيننت المرئي، حتى 200 منتج، والخدمات حتى 150 خدمة.
- مرجع العرض الحالي ومواعيد بيان المتاحة. التنفيذ يعيد التحقق من تسليم العرض وصلاحيته وأسعاره وصلاحياته.

أُزيل أيضًا قص رسالة العميل إلى أول 500 حرف في توليد الرد؛ أصبح الحد 16,000 حرف، متسقًا مع حد التحليل، حتى لا تضيع تفاصيل مؤثرة في نهاية الرسالة.

السياق الطويل يُرسل بأجزاء JSON مرتبة لا يتجاوز كل منها حد رسالة ZahyPi البالغ 16,000 حرف، دون قص المحادثة داخل وسيط النقل. يوجد اختبار يعيد تركيب السياق الطويل حرفيًا ويتحقق من عقد مهمة ZahyPi. قراءة إعداد التشغيل تستخدم إسقاطًا محدودًا للمزوّد والنموذج والتفعيل، ولا تعتمد على أعمدة التحليلات أو تقرأ مفاتيح في طبقة التحليل.

في توليد الرد يُرسل تحليل الدور وسياسة البيع برسالة system مستقلة عن تعليمات النشاط الطويلة، حتى لا يقصهما حد النقل عند وضعهما في نهاية تلك التعليمات.

الناتج عقد JSON يتحقق منه Zod: نية العميل، هدف الدور، الإجراء المقترح، الاعتراض، الاحتياج، الأسئلة المفتوحة، المشاعر، الغموض والشرط، مرجع العرض والمنتجات، وشواهد حرفية بمعرّفات رسائل. لا يقبل معرّف منتج أو عرض خارج السياق المعطى، ولا شاهدًا غير موجود أو موافقة متناقضة مع الرفض.

لا يُقبل الإجراء التنفيذي إلا بثقة معلنة لا تقل عن 0.85 ودون شرط أو غموض، ثم تمر عليه بوابات الصلاحية والبيانات الفعلية والتسليم. الثقة رقم يقدمه النموذج، وليست احتمالًا معايرًا أو ضمانًا لصحة الفهم؛ لذلك بقيت بقية البوابات والتقييم المستقل ضروريين.

## أين يستخدم الفهم

| المسار | الاستخدام الجديد |
|---|---|
| الرد والمسار السريع | إعادة استخدام التحليل نفسه للمشاعر والنية وهدف الرد بدل تصنيف لفظي مستقل |
| توجيه المبيعات | الخطوة القادمة من الاحتياج والاعتراض الحالي؛ لا يولد لفظ «غالي» خصمًا آليًا |
| الولاء وعرض الكتالوج | نوع الطلب من التحليل السياقي |
| بيان | طلب الدورة، تعديل العرض، اختيار موعد بالإشارة إليه، الموافقة والرفض |
| سلة، زد، الطلب المحلي | نية الشراء والموافقة وتعديل العرض من التحليل، مع تحقق بيانات التنفيذ القائم |
| الحجز | توجيه الطلب والموافقة إلى العرض المقصود؛ المواعيد والسعة والأسعار من الأدوات |
| الإرسال وإعادة المحاولة | إعادة تحميل تحليل الرسالة المحفوظ والتحقق من مصدره قبل حواجز إرسال واتساب |

مثال: «نعم» بعد «أشرح لك الخيارات؟» يكمل الشرح. نفس الكلمة بعد عرض محدد قد تؤكد ذلك العرض. «مو غالي، بس الوقت ما يناسبني» يُعالج كمسألة توقيت إذا كان هذا تفسير النموذج للسياق. الكلمات بحد ذاتها لا تمنح صلاحية شراء في المسار الجديد.

## التخزين والعزل

الترحيل `0150_conversation_understanding.sql` ينشئ سجلًا واحدًا لكل تيننت ورسالة. يحفظ بصمات المصدر والسياق وشواهد الرسائل ونسخة الملكية وحد الذاكرة وحالة التحليل ونتيجته وبصمتها. الحجز في SQL يسبق الاتصال بالمزوّد، وتُحرر أقفال SQL أثناء الانتظار، ثم يعاد فحص السياق قبل حفظ النتيجة.

الفشل أو JSON غير الصالح أو تبدل الرسالة أو الذاكرة أو الملكية يمنع التنفيذ. لا يرجع الدور إلى قرار بالكلمات عند فشل التحليل. إعادة المحاولة تستعمل النتيجة المحفوظة؛ التحليل الفاشل/غير المحسوم لا يكرر استدعاء مدفوعًا للرسالة نفسها. يمكن تحليل رسالة جديدة مستقلة.

الموافقة التاريخية تُقرأ بمعرّف الرسالة، لا بالبحث عن نص مثل «نعم» يمكن تكراره. ذاكرة التيننت والعميل لا تُشارك مع تيننت آخر. الملخص السابق قابل للتصحيح ولا يثبت سعرًا أو دفعًا ولا يمنح موافقة لدور جديد. هذا استمرار لذاكرة المحادثة، وليس تدريبًا تلقائيًا لأوزان النموذج أو إثباتًا لتحسن التحويل.

## حدود النطاق

- المسار الإلزامي أعلاه للمحادثات الخاصة ذات الرسائل المحفوظة. التجارب دون هوية محادثة تنفيذية تستعمل التحليل نفسه بصلاحية الرد فقط. تحليل المجموعات الكامل وتاريخ محادثة المعاينة ليسا مشمولين بهذا التغيير.
- أوامر الخصوصية والإدارة ذات الصيغة الصريحة، مثل حذف الذاكرة وإدارة تذكير بمرجع، تبقى محلية حتى عند توقف المزوّد. تحليل النص لغرض البحث، وتنسيق الأرقام والمعرّفات، والتحقق من الروابط والأسعار ليس قرارًا لغويًا بالشراء.
- بقيت القراءات القديمة للاتفاقات السابقة على الترحيل متوافقة مع عقد الموافقة القديم. قواعدها لا تصبح مسارًا بديلًا لفشل التحليل الجديد.
- الحدود المذكورة للسياق والكتالوج تعني طلب توضيح عند فقد المرجع أو غياب المنتج؛ لا تعني إرسال تاريخ العميل أو كامل كتالوج ضخم بلا حد.
- بوابات العمل لا تثبت جودة الإقناع. قياس فهم النموذج الحقيقي يحتاج تشغيلًا فعليًا للمزوّد ومراجعة بشرية لعينات مستقلة.

## الاختبارات والتقييم

دليل النتائج الآلية في `SARI_CONTEXTUAL_AI_EVIDENCE_2026-09-28.json`. تتضمن الاختبارات قاعدة MySQL اصطناعية ووسائل نقل وهمية، وتصنيفًا مصطنعًا معلومًا. هذه تثبت انتقال القرار السياقي إلى التنفيذ وحماية المصدر والتكرار والعزل؛ لا تقيس جودة GPT أو ZahyPi من تلقاء نفسيهما.

النتيجة: 1649 اختبار انحدار ناجحًا في 43 ملفًا، دون فشل أو تخطٍّ، ثم 86 اختبارًا مركزًا ناجحًا على آخر تعديلات السياسة والتعطيل المركزي. المجموعة الأخيرة تتداخل مع الأولى ولا تُجمع معها كاختبارات مستقلة. نجحت فحوص TypeScript ومفاتيح الترجمة والبناء النهائي وقراءة إعداد التشغيل من قاعدة الاختبار الفعلية. لم تُشغّل استدعاءات تقييم نموذج حي أو اختبار اختراق إنتاجي في هذا العمل.

توجد 14 محادثة اصطناعية قابلة للمراجعة في `scripts/testing/conversation-understanding-cases.ts`: موافقة على الشرح/العرض، شرط، نفي اعتراض السعر، اختيار بالإشارة، بدائل غامضة، كلام مقتبس، استفسار الدفع، تراجع، مشكلة بعد الشراء، حقن تعليمات، الإنجليزية، واعتراض القيمة.

الفحص الجاف، دون استدعاء مزوّد:

```bash
node --import tsx scripts/testing/evaluate-conversation-understanding.ts
```

لتشغيلها على المزوّد المحدد حاليًا في السوبر أدمن، مع معرّف تيننت اختبار موجود وصلاحية دفتر الميزانية:

```bash
node --import tsx scripts/testing/evaluate-conversation-understanding.ts --live --merchant-id <test-merchant-id>
```

هذا الأمر ينفذ استدعاءات مدفوعة ضمن السقف المشترك. لا ينشئ طلبًا أو حجزًا ولا يرسل واتساب. يسجل النتائج في `.tmp/conversation-understanding-evaluations` ويُرجع فشلًا إذا أخفقت حالة أو اقترح تنفيذًا عالي الثقة في حالة ممنوعة. لتقييم المزوّد الآخر يُغيّر اختيار السوبر أدمن أولًا؛ الأمر لا يتجاوزه. تقريره يذكر الإعداد، ولا يدعي رصد نموذج مختلف من الاستجابة.
