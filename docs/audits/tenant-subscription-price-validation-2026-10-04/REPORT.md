# المرحلة488 — سلامة حساب سعر الاشتراك والترقية

أثبتت الاختبارات19إخفاقًا من21قبل الإصلاح: قبول أسعار تالفة ودورات أو فترات غير صالحة، خصم رصيد بعملة مختلفة، منح التجربة رصيدًا ماليًا، وعدم تقريب الرصيد إلى الهللة/السنت.

## التغيير
- قراءة أسعار الاشتراك والإضافات والترقية كسلاسل عشرية دقيقة بحد أقصى مليون وحدة عملة، ورفض الكسور الأصغر من وحدة العملة والنصوص اللاحقة والصيغة الأسية.
- رفض الترقية عند فترات غير صالحة أو منتهية أو لم تبدأ، ودورة أو حالة غير معروفة، أو اختلاف العملة.
- التجربة لا تمنح رصيدًا ماليًا؛ الحساب النشط يحتفظ بسياسة الرصيد اليومي الموجودة مع تقريب الرصيد مرة واحدة ثم الطرح بوحدات صحيحة.
- رفض NaN/Infinity والسالب والمبلغ غير الدقيق قبل إنشاء المعاملة أو التفعيل الفوري. يبقى المبلغ الصفري الحقيقي ممكنًا.
- إخفاء تفاصيل إخفاق مصدر حساب الترقية.

## التحقق
109/109حالات وحدة وتراجع، منها استدعاءات الراوتر التي تثبت عدم إنشاء معاملة أو الاتصال بالمزود أو تفعيل الباقة عند فشل الحساب. فحص TypeScript وبناء الإنتاج ناجحان. لا تغييرات تخزين أو ترحيل تستلزم عينة MySQL جديدة في هذه المرحلة.

## الحدود والمتابعة
لم يُجر اتصال بمزود دفع أو نشر. هذا إصلاح حسابي؛ الرصيد للحسابات النشطة ما زال مشتقًا من سعر الباقة المسجل، ولا يثبت مبلغ الدفع التاريخي. مراجعة السعر قبل التأكيد وربطها بنسخة الحالة، والواجهة المشتركة للباقات والمقارنة والشراء، ما زالت أعمالًا تالية. لا ادعاء اكتمال مراجعة الأمن أو النظام.
