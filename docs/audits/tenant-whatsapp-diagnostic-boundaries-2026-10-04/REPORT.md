# المرحلة506 — حدود اختبارات اتصال وإرسال واتساب

تعديل محلي على `main` لثلاثة مداخل: `whatsapp.testConnection` و`sendTestMessage` و`sendTestImage`. لا رسائل أو اتصالات مزود فعلية أو نشر.

## ما ثبت وما تغيّر

كان الراوتر الرئيسي ينفذ طلبات Axios مباشرة من مدخلات string غير مقيدة ودون تحديد متجر لهذه الاختبارات. أما النسخة المستقلة فاحتوت حدًا في ذاكرة العملية للنص فقط، فلم يوفر حدًا مشتركًا بين النسختين أو العمليات أو اختبار الصور. كان النجاح يعيد جسم المزود الخام؛ نجاح HTTP لا يثبت إقرار قبول رسالة.

- استبدلت النسختان بمجموعة إجراءات واحدة؛ تختار التيننت عبر هوية الخادم، وتطلب مالكًا حيًا، وتتحقق من حالة حسابه وحساب المالك الأساسي. المدير والمشاهد ومشرف المبيعات لا يمكنهم استخدام هذه الواجهة الحساسة.
- هوية مزود رقمية محدودة ورمز محدود بحروف آمنة، مع رفض مفاتيح إضافية ومعرف متجر مزور. الروابط المبنية لا تقبل حقن مسار أو أصل جديد، وإعادة التوجيه معطلة والوقت وحجم الرد مقيدان.
- عند وجود الهوية في النظام يجب أن تكون Green API ومملوكة للمتجر ومطابقة للمفتاح المفكوك من التخزين. إرسال الاختبار يحتاج سجلًا محفوظًا ونشطًا وغير منتهٍ. يستطيع المالك اختبار اتصال مفاتيح جديدة قبل حفظها؛ هذا الاختبار لا يحفظها ولا يمنحها ملكية.
- التحقق الأول يسبق حجز الحصة، ثم تتكرر قراءة الصلاحية والاتصال تحت أقفال قراءة أثناء طلب المزود المحدود. تعذر قاعدة البيانات أو فك التشفير أو غياب الصلاحية يمنع الطلب.
- حد دائم في MySQL:30اختبار اتصال لكل10دقائق و10محاولات إرسال نص أو صورة مشتركة لكل24ساعة لكل متجر. لا بديل ذاكرة عند فشل المصدر؛ المحاولة غير المؤكدة تستهلك الحصة ولا تعاد تلقائيًا.
- الاتصال الموجب يحتاج `authorized` ورقم `wid` شخصي صالح من إعدادات المزود. الإرسال الموجب يحتاج `idMessage` نصيًا صالحًا، ويعيد `accepted` فقط؛ هذا قبول مزود وليس إثبات تسليم. لا payload أو أسرار أو URL أو خطأ نقل خام في الرد.
- الصورة تقبل HTTPS دون credentials أو fragment أو منفذ مخصص أو عنوان محلي/IP حرفي. هذا تحقق في عنوان يُمرَّر للمزود، وليس إثبات DNS أو سياسة جلب داخل بنية المزود.

## الأدلة

نجحت **132حالة وحدة** في5ملفات، منها عقود المدخلات والعزل والرفض قبل الآثار ورد المزود الأدنى وHTTPوالتحويل والمهلة وفشل الحصة وسحب الصلاحية، مع تراجع مسارات واتساب والحصة المشتركة. ثم أعيد ملف الاختبارات المتأثر بعد إصلاح تضييق أنواع المدخلات بنجاح.

نجحت **17حالة MySQL**:15للحدود الجديدة وحالتان لتراجع workspace. أُعيدت15الجديدة بعد تحسين مقارنة السجل قبل/بعد. أُثبت قبول10من16طلبًا متزامنًا مختلطًا للنص والصور ورفض6بالحد، وعزل المتجر ومطابقة المفاتيح وتعطيل الحساب والعضوية والانتهاء وعدم تغيير السجل. جميع طلبات المزود مُحاكاة. نظفت fixtures بحساباتها الموسومة وبصمات حصة المعرفات نفسها فقط.

كشف فحص TypeScript الأول3أخطاء تضييق في اتحاد مخططات Zod؛ صُحح بناء جسم النص والصورة بالمخطط الخاص بكل نوع، ثم نجح فحص الأنواع وبناء الإنتاج النهائي. لا تغيير مفاتيح ترجمة أو مخطط قاعدة البيانات بهذه الدفعة؛ أعيد استخدام جدول الحصة المشترك القائم.

## المتبقي

صفحة الاختبار القديمة وحقولها ما زالت تحتاج التصميم الجديد، وإزالة رقم الهاتف المسبق، ومراجعة النص/الصورة قبل الإرسال، ورسالة تفصل قبول المزود عن التسليم. حفظ/حذف الربط القديمان لم يعالجا بهذه الدفعة. كذلك تبقى استعادة محاولة إرسال بمعرف ثابت ومصالحة النتيجة غير المؤكدة؛ الحد الدائم لا يحل مشكلة تكرار ضغطة جديدة. لا اختبار اختراق شامل أو Safari/iPhone فعلي أو إنتاج.
