# المرحلة 99: مراجعة Sheets محفوظة واعتماد ذري وإيصال

أضيفت prepare/read/commit/receipt/discard تحت products.sheetImport. يحفظ الترحيل176 مراجعة معزولة بهوية التاجر والمستخدم وUUID، ولقطة الورقة ووقت قراءتها وخطة القيم قبل/بعد وبصمتها. يشترط اعتمادها موافقة صريحة؛ لا يقبل API صفوفًا أو بيانات اعتماد يقدمها المتصفح.

## السلوك والتحقق

- قراءة المزود خارج معاملة المنتجات، ثم إعادة فحص الربط والصلاحية تحت قفل التاجر قبل حفظ المراجعة. إعادة التحضير بنفس UUID والمدخلات تعيد اللقطة المحفوظة دون قراءة Google جديدة؛ المدخلات المختلفة ترفض. التحضيران المتزامنان قد ينفذان قراءتين فقط، لكنهما يحفظان مراجعة واحدة متطابقة.
- حد30 تحضير/ساعة، و3 مراجعات للمستخدم و10 للتاجر، و8MiB للمحتوى، وصلاحية24 ساعة. عند التحضير تُزال المراجعات المنتهية لهذا التاجر؛ الإيصالات المكتملة تبقى مستقلة. قراءات الاستعادة متاحة دون استهلاك حد المزود.
- قراءة فهرس بحد20 ألف منتج تشمل المخفية والخارجية لكشف التصادم. تُقرأ تفاصيل المرشحين فقط؛ الأسعار القديمة غير المثبتة تمنع التحديث، بدل افتراض وحدة السعر.
- الاعتماد يستخدم معاملة SERIALIZABLE: قفل التاجر، وفحص العضوية والحساب والربط وإعدادOAuth، وإعادة بناء الخطة من المنتجات الحالية. تغير منتج أو SKU أو مطابقة أو ربط يرفض الخطة كاملة. يُطبق فقط ما ظهر كحقل متغير؛ يحتفظ بالمخزون والوصف والحالة وغير ذلك عند غياب العمود.
- تُحفظ الإضافات والتحديثات والإيصال معًا أو تُلغى كلها. الطلب المكرر بنفس UUID يعيد الإيصال؛ طلب مختلف لنفس المراجعة المعتمدة يرفض. إيصال الحالة «دون تغيير» لا يكتب صف المنتج. حذف المراجعة لا يحذف المنتجات أو الإيصال.
- المراجعة مرقمة ومصفاة مع القيم الأصلية وخطة الصف نفسه، وتحقق صريح من الأعداد والهوية وربط الإيصال. وصول المستخدم الآخر أو تيننت آخر أو مشاهد إلى تفاصيل المراجعة ممنوع.

نجحت **158 حالة** وحدة/حدود تشمل API والمبالغ والخطة والقارئ والمزود والاستيراد السابق، و**52 حالة MySQL**:28 للمراجعة الجديدة و13 لعزل المصدر و11 رجعية لاستيراد الملفات. شملت فقد الرد بعد الالتزام، تعطل حفظ الإيصال بعد الكتابات والتراجع الكامل، اعتمادين متزامنين، ومراجعتين متنافستين على SKU نفسه، والتغييرات الطارئة والصلاحيات والعبث بالنتائج. نجح TypeScript وبناء الواجهة والخادم والعامل وحد حزمة العميل.

## حدود المرحلة والمتابعة

طُبق الترحيل176 على قاعدة الاختبار المحلية sari_pages_test فقط دون تقديم سجل ترحيلاتها القديم. لم تتغير إعداداتOAuth العامة؛ اختبارات SQL نفذت استعلام إعداداتها الحقيقي ثم استبدلت نتيجته ببيانات اختبار، وكل ردودGoogle محاكاة. لا كتابة إلى Sheets ولا استدعاء مزود حقيقي.

الاعتماد يطبق **اللقطة التي قرأها التاجر**؛ لا يعيد جلب الورقة لحظة الاعتماد. ستعرض الشاشة القادمة وقت القراءة والنطاق وحدوده وخيار إعادة المراجعة بوضوح. لا تغيير واجهة في هذه المرحلة، ولا دليل جديد علىSafari/iPhone. API القديم باقٍ مؤقتًا حتى ربط الشاشة والموك أب ثم إغلاقه. أعداد تغطية الصفحات ثابتة. كوميت محلي على main؛ لا رفع ولا نشر.
