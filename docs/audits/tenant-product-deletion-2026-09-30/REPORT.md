# المرحلة 80 — مراجعة حذف المنتجات

أضيفت `products.editor.deleteReview/deleteWrite/deleteReceipt`. تعيد المراجعة المنتجات المحددة وأسماءها وأسعارها وحالاتها وعدد الخيارات والمتغيرات والمراجع المانعة. التنفيذ يحتاج موافقة صريحة وبصمة المراجعة نفسها، ويعيد فحص الصلاحية والمصدر وكل المنتجات قبل حذف أي صف.

## السلوك

- مجموعة من1 إلى100 معرف صحيح وفريد، بترتيب ثابت. مرجع مفقود أو أجنبي يرفض المجموعة كلها، دون تخطيه وادعاء نجاح جزئي.
- الحذف والإيصال معاملة واحدة بعزل Serializable، مع قفل المتجر والمنتجات والتفاصيل. فشل حذف صف متأخر يرجع الصفوف السابقة. تكرار الطلب المتزامن يعيد إيصالًا واحدًا.
- تشمل البصمة بيانات المنتج ومحتوى خياراته ومتغيراته ومصدره وأعداد المراجع. تغير المنتج أو تفاصيله بين المراجعة والتنفيذ يوقف العملية.
- تمنع المراجعة حذف منتج ذي مصدر خارجي، أو مكافأة ولاء، أو مقارنة منافس، أو تقييم عميل، أو عرض مخصص لمنتجات يشمله. إذا تعذّر فهم قائمة منتجات عرض، يمنع الحذف حتى إصلاح المرجع بدل تخمين أنه غير مرتبط.
- تمنع تفاصيل تحمل تيننتًا مختلفًا حذف صفوفها عبر cascade. الخيارات والمتغيرات السليمة تظهر أعدادها في المراجعة، ثم تحذف مع أصلها عند الموافقة.
- تتوقف مراجعة منتج يتجاوز500 خيار أو500 متغير بدل إخفاء التفاصيل الزائدة ثم الحذف. هذا حد معلن للمسار، وليس ادعاء تغطية بيانات تاريخية غير محدودة.
- يفحص الاسترداد التيننت والمنفذ؛ فقد رد commit لا يستدعي حذفًا جديدًا. يستخدم إيصال الحذف جدول المرحلة79، فلا يلزم ترحيل آخر.

## التحقق

100 اختبار وحدة وعقد ناجحًا، و19 اختبار MySQL ناجحًا للمحرر والحذف. نجح فحص الأنواع وبناء التطبيق والخادم والعامل وميزانية الحزمة. تشمل الاختبارات حذف مجموعة وخياراتها ومتغيراتها، رفض نسخة تغيرت، منع مصادر ومراجع وتيننتات غير صالحة، صلاحية متغيرة، تراجع المجموعة، إعادة متزامنة، وفقد رد الحفظ ثم استرداده.

الاختبارات محلية على تيننتات مؤقتة في `sari_pages_test`، ولا تحتوي حذفًا من حساب التاجر الحقيقي أو أي اتصال بمزود خارجي.

## المتابعة والحدود

هذه واجهات خلفية للواجهة الجديدة؛ صفحة المنتجات الحالية لم تتحول بعد، و`delete/bulkDelete` القديمتان ما زالتا مفتوحتين حتى نقل المستهلك. ستعرض الشاشة سبب منع الحذف وتتيح مراجعة المنتج وأرشفته عند الحاجة. حذف المنتج لا يحذف الطلبات التاريخية التي تحفظ بيانات بنودها منفصلة، وليس عملية حذف معرفة من محادثات أو ملفات مرفقة.

لا يصح تفسير فحص المراجع بوصفه ضمانًا لكل كاتب قديم أو تكامل خارجي؛ مسارات إنشاء المراجع القديمة التي لا تتحقق من وجود المنتج تبقى بحاجة تدقيق مستقل، خصوصًا الكتابة بعد اكتمال حذفه. القراءة والمراجعة تستخدمان بيانات النظام المحلية، ولا تثبتان حالة المزود الخارجي. التغطية التصميمية ثابتة ولا نشر؛ التالي تحويل الشاشة والمحرر والمراجعة والمسودات إلى التصميم الجديد ثم الموك أب.
