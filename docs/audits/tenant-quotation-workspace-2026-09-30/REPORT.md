# صفحة عروض الأسعار — المرحلة 53

أُزيلت واجهة SalesHub السابقة واستُبدلت بمساحة عروض واضحة: ملخص شامل، هدف الشهر، قائمة قابلة للبحث والتصفية والترقيم، ثم تفاصيل العرض ومراجعة إجراءات الحفظ والإرسال. لا تختفي عروض بعد أول50؛ القراءة تعرض20 في الصفحة وتصل إلى بقية الصفحات من العقد الموحد.

## مطابقة الخصائص

| الوظيفة | التطبيق الحالي |
|---|---|
| قائمة العروض | بحث حرفي بالعميل والهاتف والرقم، كل الحالات بما فيها غير المعروف، ترقيم وعدد النتائج، حالة الفراغ وفشل القراءة والصلاحية |
| الملخص | جميع العروض والحالة المقبولة والعينة، قيم العملات منفصلة، دون جمع SAR وUSD أو ادعاء إيراد محصّل |
| هدف الشهر | النسخة والفترة من الخادم، المبلغ الدقيق، الصفر مسموح، مراجعة تعارض ثم حفظ جديد صريح، تفسير عينة الإنشاء الشهرية |
| الإنشاء | عميل وهاتف اختياريان،50 بندًا، اسم ووصف وكمية وسعر، SAR/USD، ضريبة وصلاحية، مجموع مشترك صحيح، أخطاء الحقول مع التركيز على أول خطأ |
| المسودة | حفظ بجلسة المتصفح لمدة24ساعة بنطاق المستخدم والتيننت، إغلاق وعودة دون فقد، حذف محلي بتأكيد مستقل، مسح عند الخروج |
| الحفظ | مرجع محفوظ قبل الطلب، قفل النقر المتكرر، إعادة المحاولة بالمرجع نفسه، قراءة إيصال بعد فقد الاستجابة دون إعادة كتابة، إهمال رد بعد الخروج |
| التفاصيل | البنود والأوصاف كاملة والمبالغ والنسخة والصلاحية والحالة، المحافظة على النص القديم وحد العرض، رابط المحادثة المملوكة |
| نسخ العرض | تنسيق محلي من البيانات المعروضة؛ لا اختيار قالب ولا شروط تلقائية، منع النسخ الكامل عند نقص البنود |
| قبول/رفض | فتح مراجعة للمحتوى والحالة قبل التنفيذ، حماية النسخة واتفاق الطلب والصلاحية، إدارة الصلاحيات من الخادم |
| الإرسال | شاشة المرحلة52 نفسها؛ المراجعة والإيصال متاحان حتى للعروض المغلقة دون إعادة إرسال تلقائية |

أُضيفت صلاحيتا الإدارة والهدف لنتيجة مساحة القراءة باستخدام الدور المؤكد في الراوتر، مع بقاء الحماية داخل الكتابات. حُدّ هاتف المسودة الجديد إلى8–15 رقمًا مع علامة+اختيارية، بما يوافق مرحلة الإرسال. المسودات المحلية تتضمن محتوى العمل، ولا تغادر المتصفح إلا عند حفظ العرض صراحةً.

## التحقق

- نجحت **258 حالة** في `tests.json`، تشمل17 رحلة واجهة و6 حالات مخزن/مدخلات، وحدود القراءة والكتابة والمراجعة والإرسال والصلاحيات والاستعادة. فشل عابر في صياغة ملف الاختبار أُصلح قبل التشغيل النهائي.
- نجح فحص TypeScript والبناء. فحص الترجمة النهائي:9387 استدعاء و417 مفتاحًا ديناميكيًا دون مفاتيح مفقودة. حجم مدخل البناء103388 بايت gzip.
- نجحت132 حالة لحفظ الخصائص واتساق الحصر في `inventory-tests.json`. الحصر الحالي126مسارًا و273ملفًا و1903عناصر، مع294قراءة hook و18قراءة برمجية و4طلبات متصفح، ولا رابط حرفي مفقود أو صفحة يتيمة. هذه أعداد مصدر وليست نسبة اكتمال.
- التيننت المحلي نفسه: حُفظ العرض `Q-260930-a75feb427b8d447c93a2b6ac11e55500` بثلاث وحدات×10.01 وضريبة4.50 وإجمالي34.53، ثم سُجل القبول بعد شاشة المراجعة وظهرت النسخة2. هذه بيانات فحص اصطناعية فقط.
- تحققت رسائل الحقل المطلوب، الإغلاق واستعادة المسودة، البحث عن«مرحلة53»، ونسخ التفاصيل كاملة مع قراءة محتوى الحافظة. استعادة التركيب اختُبرت آليًا؛ محاولة إعادة تحميل IAB مع تنبيه المسودة لم توفر دليل إعادة تحميل مستقلاً فلا ندعيه.
- عند480×860: عرض مستند الصفحة450 دون زيادة أفقية، لوحات المحتوى420، لا زر أقل من44. التفاصيل داخل حوار418×828، وجسمها الداخلي362 دون زيادة أفقية، وأزرار النسخ والسجل44داخل التذييل الظاهر. أُعيد العرض إلى الطبيعي. دليل المكتب `desktop-final.png`؛ خلل أداة تصوير العرض الضيق مستمر منذ المرحلة52.
- لا استدعاء لمزود رسائل أو خدمة دفع أو ذكاء اصطناعي خارجية.
