# المرحلة 225 — مصدر اقتراحات الرد

أصبحت الاقتراحات والرد المخصص وتحسين المسودة تتطلب صلاحية الرد داخل المتجر المحدد. لا تعتمد الاقتراحات على رسائل المتصفح أو اسم العميل المرسل منه؛ تُقرأ المحادثة المملوكة للتيننت مع الذاكرة ومصادرها والعروض وأدوار المتحدثين من لقطة التخزين المعزولة. بقيت أسماء الإجراءات ومدخلاتها الأساسية والردود السريعة والأنماط الخمسة للتحسين متاحة.

يفحص الخادم الأدلة مرة أخرى بعد التوليد. تغيّر العميل أو الرسائل، بما فيها تعديل بعد حد المقتطف، أو إصدار التسليم يمنع إعادة الاقتراح القديم. الربط الداخلي يتضمن بصمة المحتوى الكامل ورقم العميل ولا يُمرر الرقم أو بصمته إلى النموذج. المقتطفات محدودة إلى 600 حرف، ويُصرّح للنموذج أنها ليست النص الكامل وأن معلومات المتجر المرسلة غير متحققة. هذا لا يثبت دقة النموذج أو حصانته الكاملة من حقن التعليمات؛ كل ناتج مسودة تتطلب مراجعة الموظف.

أُلغي النجاح الوهمي بردود عامة عند فشل المزود، وأضيف تحقق صارم لأربعة أنماط متميزة وحدود النصوص والنتيجة. الأخطاء لا تسرب رسائل المزود. صُححت قوالب التوفر والسعر والشحن والتعويض التي كانت تؤكد وقائع غير مثبتة، وأصبحت تطلب معلومات للتحقق.

- نجحت 78 حالة صلاحيات وعقود، و32 حالة MySQL، و136 حالة لحصر الميزات؛ المجموع 246 دون فشل أو تخطٍ.
- تتضمن الحالات تيننتًا آخر، حسابًا بلا صلاحية، حقول هوية مزورة، نتيجة تالفة، فشل المزود، محادثة خالية، تغيّر الرقم والملكية ووصول رسالة وتعديل ذيل رسالة طويلة أثناء التوليد، واستمرار خصائص الرد المخصص والتحسين.
- نجح TypeScript وبناء المشروع. بقيت 126 مسارًا دون حذف مسارات. لا مفاتيح ترجمة جديدة ولا فحص بصري في هذه المرحلة الخلفية.

اختُبر الذكاء الاصطناعي باستجابة محاكاة فقط، ولم تُرسل رسالة خارجية أو تُستخدم خدمة مدفوعة أو يُنشر المشروع. التالي واجهة الاقتراحات: الفشل الواضح، عزل النتائج المتأخرة، وحفظ مسودة التاجر عند إدراج اقتراح.
