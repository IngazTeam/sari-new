# المرحلة133 — مطابقة نسخة المنتج عند الموافقة والفاتورة

2026-09-30، محلي على main دون push أو نشر.

وجد تتبع المنتج إلى الشراء أن قارئ SQL يستخدم v.updatedAt، بينما جدول product_variants يعيد updated_at. كانت قيمة variantVersion تُحفظ بالنص undefined. صُحح المرجع ليكون بصمة من وقت التحديث الصحيح وهوية النسخة واختياراتها والسعر ووحدته والتفعيل. وجود وقت تحديث مفقود يوقف إنشاء العرض.

تتضمن البصمة المقاس/اللون وSKU والباركود والوزن، فتكتشف تعديلًا يقع في الثانية نفسها حتى لو بقي السعر والاسم ثابتين. إعادة فحص القبول والفاتورة تستخدم البصمة نفسها. العرض القديم غير المقبول ذو مرجع undefined لا يُرقّى بصمت؛ يحتاج عرضًا جديدًا وموافقة جديدة. لا تعديل على بيانات المنتجات أو الطلبات القائمة ولا إرسال أو دفع خارجي.

## التحقق

-99 حالة MySQL ناجحة عبر اتفاقيات الشراء وهامش الفاتورة وتفاصيل المنتج.
-8 حالات جديدة تغطي قبول النسخة غير المتغيرة، تغير الوقت أو الاختيارات أوSKU أو الباركود أو الوزن، تغير النسخة قبل اعتماد الفاتورة، ورفض مرجع العرض القديم. تؤكد عدم إنشاء طلب في حالات التعارض وبقاء الفاتورة قيد المراجعة.
- TypeScript وبناء العميل والخادم والعامل ناجحة. لم تتغير مكونات الواجهة أو الترجمة أو المسارات في هذه المرحلة.

التالي: انخفاض مخزون المنتجات ونسخها، ثم متابعة بقية سجل صفحات وخصائص التيننت. لم يتحقق نشر أو فحص Safari/iPhone فعلي.
