# المرحلة 438 — تنفيذ تحليل المنافس بهوية دائمة

2026-10-04، main، محلي دون دفع أو نشر.

استُبدل التنفيذ القديم الذي يكتب درجات ومنتجات متفرقة بعامل يستخدم مصدر0202 وحفظًا ذريًا. يُجدّد التفويض دون تداخل، ويُراجع قبل التحليل والاستخراج والحفظ. التتبع المحلي للسياق يضيف فحص الصلاحية قبل DNS وقبل فتح اتصال الموقع، وقبل تجهيز استدعاء النموذج، ويرفض اختلاف التيننت. الطلبات الخارجية السابقة لا تُلغى بأثر رجعي، لكن النتائج المتأخرة لا تُحفظ.

تستعمل المنتجات نسخة المحتوى نفسها التي حللها الموقع. أضيف وضع استخراج صارم للمنافس: فشل النموذج أو JSON المشوه أو النص غير الكافي لا يُحوّل إلى نجاح فارغ؛ يبقى سلوك الاستخراج الاختياري للمتصلين الآخرين كما كان. تُراجع درجات ومنتجات النتيجة قبل الحفظ ولا تخزن تفاصيل المزود الخاصة في رسالة الفشل.

قراءة القائمة أو التفاصيل تسوي المهام التي انتهت صلاحيتها، فيتحول التقرير المنقطع إلى فشل مفهوم بدل البقاء جارياً. أضيف قارئ لمحاولة المستخدم والتيننت الحاليين، ومعرّف اختياري للإضافة خلال انتقال الواجهة. الطلب المتكرر بمعرّفه لا يشغّل عاملاً جديدًا؛ رد القبول لا يدعي اكتمال التقرير. أضيف حارس إصدار competitor-analysis-durable-0202 لمنع الرجوع إلى عامل قديم بعد الترقية.

التحقق: 84 حالة للرواتر والعامل والاستخراج والنقل، 55 حالة تراجع للواجهة وتحليل المواقع وخصوصية السجلات وبوابة النموذج، 44 حالة MySQL تشمل العامل الفعلي مع مزود محاكى، و45 فحص إصدار. نجح TypeScript وبناء التطبيق. البيانات الاصطناعية تنظف بعد الاختبارات ولا يوجد اتصال بمزود خارجي.

التالي: جعل معرف الإضافة مطلوبًا، وحفظ مرجعه في جلسة المتصفح واستعادته من الواجهة والموك أب. لا يُدّعى بعد ضمان استعادة طلب أرسلته واجهة قديمة دون المعرف. يبقى توليد المقارنة الجديدة وتحليل تقارير المواقع المنفصل ومراجعة الصفحات المتبقية. لا Safari/iPhone فعلي أو نشر.
