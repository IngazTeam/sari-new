# المرحلة 503 — تصحيح مصدر تقرير اكتساب العملاء

كان التقرير يجلب تفضيلات جميع ملفات العملاء إلى الخادم، ويصنف التفضيل الناقص أو JSON التالف على أنه مصدر مباشر/عضوي، ويعيد أرقامًا صفرية عند غياب اتصال قاعدة البيانات. تستخدم الصفحة أيضًا المالك الافتراضي، وتوحي بقياس عائد الإعلان، رغم أن الحقل المقروء لا يثبت تكلفة الإعلان أو التحويل أو نسبة احتراف المبيعات.

أضيف `analytics.acquisitionWorkspace` للتيننت المختار في الطلب، بعقد بيانات محدود ومتحقق، مع إعادة فحص العضوية وحالة الحسابين تحت قفل قراءة. يقرأ SQL مجموعات محدودة بدل إعادة ملفات التفضيلات، ويُرجع التصنيف والعدد فقط دون اسم العميل أو هاتفه أو الوسم الحر. لا تتحول قيم مثل `__proto__` إلى مفاتيح كائن ديناميكية. تبقى البيانات الناقصة أو ذات النوع غير الصحيح غير منسوبة، وتُجمع الوسوم غير المعروفة تحت «أخرى»؛ لا تصبح مباشرة دون وسم مباشر صريح.

تعتمد النسب على عدد ملفات العملاء في الفترة. أضيفت فترات كل السجل أو 30 أو 90 يومًا وفق تاريخ إنشاء الملف وبساعة UTC من قاعدة البيانات، مع استبعاد السجلات المستقبلية. ليست هذه فترة وقوع الإعلان أو إثبات اكتساب جديد. القراءة القديمة تمر بالمصدر المصحح نفسه، وترفض تيننتًا مختلفًا قبل استدعائه؛ لا تعطي القراءة المتعذرة صفرًا ولا تكشف نص الخطأ الداخلي.

## التحقق

- نجحت 79/79 حالة وحدة وعقد وراوتر وتراجع تحليلات، و12/12 حالة MySQL في تيننتات مؤقتة تم تنظيفها.
- شملت الاختبارات النسب والمجاميع المتناقضة والحدود العددية، UTC والفترات، JSON غير الصالح، وسومًا حساسة أو شبيهة بمفاتيح الكائن، عزل المتاجر، العضوية الملغاة، المالك الملغى، توقف الحساب، والقراءة دون تعديل المعرفة.
- صحح اختباران أوليان: قيمة «تصنيف متناقض» كانت تطابق العدد الصحيح أصلًا، وعينة تعطيل حساب استخدمت قيمة enum غير موجودة. أُعيدت المجموعات بعد التصحيح ونجحت.
- نجح TypeScript وبناء الإنتاج وحد حزمة الدخول. بقي تحذير حجم الحزم المعتاد.

مرحلة 504 التالية تستبدل الصفحة القديمة بالمكوّن المشترك والموك أب والتفسير الصحيح للأرقام والترجمة والحالات. لم تنفذ هذه المرحلة تتبع إعلانات جديدًا أو تدّع وجود تغذية تلقائية لهذا الوسم؛ البحث في مواضع `acquisitionSource` لم يثبت مسار كتابة نشطًا من كاشف المصدر القديم. لا نشر أو اختبار سفاري/آيفون فعلي.

إيضاح بعد المرحلة 504: فحص الأنواع في الواجهة أثبت أن الراوتر المستقل المختبر هنا لم يكن مركبًا تحت `analytics` في التطبيق الرئيسي، وكذلك الإجراء الذي كانت تستدعيه الصفحة القديمة. عولج الربط بوحدة إجراءات مشتركة واختبار تركيب وتجربة فعلية؛ راجع [تقرير المرحلة 504](../tenant-acquisition-workspace-ui-2026-10-04/REPORT.md).
