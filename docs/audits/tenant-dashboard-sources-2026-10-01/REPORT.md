# المرحلة 196: المصادر وحالة الربط في الرئيسية

أضيف dashboard.sources ليعيد عقدًا معزولًا للتيننت يتضمن مجموعات المعرفة وحالات استخراج الملفات والجمهور وسجل المنصة المحددة. أُعيد استخدام قارئ المجموعات القائم، مع تمديد محدود يسمح بقراءات إضافية قبل إغلاق معاملة القراءة نفسها. لا تهيئة جداول أثناء القراءة ولا قراءة مفاتيح أو فك أسرار.

المزامنة تخص المنصة المختارة: سلة وبيان من سجلاتهما، وزد بثلاثة تواريخ مستقلة للمنتجات والطلبات والعملاء، وبقية المنصات المسجلة من سجلات الربط مع تقييد نوع المنصة والتيننت. لا يتم إنشاء أسماء جداول من مدخلات. تُفرّق الواجهة بين عدم وجود ربط والحالة غير المعروفة والخطأ والتوقف وانتظار التحقق؛ الإعداد المحفوظ لا يعني اكتمال المزامنة. المتدربون النشطون لبيان منفصلون عن ملفات العملاء للمتاجر.

حُفظت أعداد المصادر والجمهور ووجهات الإدارة، وأضيف تفصيل استخراج الملفات والتحذير من جمع المجموعات المشتقة كأنها مصادر مستقلة. يرفض المكوّن بيانات تيننت مختلف أو عقدًا متناقضًا أو نتيجة قديمة بعد الخطأ. أُبقي API القديم متاحًا للتوافق، لكنه لم يعد مصدر الرئيسية، ووُثق الاستبدال في سجل حفظ الخصائص.

نجحت179حالة، منها43للملخص والواجهة والمعاملة و136للحصر وحفظ الخصائص. نجحت10حالاتMySQL، تشمل مجموعات المعرفة السابقة وقراءة سجل سلة وزد والجمهور والتغيير المتزامن للمنصة أثناء اللقطة. نجحت الأنواع والبناء والترجمة. صُحح نوع معاملات mysql2 وصياغة محاكاة التزامن، ثم كشف الحصر وجهتين غير موجودتين لإدارة الربط وصُححتا إلى platform-integrations قبل إعادة نجاح الفحص.
