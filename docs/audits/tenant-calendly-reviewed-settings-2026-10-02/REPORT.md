# المرحلة 340 — إعداد Calendly المراجع واستعادة النتائج

2026-10-02، main؛ لا رفع أو نشر أو إرسال رسائل فعلية.

## التنفيذ

أضيف saveWorkspaceSettings بعقد صارم يربط الاختيار ببصمة الربط ورقم طلب قابل للاستعادة. تتكرر مراجعة الصلاحية والقيم داخل قفل التيننت قبل حفظ مفتاح syncToWhatsApp وحده باستخدام JSON_SET؛ تحفظ بقية الإعدادات والاعتماد. لا يُفعل الخيار مع ربط معطل أو اعتماد أو هوية أو تسجيل webhook محلي ناقص. يمكن إيقاف الخيار في هذه الحالات. البيانات التالفة تُرفض دون استبدال صامت.

يحفظ الاختيار ونتيجة النجاح معًا، وتظل النتيجة غير محسومة عند بدء التنفيذ وفشل إكماله. لا يُلغى نجاح حُفظ وفُقد تأكيده. أضيفت مداخل استعادة إيصال صاحب الطلب، وقراءة العملية المانعة، ومراجعتها بواسطة مخول. كل المداخل الخمسة عشر مقيدة بالتيننت المختار وصلاحية التكاملات؛ لا يقبل أي منها actorId أو merchantId من المدخلات، ولا يعرض أخطاء التخزين الخام.

## التحقق

207 اختبارات معزولة و38 اختبار MySQL ناجحة، وصفر فشل مجموعات. فحص الأنواع والبناء ناجحان. شملت الاختبارات حفظ القيمة نفسها، تعارض نسخة المراجعة، العبث بالطلب المكرر، غياب جاهزية الربط، الإعدادات التالفة، سحب العضوية، فشل حفظ الإيصال مع rollback للقيمة، واستعادة النجاح بعد فقد تأكيد commit.

## الحدود والتالي

هذه مداخل الخادم الجديدة؛ الصفحة القديمة لم تنتقل إليها بعد، ولم يُغلق مدخل updateSettings القديم حتى ترحيل الواجهة. الجاهزية هنا محلية وليست فحصًا حيًا لصلاحية اعتماد المزوّد أو ضمانًا لتسليم واتساب. التالي الربط والفصل والفحص بالمراجعة ثم مزامنة ذرية، فالواجهة والموك أب وإغلاق المداخل القديمة. لا Safari/iPhone فعلي.
