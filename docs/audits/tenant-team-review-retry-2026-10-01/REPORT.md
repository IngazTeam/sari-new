# المرحلة 218 — استعادة طلب مراجعة الفريق بعد انقطاع الاستجابة

أصبحت هوية طلب المراجعة وسببها محفوظين في sessionStorage قبل استدعاء الخادم. عند إغلاق القسم أو إعادة تركيبه تُستعاد الهوية والسبب نفسيهما، فلا تُنشأ مراجعة إدارية ثانية بسبب فقد الاستجابة الأولى. مفتاح الحفظ معزول بالحساب والمتجر والنوع والمحاولة والمحادثة وصاحب الرد. لا يُحفظ نص الرسالة أو ملف الصوت.

يُرفض السجل التالف أو المنقول من سياق آخر، ويوقف فشل التخزين العملية قبل استدعاء الخادم. تظهر إعادة محاولة القراءة، ويحتاج حذف المرجع التالف إلى إجراء صريح يؤكد مراجعة السجل الإداري. لا يرسل هذا الإجراء أي طلب مراجعة تلقائيًا. السبب محفوظ حتى حسم الطلب. لا يحذف اكتمال قديم مرجع محاولة أحدث، ولا تُقبل آثار نتيجة وصلت بعد إغلاق العنصر.

تُرسل حقول عقد API فقط، دون غلاف التخزين أو هوية الحساب المشتقة محليًا. خدمة المراجعة الحالية وصلاحياتها لم تتغير. لا يعيد التحقق إرسال رسالة للعميل.

- نجحت 139 حالة لاختبارات التخزين والواجهة وصلاحيات مراجعة الفريق وصفحة المحادثات، و136 حالة لحصر الميزات وحفظها؛ المجموع 275، بلا فشل أو تخطٍ.
- تغطي الحالات انقطاع الاستجابة، الإغلاق أثناء الطلب، الاستعادة، إعادة استخدام UUID والسبب، فشل الكتابة الصامت، فشل الحذف، اختلاط السياقات، وعدم حذف المرجع اللاحق بنتيجة قديمة.
- نجح TypeScript وبناء المشروع وفحص الترجمة العالمي: 11311 استدعاءً و883 مفتاحًا ديناميكيًا محسومًا، دون مفاتيح ناقصة أو أخطاء استبدال أو استدعاءات غير محسومة. بقي تنبيه البناء المعروف لحجم بعض الحزم.
- لم تتغير قاعدة البيانات أو خدمة الخادم، ولم تُكرر اختبارات MySQL التي نجحت في المرحلة 217. التحقق الجديد سلوكي بمكوّن React الفعلي وبيانات محاكاة؛ لا تدّعي هذه المرحلة لقطة بصرية جديدة أو اختبار Safari/iPhone فعليًا.

يبقى المرجع طوال جلسة التبويب دون مهلة انتهاء، حتى لا تُفقد هوية عملية غير محسومة بسبب الوقت. sessionStorage لا يضمن الاستعادة بعد إغلاق المتصفح كليًا؛ حماية الخادم وسجل المراجعات يبقيان المرجع النهائي. لا نشر أو إرسال خارجي. التالي تسليم المحادثة ومصادر أدلتها ثم نوافذ التصعيد والعروض والتصميم والموك أب.
