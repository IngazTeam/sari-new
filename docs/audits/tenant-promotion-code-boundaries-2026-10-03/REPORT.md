# المرحلة 378 — حدود كود العرض التلقائي

أصبح الإنشاء يرفض إنشاء كود لا يفرض شروط العرض: نطاق منتجات أو فئات، بداية مستقبلية، حد أدنى يتجاوز قطعة، أو انتهاء سابق. يبقى حفظ العرض دون كود ممكنًا. يشمل الحفظ الذري العرض والخصم، فلا يبقى خصم يتيم عند الرفض.

أضيف شرح داخل النموذج ورسائل عربية وإنجليزية لأسباب الرفض، مع إخفاء أخطاء البنية الداخلية. أضيفت قدرة الإصدار `promotion-code-boundaries-v1` لمنع الرجوع عبر المحدّث إلى إصدار دون الحماية.

التحقق: 49 اختبار وحدة، و15 MySQL على تيننتات مؤقتة، و20 اختبار إصدار؛ دون فشل أو تخطي. نجح فحص TypeScript والترجمات (13035 استدعاء و854 مفتاحًا ديناميكيًا، بلا مفاتيح مفقودة) والبناء في 13.58 ثانية. فُحص شرح الكود في المتصفح المحلي، ودليله `code-terms.png`.

هذه مرحلة تصحيح شروط الكود، وليست اعتمادًا للواجهة القديمة أو دليل التحويل الظاهر فيها. التالي المراجعة قبل القرار وإيصال الحفظ، ثم استبدال واجهة العروض وربط الموك أب وفحص الهاتف. لم يحدث نشر أو إرسال خارجي، ولم يُفحص Safari أو iPhone فعليًا.
