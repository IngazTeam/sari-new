# المرحلة 471 — تعطيل رابط الدفع بعد مراجعة النسخة

أضيف payments.linksWorkspace.disableReviewed بمعرف الرابط وبصمة النسخة ومراجعة صريحة. يفحص المالك الحي والمتجر النشط ويقفل سجل الرابط داخل المعاملة، ثم يقارن البصمة المقيدة بالحساب والتيننت وجميع حقول الرابط. لا يغير سجلًا غائبًا أو أجنبيًا أو نسخة تبدلت، بما فيها metadata غير المعروضة.

الإجراء يغير is_active/status فقط ويحافظ على المعلومات المالية والعدادات والعلاقات. لا يقر النجاح إلا بتأثر صف واحد وإعادة قراءة حالة التعطيل الفعلية قبل الالتزام. تعطيل سجل معطل بالفعل يرجع already_disabled بعد مراجعة نسخة حالية، أما إعادة إرسال نسخة قديمة بعد نجاح سابق فترجع تعارضًا، لتدفع الواجهة لاحقًا لقراءة النتيجة دون إعادة طلب مجهول. فشل الالتزام الموروث من حارس المعاملة يرجع نتيجة غير محسومة ولا يتحول لنجاح.

نجحت124حالة وحدة وعقد، و16MySQL، والأنواع والبناء. تشمل رفض عدد صفوف0/2 أو إقرار ناقص، ورفض نتيجة متفائلة لا تطابق السجل، وحفظ الحقول الأخرى، وغياب الرابط وتيننت آخر وعضو مشاهد ومتجر pending، وتغير بيانات مخفية. عند طلبين متزامنين بالبصمة نفسها نجح واحد ورُفض الآخر كتعارض. يمكن للمالك تعطيل علم تشغيل تالف بمراجعة صريحة دون اعتباره صالحًا قبلها. أمثلة MySQL تُنظف بعد الاختبار ولا تتصل بمزوّد.

التعطيل لا يسترجع أموالًا ولا يلغي تحصيلًا أو محاولة دفع بدأت من قبل. لا ترحيل جديد. الواجهة والإجراء القديم لم يربطا/يغلقا بعد؛ التالي إنشاء رابط آمن مع استعادة الطلب ثم واجهة الروابط والموك أب وإغلاق القديم. لا نشر أو اختبار Safari/iPhone فعلي أو اختراق شامل.
