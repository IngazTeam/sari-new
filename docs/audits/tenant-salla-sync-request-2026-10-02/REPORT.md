# مرحلة 301: طلب مزامنة سلة واستعادة نتيجته — 2026-10-02

أضيف مسار طلب دائم بمعرّف UUID وهوية الحساب والتيننت وبصمة الربط ونوع المزامنة. يسجل الطلب وسجل المزامنة ذريًا ثم يعيد إيصال انتظار النتيجة، ويتابع التنفيذ دون إبقاء طلب المتصفح مفتوحًا. إعادة المعرّف تقرأ النتيجة المحفوظة ولا تشغل المزامنة مرة أخرى، حتى بعد تغير الربط. يُرفض استعمال المعرّف نفسه من حساب آخر أو بقصد مختلف.

طلب واحد من هذا المسار ينفذ لكل تيننت، وثلاثة طلبات جديدة بحد أقصى خلال خمس دقائق لجميع الحسابات المشتركة. قبل الشبكة وداخل حفظ المنتج تتجدد مهلة تنفيذ مدتها 60 ثانية مع فحص الصلاحية والربط. توقف التجديد يجعل النتيجة منقطعة؛ لا يُدّعى أن المنتجات السابقة لم تُحفظ، ولا يظهر عدد اكتمال مؤكد. بدء طلب جديد يمنع العامل القديم من مواصلة الكتابة. لا يوجد استئناف تلقائي بعد تعطل العملية.

النتائج تميز الانتظار والنجاح والفشل والانقطاع. النجاح يتطلب سجلًا مؤكدًا وعددًا صحيحًا؛ عند فقدان تأكيد commit يمكن قراءة النتيجة المخزنة، دون إعادة التنفيذ. السجل المجهز مسبقًا يُفحص للتيننت والنوع والحالة قبل طلب المزوّد، بينما مهام النظام تنشئ سجلاتها كالمعتاد.
