# مصدر قوالب العروض والاختيار الصريح — المرحلة55

أُزيلت القوالب التجارية الثلاثة التي كانت تُزرع بمجرد قراءة قائمة فارغة. كانت تحمل افتراضات ضريبة وصلاحية ودفع وتسليم وضمان دون اعتماد التاجر. لا يحذف الإصلاح أي قالب سبق حفظه، ولا يستنتج أن نصه صحيح.

أصبح مصدر القراءة مستقلًا، مع فحص جاهزية المخطط دون إنشاء بيانات، وهوية تيننت صحيحة، وترتيب ثابت، وفشل واضح عند تعذر المصدر. حد التوافق200سجل؛ إن تجاوزه المصدر يفشل بدل تقديم قائمة مبتورة كأنها كاملة. شاشة مرقمة للقوالب القديمة الكبيرة تبقى مرحلة لاحقة.

أُخضعت قراءة القوالب لصلاحية `analytics.read` مع رسالة خطأ آمنة. تنسيق النسخ القديم يضيف الشروط فقط عند تمرير `templateId` صراحةً؛ غيابه أو null يعني دون قالب، واختيار سجل مفقود أو تابع لتيننت آخر يفشل دون بديل. لا يتصل هذا المسار بمزود ولا يرسل شيئًا. شاشة النسخ الجديدة في المرحلة53 تنسخ أصل العرض دون قالب أساسًا.

## الفحص

- 44حالة معزولة: القراءة بلا كتابة، هوية التيننت، فشل المصدر والمخطط، حد القائمة، حفظ النص، صلاحيات الراوتر، رفض الحقول الزائدة والاختيارات غير الصحيحة، والاختيار الصريح.
- 23حالة MySQL محلية: شملت إعادة قراءة قائمة فارغة مع بقاء الجدول فارغًا، عزل القالب المختار، والتوافق ومراجعات المستندات السابقة.
- نجحت الأنواع وبناء التطبيق. الأدلة في `tests.json` و`mysql-tests.json`.

## التالي

ما زالت كتابات القوالب القديمة تحتاج قفلًا وتسلسلًا للحد20، وحماية تحديث الافتراضي من سجل أجنبي، ومراجعة نسخة قبل التعديل والحذف، وإيصالًا يمنع تكرار إنشاء القالب بعد فقد الاستجابة. ستليها الشاشة الجديدة والموك أب. لم نتعامل مع هذه الفجوات كأنها مكتملة؛ التغطية ثابتة، ولا دفع أو نشر.
