# النقل المراجع لإشعارات الطلبات

المرحلة 415، 2026-10-03. أصبح عامل إشعارات حالة الطلب يستهلك تفويض 0199 المحفوظ مع قرار التاجر، ويثبت صلاحية المراجع والمالك والتيننت والطلب والقناة قبل الحجز، ثم يعيد فحصها تحت الأقفال مباشرة قبل الاتصال بالمزود. يرتبط الإرسال بالنص والمستلم وإيصال القرار وبصمة الطلب والقناة، ولا يثق بمدخلات العامل وحدها.

لكل محاولة رمز حجز جديد. لا يستطيع العامل المنتهي حجز سجل الإرسال أو تعديل محاولة أحدث. الحجز الأول وإعادة المحاولة يتسلسلان تحت قفل التيننت؛ يبقى القفل مع أقفال الحساب والطلب والقناة خلال الاتصال بالمزود وحفظ النتيجة. الإرسال المتزامن أو إعادة تشغيل العامل لا ينتجان اتصالًا ثانيًا بعد وجود قبول مطابق.

الإيصال المطابق وحده يثبت قبول المزود؛ حالة العامل وحدها لا تكفي. تُفحص هوية التيننت والقناة والمزود والاتجاه والنص والمستلم والتفويض والتواريخ. يُحفظ إيصال المزود وتسوية الإشعار معًا. يبقى القبول التاريخي الصحيح ظاهرًا بعد سحب صلاحية المراجع. الرسائل التي رفضها المزود صراحةً يمكن إعادة محاولتها، بصلاحية حديثة وتأخير تصاعدي وحد أقصى ثماني محاولات. النتيجة المجهولة، أو الإيصال المتعارض، أو السجل القديم بلا تفويض، تنتقل للمراجعة دون إعادة إرسال آلية.

## نتائج التحقق

- نجحت 174 حالة وحدة وانحدار، تشمل العامل الجديد، العقود والمدخلات المعدلة، ذرية قرار الطلب، وقواعد واتساب والحملات والجدولة وإشعارات WooCommerce.
- نجحت 97 حالة MySQL مع مزود محاكى، منها 50 حالة للنقل الجديد. شملت تزامن الحجز والإرسال، انتهاء مهلة العامل، سحب الحساب والعضوية والقناة، تغيير الطلب والرمز بعد قراءة القناة، تزوير المرجع والنص والمستلم، الحد الأعلى للمحاولات، والإيصالات المتعارضة.
- اختبرت أربعة أقفال مستقلة أثناء اتصال المزود: التيننت، المالك، الطلب، والقناة. وفشلت محاولات تعديلها المتزامنة كما هو مطلوب. واختبرت فشل حفظ الإيصال، وفشل المعاملة قبل اعتمادها وبعده: لم تتكرر الرسالة؛ النتيجة المثبتة بقيت مقبولة، والمجهولة احتاجت مراجعة.
- نجحت 40 حالة لفحص الإصدار. القدرة المطلوبة الجديدة `order-notice-reviewed-transport-0199` تمنع العودة إلى عامل لا يفرض التفويض.
- نجح فحص الأنواع وبناء الواجهة والخادم والعامل وميزانية الحزمة. يوجد تحذير Vite المعتاد بشأن حجم بعض الحزم.

استُخدمت قاعدة اختبار محلية وتيننتات مؤقتة نُظفت بعد الاختبارات. جميع نتائج المزود محاكاة؛ لا إرسال خارجي، ولا نشر، ولا ادعاء اختبار اختراق شامل أو Safari/iPhone فعلي. لم تتغير الواجهة أو مفاتيح الترجمة في هذه المرحلة. التالي إزالة قراءات الإشعارات وتنفيذ دورة الطلب القديمة غير المستخدمة، ثم متابعة فجوات الحصر الموثقة.
