# المرحلة315: مداخل WooCommerce وحصر الخطوات التالية

الصفحات المرتبطة فعليًا أربع: الإعدادات والمنتجات والطلبات والتحليلات. يوجد ملف إعدادات قديم خارج مسار App؛ لا يُحذف قبل التحقق من مراجع استخدامه. لا تغير هذه المرحلة تصنيف تصميم الصفحات الأربع؛ ما زالت تحتاج المصدر الكامل والواجهة والموك أب.

## الإصلاح

- قراءة الإعدادات وسجل المزامنة وآخر مزامنة تتطلب `integrations.manage`. بقيت قراءات المنتجات والطلبات للأعضاء، بما فيهم المشاهد، والتحليلات تحت صلاحيتها الحالية. لا ادعاء بأن اختيار التيننت كان غائبًا: middleware الحالي يحل العضوية والتيننت المحدد أصلًا؛ أثبتنا ذلك عبر الراوتر المباشر والمركب.
- كل19مدخلًا يرفض غياب مخزن البيانات ويخفي أخطاء الخادم الداخلية بدل عرض تفاصيلها. تحققت الاختبارات من رفض العضوية المفقودة والسياق المزور والمدخلات الزائدة؛ الإجراءات دون معطيات ترفض حقول التيننت أو المستخدم المحقونة.
- تغيير جذر المتجر، بما فيه المسار، يتطلب إدخال المفتاح والسر صراحةً. لم يعد العنوان الجديد يعيد استعمال المفتاح المخفي المحفوظ ويرسله إلى وجهة أخرى. يبقى استعمال المفتاح الحالي متاحًا لنفس العنوان بعد تطبيعه. يمكن إصلاح عنوان قديم غير صالح بإدخال الاعتمادين الجديدين. رفض التغيير الناقص يحدث قبل إنشاء العميل أو أي طلب خارجي.

## التحقق

نجحت223حالة معزولة للراوتر المباشر والمركب والاتصال والمزامنة والمصالحة وwebhook ودورة الطلب، و5حالات MySQL بتيننتات مؤقتة نظيفة: اختيار التيننت، المدير متعدد العضويات، المشاهد ومشرف المبيعات، منع سجل التيننت الآخر، وسحب عضوية المالك وتعليقه. تعالج اختبارات الحالة19مدخلًا. كانت أخطاء الجولة الأولى في افتراض اختبار مصدر قديم وحقول بذرة الاختبار، وصُححت ثم نجحت الجولة النهائية.

نجح TypeScript والبناء17.73ثانية. لم تتغير الترجمة أو الواجهة، ولا ترحيل قاعدة بيانات أو اتصال بمزود خارجي أو إرسال واتساب. الأدلة المحلية `.tmp/tenant-ux/phase315-tests.json` و`phase315-mysql.json` وسجلا الأنواع والبناء.

## ما بقي قبل التصميم

1. مراجعة انتهاء الصلاحية أثناء انتظار القفل والعمل الخارجي؛ فحص الدخول وحده لا يثبت استمرارها. إضافة عقود مراجعة الربط والفصل والطلبات غير المؤكدة قبل تحديث الواجهة.
2. مصدر كامل ومتسق للإعدادات والمنتجات والطلبات والسجلات والتحليلات؛ التحليلات القديمة تقرأ حد2,000طلب، والإيرادات تجمع عملات دون فصل، ويحتاج تاريخ الفترة تحققًا تقويميًا، وعداد المحادثات قد يرجع فراغًا عند فشل القراءة. هذه نتائج تدقيق تحتاج إصلاحًا، وليست مؤشرات مكتملة موثوقة.
3. صفحات جديدة تحافظ على الحقول والخصائص الحالية: إعداد الاتصال والتحقق وwebhook والمصالحة والفصل؛ بحث المنتجات وصفحاتها؛ فلاتر الطلب والتفاصيل والحالة والإشعارات؛ الفترات ومؤشرات المبيعات والعملاء. ثم موك أب بالمكوّنات الفعلية وفحص اللغتين والمقاسات.
4. أثناء توسيع التحقق عُثر على اختبار MySQL قديم لزد ما زال يستدعي `updateSettings` المتقاعد. سيُحدث لإثبات الرفض وحفظ الإعدادات بالطريق المراجع قبل مواصلة WooCommerce. لا يُعاد فتح المسار القديم لإرضاء الاختبار.

هذه مرحلة دخول وحماية أسرار محددة، وليست pentest شاملًا أو إثبات اكتمال حماية جميع العمليات أو اكتمال التصميم. لا نشر.
