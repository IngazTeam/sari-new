# المرحلة 464 — إغلاق إعدادات الدفع القديمة

وُحد merchantPayments في راوتر واحد. تُبقي أسماء getSettings/saveSettings/testConnection القديمة كواجهات رفض ثابتة تطلب تحميل الشاشة الجديدة، مع مصادقة الجلسة والتحقق من اختيار التيننت ومخطط حفظ صارم. لا تلمس الإعدادات أو العضوية أو المزود، ولا ترد بنجاح على الحفظ القديم. workspace/saveReviewed/probeReviewed هي مسارات الشاشة الفعلية.

أُزيل تنفيذ الراوتر المكرر ومساعد verifyMerchantTapCredentialsSnapshot وكاتبه القديم setMerchantPaymentVerifiedIfCredentialsMatch بعد حصر الاستدعاءات. المصدر الجديد يستعمل صلاحية حية وبصمة مراجعة قبل نقل المفاتيح وبعده، ويعيد قراءة نتيجة الحفظ. مسارات روابط الدفع والتحصيل والـwebhooks بقيت مستقلة. مساعد عرض البيانات المحدود وبعض مساعدات إعداد البيانات الداخلية غير المكشوفة كمسارات بقيت، ولا تُعد بديلًا مصرحًا للحفظ من التاجر.

أثبت اختبار الإغلاق تسعة إخفاقات قبل الإصلاح. نجح التشغيل النهائي بـ555 حالة تشمل الإغلاق، المصدر الجديد، الواجهة، صلاحيات الفريق، خصوصية العرض، والتحصيل وwebhooks والاشتراكات. نجحت22 حالة MySQL تشمل جلسات HTTP حية، عزل المتاجر، وبقاء بيانات المفاتيح دون تغيير بعد طلبات قديمة، وخروج DTO الجديد دون أسرار. نجحت الأنواع والبناء و51 اختبار إصدار. أعيد توجيه فحص الادعاء المزور للصلاحية إلى تعديل دور الفريق، ليبقى اختبار صلاحية فعليًا بعد تقاعد مسار الدفع القديم.

أضيفت قدرة payment-settings-reviewed-only-v1 إلى حارس الإصدار ودليل التشغيل لمنع الرجوع لإصدار يعيد المداخل القديمة. لا ترحيل جديد، ولا اتصال Tap فعلي أو تحصيل أو نشر.

التالي: استكمال صفحات سجل المدفوعات وتفاصيله وروابطه ومصادر بياناتها، ثم بقية الفجوات المسجلة. حدود Safari/iPhone الفعلية والتنقل الداخلي بمسودات ما زالت معلنة؛ لا ادعاء اكتمال100%.
