# المرحلة351 — عزل أكواد الخصم وصلاحياتها

كشف تدقيق `/merchant/discounts` تنفيذين متوازيين للإجراءات الستة يعتمد كلاهما متجر المالك بدل التيننت المختار. وُحد مسار التطبيق والوحدة المستقلة على `discountsRouter`، مع صلاحية القراءة لأعضاء المتجر وصلاحية `campaigns.manage` للإنشاء والتعديل والحذف. يعاد إثبات الحساب والعضوية وحالة المتجر داخل معاملة التخزين، مع أقفال حتى الالتزام. العضوية المعطلة تمنع رجوع المالك إلى صلاحية افتراضية.

كل قراءة أو تعديل أو حذف للسجل مقيد بـmerchantId وid في SQL. لا تُحوّل قاعدة غير متاحة إلى قائمة فارغة أو حفظ ناجح. رفض التكرار يعتمد القيد الفريد الفعلي، وتتحول أخطاؤه إلى تعارض دون كشف SQL. عند فقد إقرار COMMIT تُتلف الوصلة ولا تعاد العملية تلقائيًا؛ هذه ليست استعادة بإيصال دائم.

أصبحت المدخلات صارمة: لا حقن هوية أو معرفات غير صحيحة، ولا تعديل فارغ، ولا نسبة أكبر من100. الأعمدة الحالية تحفظ مبالغ صحيحة بوحدة العملة، لذلك يُرفض الكسر بدل تقريب صامت؛ لا تغيير لوحدة المال. يُتحقق من اليوم الحقيقي ومدى TIMESTAMP وتطبيع الكود قبل حد طوله. يبقى تاريخ الانتهاء منتصف الليل UTC وفق السلوك السابق، ويحتاج شرحًا صريحًا في الواجهة التالية.

## التحقق

- نجحت **258/258** حالة نهائية للحدود والصلاحيات والتخزين وخصومات الطلبات وحفظ خصائص126مسارًا، دون مجموعة فاشلة (`phase351-final.json`).
- نجحت **9/9 MySQL** لخصومات اللوحة: مدير لديه متجر آخر مملوك، السجل الأجنبي، نفس الكود بمتجرين، الإنشاء المتزامن، تحديث/حذف معزول، منع العضوية المسحوبة والحساب غير النشط، والمدخلات غير القابلة للحفظ. يتضمن الاختبار سحب العضوية أثناء انتظار قفل المتجر ثم إثبات غياب أي إنشاء (`phase351-mysql-final.json`).
- نجحت **106 حالات MySQL** إضافية لتطبيق كوبون الطلب وتحرير استخدامه في التشغيل الأول. مجموعه113نجاحًا وإخفاق واحد كان من استعمال قيمة غير موجودة في enum بحساب الاختبار؛ صُحح إلى `deletion_pending` وأعيدت مجموعة اللوحة كاملة. المحصلة115حالة MySQL مميزة ناجحة عبر التشغيلين؛ لا تُحسب المحاولة الأولى نجاحًا كاملًا.
- صُححت افتراضات حارسين قديمين في `remediation-regression.test.ts` عن موقع إجراءات الصوت وتصدير العملاء بعد النقل السابق. لم يُحذف الحارسان، وأعيد فحصهما. الحالات13المتخطاة لاختبارات آلية قديمة لم تُحسب نجاحًا.
- نجح TypeScript، والبناء النهائي خلال16.69ثانية مع تحذير الحزم الكبيرة القائم. لم تتغير مفاتيح الترجمة أو migrations أو ملفات الواجهة في هذه المرحلة. الأدلة `.tmp/tenant-ux/phase351-*`.

## المتابعة

شاشة الخصومات القديمة والموك أب العام ما زالا بحاجة إلى الاستبدال. تشمل الفجوات القائمة: بحث وصفحات ولقطة إحصاء متسقة، التفريق بين التفعيل والصلاحية الفعلية والمنتهي والمستهلك، أخطاء الحقول، مراجعة التعديل والحذف بنسخة، والتعامل مع الكوبونات الآلية المرتبطة بالعميل. لا تدعي هذه المرحلة إيصالًا دائمًا للكتابة أو فحصSafari/iPhone أو النشر أو اكتمال النظام. عدّ `active` القديم يعني العلم المحفوظ فقط إلى أن يكتمل مصدر الشاشة الجديدة.
