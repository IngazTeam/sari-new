# المرحلة 229 — التحقق من مصدر سجل واتساب

أضيفت وسيلة قراءة محمية لسجل المحادثات، تستخدم GET لقائمة المحادثات وPOST لآخر 50 رسالة متاحة لكل محادثة فردية. لا تتبع التحويلات، وتقبل عناوين Green API المسموحة عبر HTTPS فقط، وتخفي أخطاء المزود ورموزه. بقيت وسيلة إعدادات الاتصال السابقة متوافقة.

وُحد اشتقاق هوية الرسالة الواردة مع طابور الاستقبال دون تغيير قيمة التجزئة الحالية. جهزت هوية منفصلة للصادر المستورد، مرتبطة بالتيننت وحساب المزود. تمنع معالجة البيانات المكررة أو المتعارضة من اختيار نسخة اعتباطية.

تتحقق المعالجة من هوية المحادثة والرسالة والتاريخ والاتجاه وحالة قبول الصادر. لا تستبدل تاريخًا مفقودًا بالوقت الحالي، ولا تقص النص إلى 5000 حرف. تتوقف عند تجاوز سعة TEXT بالبايت. تحتفظ بروابط المرفقات الآمنة، وتعد السجلات المرفوضة بدل تحويل أنواع مجهولة إلى دليل محادثة. لا تنسب الصادر إلى المساعد أو الموظف دون دليل. الرسائل المحذوفة وإشعارات التعديل والحذف لا تعاد كرسائل عادية؛ ليست هذه المرحلة نظامًا لمزامنة حذف أو تعديل رسائل محفوظة سابقًا.

- نجحت 248 حالة للوحدات والاتصال وحصر الخصائص، و18 حالة MySQL حقيقية لطابور الوارد؛ 266 حالة بلا فشل أو تخطٍ.
- نجح TypeScript وبناء المشروع. لا تغييرات واجهة أو ترجمة هنا.
- جميع اتصالات المزود في الاختبارات محاكاة، مع بيانات محلية قابلة للحذف؛ لا استيراد خارجي أو نشر.

راجعت طريقة الطلب حسب [توثيق GetChats](https://green-api.com/en/docs/api/service/GetChats/)، وحدود السجل وحقوله حسب [توثيق GetChatHistory](https://green-api.com/en/docs/api/journals/GetChatHistory/). السجل هو ما يتيحه المزود وقد يتأخر؛ لا وعد باستعادة جميع الرسائل القديمة أو المجموعات.

هذه مرحلة تأسيس وفحص: مسار الاستيراد القديم لم يُستبدل بعد. المرحلة التالية توصل التحقق بالحفظ الذري وعزل التيننت، وتختبر التكرار والفشل الجزئي وتغير الرقم الرئيسي، ثم تحفظ كوميت مستقلًا.
