# المرحلة 222 — واجهة مراجعة ردود التصعيد

رُبطت القائمة بلقطة المرحلة 221 مع تأكيد الحساب والمتجر والمحادثة ومؤشر الصفحة. لا تظهر بيانات الفتح المخزنة قبل القراءة الجديدة، وتختفي النتائج عند الخطأ أو اختلاف السياق. أثناء التحديث الدوري تبقى البيانات الحالية والملاحظة مقروءة وتتعطل المراجعة مؤقتًا.

أصبحت مسودات الملاحظات محفوظة في ذاكرة مساحة المحادثة حسب المحاولة؛ تبقى عند التنقل للأقدم والعودة أو فشل قراءة عابر. تُعزل عند تغيير الحساب أو المتجر أو المحادثة، ولا تُحذف إلا الملاحظة التي أكد طلبها النجاح. تأكيد مراجعة الأدلة مرتبط بالمحاولة والصلاحية والملاحظة؛ أي تغير يتطلب تأكيدًا جديدًا.

مُنع تكرار النقر، وفُحص عقد نتيجة الكتابة، وأُهملت آثار الطلبات التي اكتملت بعد تغير السياق أو الأدلة. بعد فشل الطلب يلزم نجاح قراءة أحدث من لحظة الفشل قبل إعادة المراجعة، حتى إذا اكتمل تحديث خلفي أثناء الطلب. بعد النجاح تُحدث القائمة وستة مصادر مرتبطة، بينها الرسائل وملخص التسليم والمصدر القديم المتوافق.

- نجحت الحزمة الأولى من 91 حالة، ثم 20 حالة واجهة بعد إضافة حالة التحديث أثناء الحفظ، و136 حالة حصر. يوجد 228 اختبارًا مميزًا في هذه المجموعات، بلا فشل أو تخطٍ.
- نجح TypeScript والبناء وفحص الترجمة: 11317 استدعاءً و883 مفتاحًا ديناميكيًا محسومًا، بلا أخطاء أو مفاتيح ناقصة أو غير محسومة.
- أُعيد تشغيل الخادم المحلي المحمي على 3018، وفُتح قسم التصعيد واستُخدم تحديث السجل. ظهر الفراغ الصحيح لتيننت الفحص دون تعذر قراءة. حُفظت وفُحصت desktop-escalation-empty.png.

السيناريوهات غير الفارغة وحفظ الملاحظة والطلبات المتأخرة فُحصت بمكوّن React الفعلي وبيانات محاكاة؛ الصورة الحية تثبت الحالة الفارغة فقط. حفظ الملاحظات هنا في الذاكرة أثناء مساحة العمل، ولا يشمل إعادة تحميل المتصفح. لا Safari/iPhone فعلي أو إرسال خارجي أو نشر. التالي مصدر مراجعة عروض الخصم وواجهتها ثم بقية المحادثات والتصميم والموك أب.
