# المرحلة 245 — الإيصالات القديمة والنتائج المجهولة

أُنجزت محليًا على main بعد المرحلة244. لا نشر أو ترحيل أو اتصال بمزود خارجي. قاعدة MySQL والتيننتات المستخدمة للاختبار محلية ومؤقتة ونُظفت.

كان العامل يراجع queued وprovider_unreachable فقط. لذلك أمكن لإيصال قديم failed مع http_408 أو http_500 أن يمر إلى رد الحصة وإعادة المحاولة، رغم أن قناة واتساب ترفض إعادة إرساله. كذلك لم يفصل بين فشل التسليم بعد قبول المزود وبين الرفض قبل القبول، وبين نجاح قديم بلا معرف إيصال ونجاح مثبت.

أُضيف تصنيف موحد لدليل الحملة. القبول يتطلب معرف رسالة من المزود مع حالة مناسبة، ويبقى مثبتًا عند فشل التسليم لاحقًا. الحالات المجهولة والقيم غير المفهومة والنجاح القديم بلا معرف تُراجع مع إبقاء الحصة، دون إعادة إرسال أو رد آلي. الرفض المؤكد يقتصر على أكواد المزود الصريحة وأكواد المنع المحلية المعروفة. يستخدم مسار إعادة المحاولة داخل خدمة واتساب التصنيف نفسه للحملات.

يفحص العامل الإيصال قبل شروط إرسال جديد؛ سحب الموافقة بعد قبول المزود لا يمحو ما حدث سابقًا ولا يسمح برسالة جديدة. إذا رفضت قناة النقل إعادة محاولة قديمة لغياب صلاحيتها الدائمة، تُعاد الوحدة الجديدة غير المستخدمة وفق الفترة الأصلية وتُفتح مراجعة مرة واحدة، بدل دورة من ثماني محاولات. يُطبّق التصنيف أيضًا عند إعادة قراءة الإيصال بعد انتظار قفل العامل.

نجحت **486 حالة معزولة و111 حالة MySQL، بإجمالي597** دون مجموعات فاشلة، مع TypeScript والبناء. تشمل الإضافات مصفوفة أكواد الغموض والرفض، فساد معرف الإيصال، الاسترداد الفعلي دون مزود، بقاء الحجز أو رده الصحيح، المراجعة المفردة، وثبات قبول سابق بعد سحب الموافقة. الحزمة الرئيسية لم تتغير، وتحذير أحجام الأجزاء المعروف باقٍ.

الأدلة: `.tmp/tenant-ux/phase245-tests.json`، `phase245-mysql.json`، `phase245-types.log`، `phase245-build.log`.

التالي مصادر قائمة الحملات وإحصاءاتها وتقاريرها ثم التصميم التفصيلي والموك أب. القبول ليس إثبات تسليم أو قراءة. لا تدعي هذه المرحلة اكتمال تدقيق اللوحة أو Safari/iPhone أو اختبار اختراق شامل.
