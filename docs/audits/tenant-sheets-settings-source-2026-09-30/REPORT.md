# المرحلة 115 — مصدر حالة الربط وحفظ التقارير والفصل

أصبحت حالة Sheets وإعدادات التقارير والفصل تتطلب صلاحية إدارة التكاملات وجلسة نشطة داخل المعاملة. تعيد الحالة هوية المستخدم والتيننت وبصمة الاتصال وتفصل الاتصال المفقود وبيانات الاعتماد التالفة وتعطيل OAuth والحاجة إلى وجهة. أخطاء قاعدة البيانات أو إعدادات التقارير التالفة لا تتحول إلى «غير مربوط» أو خيارات متوقفة. لا تعاد بيانات الاعتماد إلى العميل.

يشترط الحفظ والفصل بصمة اللقطة ومراجعة صريحة، ويرفضان تغيّر الاتصال أو العضوية أو الجلسة. يحفظ تحديث الخيارات الحقول الأخرى، ويتيح إيقاف الإرسال عند تعطيل OAuth دون السماح بتفعيله. يفصل الإجراء الاتصال ويصفر الوجهة والجدولة ويلغي محاولات الربط المعلقة داخل معاملة واحدة، دون حذف ملفات Google. تعرض الواجهة القديمة مؤقتًا فشل القراءة بدل خيارات مضللة وترسل العقد الجديد مع تأكيد التفعيل والفصل؛ تحويلها إلى التصميم التفصيلي يأتي بعد تصحيح إنشاء الجدول.

اكتُشف أن مهام التقارير كانت تنشئ الملفات لجميع الاتصالات النشطة حتى عندما تكون خياراتها متوقفة؛ أصبح الإنشاء مشروطًا بتفعيل صريح ووجهة وبيانات اعتماد، وتُعاد قراءة الخيار وهوية الربط قبل إرسال واتساب. لا يثبت ذلك إلغاء طلب خارجي بدأ قبل تغيير الخيار، أو موثوقية حسابات التقارير القديمة؛ تبقى مراجعة هذه العمليات ضمن السجل. صُحح عنوان عودة Sheets المعروض للإدارة ليأتي من أصل الخادم المعتمد ومساره المسجل.

نجحت52 حالة للمصدر والعقود والصلاحيات والمهام والواجهة، و27 حالة MySQL تشمل20 للربط و7 للحفظ والفصل، و168 حالة رجعية والحصر. نجحت الأنواع والترجمة (10000 استدعاء و451 مفتاحًا ديناميكيًا) وبناء التطبيق والخادم والعامل وحد الحزمة. بقيت126 مسارًا و306 ملفات و2023 عنصرًا دون إسقاط مسار أو رابط غير صحيح أو ملف يتيم. نتائج الاختبارات محفوظة في سجلات المرحلة المحلية.

لم يحدث ربط Google أو إرسال واتساب أو تغيير إعدادات خارجية. لا ترحيل جديد في هذه المرحلة ولا نشر. التالي إنشاء وجهة Sheets كاملة مع معالجة النتيجة غير المؤكدة، ثم الشاشة الجديدة والموك أب وبقية الحصر. Safari/iPhone غير مثبتين.
