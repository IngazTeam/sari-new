# المرحلة 462 — مصدر إعدادات الدفع والحفظ والفحص المراجع

أضيفت workspace/saveReviewed/probeReviewed لمساري إعدادات الدفع الحاليين. المصدر يربط الهوية بالتيننت ويقرأ تحت معاملة وصلاحية عضوية وحسابات حية. لا يعرض إعدادات الدفع للمشاهد أو مشرف المبيعات، مع إبقاء صلاحية المالك والمدير الموجودة. الحساب أو المالك غير النشط والعضوية المسحوبة يوقفان الوصول؛ المتجر المعلق في انتظار التفعيل يظهر للمالك والمدير للقراءة فقط.

المصدر يفرق بين غياب السجل وتعذر قاعدة البيانات والقيم القديمة غير الصالحة والتكرار. لا يكتب افتراضيات عند القراءة، ولا يختار أول سجل مكرر. البصمة HMAC مرتبطة بالحساب والمتجر والحقول الخام المختارة. لا يختار سر webhook أو عنوانه، ولا يعيد المفتاح السري أو مقتطفًا منه. حالة المفتاح تفصل الغياب والحفظ وعدم الصلاحية وتعذر فك التشفير.

الحفظ يفحص بصمة المراجعة تحت قفل، ويقبل قصدًا واضحًا للمفتاح: إبقاء، استبدال، أو مسح. الاستبدال يستخدم تشفير الأسرار الموجود، ويتحقق من القراءة بعد الكتابة قبل إعلان النجاح. تغيير المفاتيح أو الوضع يبطل التحقق السابق، والتعطيل لا يمسح مفتاحًا غير قابل للقراءة تلقائيًا. تُحفظ إعدادات الرسالة والإرسال القديمة دون تعديل لأنها ليست موصولة بمسار تنفيذ؛ المصدر يصرح بأنهما غير مطبقين. العملة SAR معلنة في الطلب، وليست تحويلًا لعملة المتجر.

فحص المفاتيح يقرأ النسخة المراجعة قبل طلب تحقق المزود، ثم يعيد فحص الصلاحية والنسخة قبل تسجيل النتيجة. تغير العضوية أو الإعدادات أثناء الانتظار يمنع الكتابة المتأخرة. الرفض401/403 يزيل التحقق، وتعذر المزود لا يعد رفضًا ولا نجاحًا. فحص المفاتيح لا ينشئ رسومًا ولا يفعّل الدفع تلقائيًا. فقدان نتيجة commit يرد بنتيجة مجهولة ويتخلص من الاتصال دون إعادة إرسال تلقائية.

التحقق:72حالة للعقد والعزل والحفظ والتشفير والفحص والخصوصية، و14حالة MySQL للمصدر والراوتر والتزامن والتراجع واستبعاد الأسرار. نجح فحص الأنواع وبناء التطبيق. اختُبر المزود بدالة محاكاة فقط، ولم تُرسل مفاتيح حقيقية أو طلب دفع. لا ترحيل جديد؛ قيد تفرّد merchant_id موجود وأثبت الاختبار عمله.

المتبقي: نقل صفحة الدفع والموك أب للمصدر الجديد، ثم إغلاق المسارات القديمة وإزالة تكرار الراوتر. المصادر الجديدة ليست دليلًا على نشر أو جاهزية مزود حقيقي، ولا على اكتمال اختبار اختراق النظام.
