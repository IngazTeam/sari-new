# المرحلة 516 — توحيد حماية إرسال إشعارات المتصفح

2026-10-04؛ main؛ محلي فقط.

كان المرسل القديم يستخدم عنوان الاشتراك المحفوظ مباشرة عبر SDK دون سياسة وجهات، مع طباعة أخطاء قد تحتوي رمز الوجهة، واعتبار فشل كتابة السجل بعد قبول المزود فشل إرسال. استُبدل نقله بالنقل المحمي نفسه لمسار إيصالات سلة: HTTPS لمزودي Push المحددين فقط، رفض بيانات الدخول والتحويلات والعناوين الداخلية والنطاقات المضللة، حد للعنوان ولحمولة UTF-8 ولرد الشبكة ومهلة20ثانية دون إعادة إرسال.

بقي تشفير Web Push والتوقيع عبر المكتبة الفعلية. صارت اشتراكات المزود المقروءة محدودة64صفًا مع رفض إرسال أكثر من63أو تكرار الوجهة. يُعاد فحص الاشتراك والمفاتيح حتى دون حارس اختياري. لا شبكة قبل إقرار سجل صالح. قبول201مع مرجع صالح لا يثبت وصول الجهاز؛ رفض HTTP الصريح منفصل عن النتيجة المجهولة. فشل سجل العرض لا يمحو قبول المزود. الحقل القديم failed يعني غير مؤكد القبول حتى تحديث واجهته، لا إثبات الرفض. لا تعطيل تلقائي لسجل قد تغير عند رد410.

أضيف دعم نطاقات Apple الفرعية وفق [WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)، وفُحص عقد القبول وفق [RFC8030](https://datatracker.ietf.org/doc/html/rfc8030#section-5). هذا لا يثبت اختبارSafari أوiPhoneفعليًا.

تبقى حدود إدارة الاشتراكات وعزلها في الراوترين وشاشة الإشعارات القديمة. التالي عامل المتصفح: كان يقبل روابط وصور من الحمولة دون تقييد، ويحذف كاشات غير تابعة له. لا نشر، لا إشعارات حقيقية، لا ادعاء اكتمال أو اختبار اختراق شامل.
