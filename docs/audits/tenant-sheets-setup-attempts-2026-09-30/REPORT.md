# المرحلة 117 — سجل إنشاء Sheets واستعادة الإيصال

أضيفت أربعة إجراءات بصلاحية إدارة التكاملات والجلسة النشطة لبدء إنشاء الوجهة وقراءة المحاولة واستعادة الاعتماد والإقرار بالمراجعة اليدوية. تحفظ قاعدة البيانات معرّف الطلب وبصمة المدخل والاتصال وحاجز إرسال سريًا وحالة المحاولة وإيصال الإنشاء ببصمته. لا تُحفظ رموز OAuth داخل السجل. تكرار معرّف الطلب يعيد المحاولة المحفوظة، ووجود محاولة مفتوحة يمنع بدء إنشاء آخر. يوجد حد10 محاولات جديدة/ساعة لكل تيننت.

يفحص الخادم الصلاحية والاتصال قبل إعداد OAuth وقبل الإرسال، ويحفظ حالة الإرسال أولًا. رد المزود المتحقق يحفظ بإيصال مستقل قبل اعتماد معرّف الملف في الاتصال. لذلك يمكن استعادة الاعتماد دون إنشاء ملف جديد إذا تعطل الحفظ أو فُقد رد قاعدة البيانات. إذا تغيّرت الوجهة أو بيانات الربط، يبقى الإيصال منفصلًا ولا يحل محل الربط الجديد. سحب الصلاحية يمنع القراءة والاعتماد مع حفظ دليل الإنشاء داخليًا.

فقد رد Google يظل غير مؤكد؛ لا تجري إعادة إنشاء تلقائية ولا يُحوّل انتهاء مهلة المحاولة إلى فشل آمن. بعد120 ثانية يمكن للمستخدم الإقرار بأنه راجع Google قبل بدء محاولة جديدة. الإقرار محلي ولا يثبت عدم وجود ملف ولا يحذفه، وقد يبقى ملف في Google لا نعرف معرّفه. هذه حماية من إعادة الإرسال التلقائية، وليست ضمان تنفيذ خارجي مرة واحدة عبر الإقرار اليدوي.

الترحيل179 أضيف لجدول المحاولات وطبق في قاعدة الفحص المحلية. نجحت111 حالة للعقود والصلاحيات والمزود والربط والإعدادات، و46 حالة MySQL تشمل19 للمحاولات و27 للربط والإعدادات. شملت الأعطال فقد تأكيد حفظ الإيصال قبل/بعد commit وتعطل اعتماد الوجهة والتزامن وتغيير الاتصال والصلاحية وتلف الإيصال. نجحت149 حالة رجعية للحصر والتقارير وإغلاق الاستيراد القديم، وفحص الأنواع وبناء التطبيق والخادم والعامل وحد الحزمة. لم تتغير ملفات واجهة المستخدم في هذه المرحلة وبقي حصرها محفوظًا.

الإجراءات الجديدة مرتبطة بالراوتر، لكن الشاشة ما زالت تستعمل مسار الإنشاء القديم حتى تحويلها في المرحلة التالية؛ لا يُعد التحويل مكتملًا. التالي شاشة الإعدادات الجديدة بكل حالات الاستعادة ثم الموك أب المطابق وإغلاق الإنشاء القديم، وبعدها بقية الحصر. لا اتصال Google أو إرسال خارجي أو نشر.
