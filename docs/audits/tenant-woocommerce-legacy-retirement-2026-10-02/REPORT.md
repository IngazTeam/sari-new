# المرحلة 332 — إغلاق تنفيذ WooCommerce القديم

أُغلقت ثمانية إجراءات قديمة: حفظ الربط وفحصه وفصله، مزامنة المنتجات والطلبات، المصالحة الشاملة، تغيير حالة الطلب وإرسال إشعاره. تحتفظ بعقود الإدخال والصلاحيات ثم ترفض التنفيذ برسالة woo_dashboard:reload؛ لا تُحوّل الطلب القديم تلقائيًا إلى عملية جديدة. الصفحات الفعلية تستخدم الإجراءات المراجعة فقط.

حُذفت مسارات التنفيذ القديمة من الموجّه ودالة قاعدة البيانات التي كانت تغلق جميع حالات manual_review. المصالحة المتبقية تحفظ اللقطتين والسجل وإيصال العملية ومعرّفات الحالات المختارة وبصماتها في معاملة واحدة. لا تُغلق الحالات التي وصلت لاحقًا. أضيفت قدرة الإصدار woocommerce-dashboard-reviewed-writes-0191 لمنع تفعيل أو استرجاع كتّاب قدامى، مع بقاء أمر التحديث المعتاد صالحًا.

نجحت 464 حالة معزولة، و81 حالة MySQL، و114 اختبار انتقال وتحديث للإصدار، وفحص TypeScript والبناء وgit diff --check. شملت الاختبارات الرفض قبل قراءة الاعتمادات أو أخذ قفل التنفيذ أو إرسال رسالة، والصلاحيات والإدخالات المحقونة، والأقفال وإشعارات المزوّد، والمراجعة المحددة، والواجهات الجديدة. نُقلت اختبارات التنفيذ المصدرية إلى الخدمات المراجعة الحالية؛ الاختبارات الوظيفية لسلطة التنفيذ والإيصالات مستمرة.

هذا إغلاق لمسارات لوحة WooCommerce فقط؛ القراءات القديمة باقية للتوافق. لا ترحيل جديد ولا إرسال حقيقي ولا نشر. التالي الموك أب باستخدام المكونات الفعلية، ثم قياسات العرض باللغتين وتحديث حصر الصفحات المتبقية.
