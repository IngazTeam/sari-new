# المرحلة456 — منع الإقرار الكاذب لحفظ ملف المتجر

كان updateMerchant يرجع دون خطأ عند غياب قاعدة البيانات، ويتجاهل عدد السجلات المطابقة في رد الكتابة. صار يرفض الحالة الأولى ويرفض أي إيصال لا يثبت مطابقة سجل واحد. لا يخلط بين affectedRows وchangedRows: الحفظ المتكرر للقيمة نفسها يظل صحيحًا مع FOUND_ROWS الافتراضي في mysql2.

اختُبر المساعد الفعلي مع اتصال غائب وسجل غير مطابق وإيصال غير معروف وفشل الرد؛ لا ابتلاع للأخطاء أو إعادة إرسال تلقائية. اختبارات MySQL تثبت حفظين متطابقين عبر الراوتر وتمنع إقرار الكتابة لمعرّف غير موجود. نجحت اختبارات الوحدة وMySQL والأنواع وبناء التطبيق، كما هو موضح في سجل المرحلة.

هذا إصلاح لإقرار الكتابة فقط؛ ليس بديلًا عن نسخة مراجعة لملف المتجر أو معاملة تفويض حية أو استعادة ذات إيصال دائم. تلك متابعات صفحة الحساب، ولا ادعاء بإغلاقها هنا. لا تغييرات واجهة أو ترحيل أو نشر.
