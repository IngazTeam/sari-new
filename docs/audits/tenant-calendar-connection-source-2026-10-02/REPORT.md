# ربط التقويم وإعداداته — المرحلة 280

أُزيل مسار استبدال الكود المباشر وحالة التفويض التي تقبل معرّف التيننت، واستُبدلا بتفويض مرتبط بالجلسة والعضوية والتيننت وبصمة إعداد المزود والاتصال، يستخدم مرة واحدة وينتهي بعد عشر دقائق. يُستهلك قبل استبدال الكود، وتُراجع الصلاحية والمصدر مجددًا تحت القفل قبل الحفظ. النتائج المتأخرة لا تعيد اتصالًا فصله التاجر. لا تُعاد المحاولة تلقائيًا عند غموض استبدال الكود، ولا تظهر بيانات الاعتماد في الأخطاء أو حالة الواجهة.

أضيف مصدر إعدادات يعرض الحالة المحفوظة بصدق، دون افتراض تحقق حي من Google أو اختلاق بريد الحساب وتاريخ الاتصال. الفصل يحتاج بصمة النسخة وإقرار المراجعة؛ يمحو بيانات الاعتماد المحلية ويحفظ معرّف الاتصال وإعداداته وكل المواعيد وروابطها التاريخية. إعادة التفويض تختار التقويم الأساسي للحساب الجديد ولا ترث هدف الحساب السابق. أُصلح فحص `isEnabled` في عميل Google الذي كان يقرأ خاصية غير موجودة ويتجاوز تعطيل المزود إلى إعداد البيئة. كشفت المراجعة خطأ اسم صلاحية Google وأضيف اختبار مستقل لقيمتها الصحيحة.

- نجحت 300 حالة معزولة ثم أُعيدت الاختبارات المتأثرة بعد إصلاح اسم الصلاحية؛ تشمل حدود المزود والنقل عبر HTTP محاكى والصلاحيات ومساري الراوتر وعناوين العودة. لا اتصال خارجي.
- نجحت 31 حالة MySQL، تشمل التزامن وإعادة الاستخدام وتغيير الجلسة والعضوية والإعدادات أثناء الاستبدال والفصل أثناء نتيجة متأخرة وحفظ المواعيد دون تغيير. نُظفت بيانات الاختبارات.
- نجح فحص الأنواع وبناء الإنتاج خلال 14.23 ثانية. بقي تحذير أحجام الحزم القائم؛ الحزمة الرئيسية 424176 بايت، و126792 مضغوطة.
- الترحيل 0186 إضافي ومسجل في سجل الترحيلات والمخطط وفحص الجاهزية، وطُبق على قاعدة الفحص المحلية فقط. أُضيفت متطلبات عنوان العودة إلى دليل النشر. لا نشر ولا تفويض حساب Google فعلي.

التالي مباشرة استبدال شاشة CalendarSettings القديمة وتوصيلها بالمصدر الجديد؛ الشاشة القديمة لم تعد متوافقة مع إجراءات الربط المتقاعدة. ثم إنشاء الموعد والتوفر والموك أب الفعلي للتقويم. يبقى تدقيق المستهلكين القديمين getStatus/getStats في سجل الاستكمال. هذه تغطية محددة، وليست ادعاء اكتمال فحص النظام أو اختبار اختراق شامل.
