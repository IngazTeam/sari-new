# المرحلة 338 — مصدر Calendly المحلي الكامل

2026-10-02، main؛ قاعدة اختبار محلية وبيانات اصطناعية فقط. لا رفع أو نشر.

## التنفيذ

أضيفت ثلاثة مصادر محكومة بصلاحية التكاملات والتيننت المختار: لقطة الربط والعدادات، كل المواعيد المخزنة، وكل إيصالات التحديث. القوائم بصفحات 25 سجلًا مع بحث حرفي وفلاتر وحسابات كاملة من قاعدة البيانات، دون حد مخفي لأول مجموعة. المواعيد تدعم الحالة والفترة وزوج تواريخ صالح، والإيصالات تدعم الحالة ونوع الحدث.

تُقرأ كل نتيجة داخل لقطة REPEATABLE READ للعدادات والصفحة. العقود الصارمة تتحقق من هوية التيننت والأعداد والترتيب؛ فشل المصدر لا يتحول إلى فراغ. يُتلف اتصال المعاملة عند التباس commit أو فشل rollback. تُعرض البيانات القديمة غير الصالحة بعلامة صريحة بدل اختلاق قيم بديلة.

لقطة الربط تفصل وجود الإعداد وحالته المحلية وصلاحية الهوية والإعدادات واكتمال تسجيل webhook. وجود الاعتماد مؤشر فقط، دون فك تشفير أو إعادة الأسرار. بصمة المراجعة تتغير عند تغيير الربط أو الاعتماد أو الإعدادات، ولا تتغير بتقدم توقيت المزامنة وحده. لا تُعاد أخطاء المزوّد أو مفاتيح الإيجار أو معرفات موارد الإيصالات.

## التحقق

187 اختبارًا معزولًا ناجحًا، و18 اختبار MySQL ناجحًا، دون فشل اختبارات أو تحميل مجموعات. فحص TypeScript وبناء التطبيق ناجحان. كشف اختبار MySQL استخدام stored المحجوز اسمًا لعمود محسوب؛ استُبدل وأعيدت المجموعة كاملة بنجاح.

اختبار 56 موعدًا يعبر ثلاث صفحات دون فقد أو سجلات تيننت آخر؛ 31 إيصالًا يعبر صفحتين. تشمل الحالات البحث بالرموز ومحاولة SQL، التواريخ، الإعدادات التالفة، تغير البصمة، غياب التخزين، وإخفاء الأسرار.

## التالي والحدود

هذه مصادر محلية وليست إثباتًا لصلاحية الاعتماد لدى Calendly. لم تتغير الصفحة القديمة بعد؛ يلي ذلك أفعال مراجعة وربط ومزامنة بنتائج قابلة للاستعادة، ثم الواجهة الفعلية والموك أب وفحوص العرض. المزامنة القديمة الجزئية وخطأ مراقب الغلاف المركزي الوارد في334 ما زالا ضمن المتابعة. لا اختبار حساب مزوّد حي أو Safari/iPhone فعلي.
