# استئناف وسائط الرد القديمة — المرحلة 390

تستخدم الخطط الجديدة إصدار المنتج 2 الذي يحافظ على حارس بانرات العروض. تظل خطة الإصدار 1 التي تحتوي صورة أو مستندًا غير موسوم للمراجعة، قبل إرسال نصها أو وسائطها. لا يغير النظام إصدار الخطة المحفوظة ولا يعيد توليدها فوق حجز قديم. محاولة المرور مباشرة عبر قناة الرد تمنعها الحماية نفسها وتسجل سببًا صريحًا، دون حجز حصة جديدة.

تبقى النصوص القديمة وحدها والبانرات ذات الحارس القديم قابلة للتحقق بالشروط الحالية. لا يتغير إيصال سبق قبوله أو ظل مجهولًا، ولا تتجاوز إزالة الحارس من محاولة إعادة إرسال إيصال مرفوض الحماية. يقبل قارئ إثبات عروض الشراء الإصدارين المعروفين فقط، مع استمرار مطابقة الخطة كاملة والنص وإيصالات أجزائه.

## التحقق

- نجحت 132 حالة وحدات وعقود: 79 للوسائط والنقل والحجز، و53 لإثبات عرض الشراء.
- نجحت 215 حالة MySQL مختلفة. المجموعة الأولى 185 حالة؛ ثم 48 حالة تضمنت إعادة 18 حالة دخول وإضافة حالة دخول جديدة و29 حالة إثبات شراء. لا فشل أو تخطٍ.
- تشمل الفحوص المنتج والمستند الجديدين، والنص القديم، والبانر المحروس بإصدار 1، ومنع الخطة الغامضة قبل أول أثر، ومنع ترقية الحجز، وإيصالات القبول والمجهول والرفض، والمجموعات والحصة، وبقاء خطة العامل الغامضة في المراجعة.
- فحص الأنواع ناجح وبناء الإنتاج 18.11 ثانية. نجحت 29 حالة إصدار، مع القدرة `ordinary-reply-media-producer-v2`.

إصدار المنتج يميز الخطط التي أُنشئت بعد حفظ حارس العرض؛ لا يثبت حداثة سعر المنتج أو ملكية محتوى رابط الصورة أو سلامة DNS. معالجة الخطط القديمة المتوقفة تحتاج مراجعة مدعومة بالدليل، وليست زر إعادة إرسال تلقائي. مزوّد الإرسال محاكى؛ لا رسائل خارجية أو نشر.
