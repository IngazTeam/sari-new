# المرحلة 64 — موك أب الطلبات والمراجعة

صار مسار /merchant/orders في الموك أب يركب OrderWorkspace وOrderReport وOrderStatusForm وOrderHistory الفعلية. تشترك المسودة والتحقق واستعادة الإيصال وحالات الفشل والترجمة مع التطبيق. طبقة API للموك أب محلية فقط بلا fetch أو دفع أو إشعار خارجي.

## المطابقة

- 27 طلبًا في صفحتين 25+2، مع البحث والفلاتر والملخص والعملات وحالة الدفع المنفصلة، دون نسب مبيعات أو إيراد مسوى مصطنع.
- تفاصيل كاملة للعميل والعنوان والملاحظات والهدايا والبنود، وأمثلة أسعار قديمة غير مثبتة ونص مقصوص وطلب منصة خارجي وحالات نهائية/مجهولة.
- 11 وضعًا: بيانات، فراغ، تحميل، خطأ، منع قراءة، قراءة فقط، طلب مفقود، تعارض، استجابة ضائعة بعد الحفظ، نتيجة غير مؤكدة قبل الحفظ، سجل اصطناعي طويل للترقيم.
- مراجعة الحالة والسبب والتتبع ومعاينة النص والمستلم، وحفظ المسودة والإيصال والسجل. إعادة الطلب تستخدم UUID والمدخلات نفسها. السجل الطويل مصطنع وموسوم لاختبار الترقيم، وليس دورة حياة طلب واقعية.
- إعادة المثال تؤكد مسح بيانات المثال ومسودته فقط. عند تحميل الصفحة تعود بيانات الذاكرة إلى البداية؛ تُحذف محاولة المثال القديمة من cache ويُحتفظ بمسودتها، فلا يُزعم أن إيصال المحاكاة خادمي دائم.

## خلل اكتشفه الموك أب وأُصلح في التطبيق

عندما يحفظ المصدر حالة processing وتضيع الاستجابة، كانت قائمة الخيارات تحذف processing لأنها صارت الحالة الحالية، فيعرض المتصفح shipped رغم أن العملية المعلقة تخص processing. يحافظ OrderStatusForm الآن على خيار الحالة المراجعة معطّلًا عند غيابه من الانتقالات المتاحة. أثبت اختبار الواجهة ثم المتصفح بقاء قيمة القائمة processing حتى فحص الإيصال.

كذلك أُصلح تحميل merchantUx من ملفات الترجمة المشتركة بدل افتراض وجودها في JSON؛ لم تعد مفاتيح الترقيم الخام تظهر في الموك أب.

## الأدلة

- tests.json: 47 حالة ناجحة، منها 17 للنموذج و4 رحلات بالمكوّن الفعلي ومحول المحاكاة، و20 لواجهة التطبيق و6 للتخزين.
- inventory-tests.json: 132 حالة لحفظ الخصائص والحصر. نجح TypeScript وبناء الموك أب وبناء التطبيق، وميزانية المدخل 103410 بايت gzip.
- تجربة IAB مكتبية: الصفحة الثانية تعرض سجلين، ثم حفظ processing مع استجابة ضائعة واستعادة الإيصال والسجل دون تكرار الكتابة. لقطة recovered-receipt.png.
- تجربة النسخة المصححة عند عرض فعلي 480×860: clientWidth=scrollWidth=450 للقائمة والحالة المعلقة والتفاصيل بالإنجليزية. قيمة الحالة المعلقة processing ظلت صحيحة. لقطة uncertain-status-fixed-480.png. استُعيد الإيصال ثم أعيد حجم المتصفح.
- لا مفاتيح merchantUx أو orderWorkspace خام في تجربة الإنجليزية. الترجمة الأساسية في التطبيق سبق التحقق منها في المرحلة 62؛ لم تضاف مفاتيح إنتاج جديدة هنا.

## حدود المطابقة والتالي

أدوات الفاتورة والهامش ومحاولات الدفع وتحرير الخصم وسلة وزد محفوظة في التطبيق لكنها تعرض أمثلة فارغة في هذه الجولة من الموك أب. هي المرحلة التالية؛ لذلك الحالة «تفصيلي جزئي»، وليست اكتمالًا لكل أدوات الطلبات. المقاييس الأمنية ومعاملات الخادم مثبتة في تقارير المراحل 59–63، وليست نتيجة لهذه المحاكاة. فحص 320/390 وSafari/iPhone الحقيقي مفتوح. لا دفع أو نشر أو إرسال.

التغطية بعد إضافة الطلبات: 82 عامًا و27 جزئيًا و9 تفصيلية و8 تحويلات، من 126 مسارًا. الحصر الحالي 281 ملفًا و1947 عنصرًا. بناء الموك أب: node prototypes/tenant-dashboard/build-orders.mjs.
