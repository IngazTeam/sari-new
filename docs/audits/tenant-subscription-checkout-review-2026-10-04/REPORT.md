# المرحلة489 — مراجعة سعر الاشتراك قبل الدفع

أضيف مصدر مراجعة للمالك في المتجر المختار، يعرض الدورة والعملة والسعر والرصيد والمبلغ النهائي ونوع العملية. يقرأ داخل معاملة متسقة تحت حارس الصلاحية، ويفصل الاشتراك المنتهي عن النشط دون تحديث أي منهما أثناء القراءة. تعدد الاشتراكات الحالية أو السعر أو الحالة غير الصالحة يمنع المراجعة.

ترتبط المراجعة ببصمة HMAC تشمل المستخدم والمتجر والباقة ومزاياها والأسعار والدورة وحالة الاشتراك، وتستمر خمس دقائق بحسب ساعة قاعدة البيانات. تغيير هذه البيانات أو انتهاء المهلة يرفض التأكيد. حركات الاستخدام لا تبطل المراجعة لمجرد تغيير عداد الرسائل.

أضيف قبول اختياري لهذه المراجعة في إجراءي الاشتراك والترقية تمهيدًا للواجهة الجديدة؛ يعاد فحصها قبل إنشاء معاملة الدفع. نقلت الحسابات إلى دالة نقية مشتركة مع تطبيع التواريخ النصية إلى UTC. لم تُزل الواجهات القديمة أو تصبح المراجعة إلزامية لكل مستهلك بعد.

## التحقق
122/122حالة وحدة وعزل وتراجع. 9/9MySQL تشمل المراجعة وتغير السعر والمتجر وتعدد الاشتراكات وحظر العضو وسحب الصلاحية وقراءة المنتهي دون تغيير حالته. صححت خلال الاختبار حقول عينة الباقة الإلزامية وأسماء الأعمدة في اختبار المقارنة، ونظفت العينات. TypeScript وبناء الإنتاج ناجحان. لا مزود دفع خارجي أو ترحيل أو نشر.

## المتابعة
الخطوة التالية الواجهة المشتركة للباقات والمقارنة والشراء والموك أب. ما زال إتمام الدفع خارج معاملة قراءة المراجعة؛ يلزم فحص تعارض حالة الاشتراك عند تطبيق نتيجة الدفع، وكذلك سياسة الرصيد المبنية على سعر الباقة الحالي بدل مبلغ السداد التاريخي. لذلك لا تعد هذه المرحلة إثباتًا للاكتمال الأمني لمسار الدفع كله.
