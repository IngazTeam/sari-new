# مرحلة 347 — إغلاق كتابات Calendly القديمة

أُغلقت إجراءات الربط والفصل والمزامنة وحفظ الإعدادات القديمة بعد نقل واجهة التاجر والموك أب إلى الإجراءات المراجعة. تستمر المداخل القديمة في التحقق من المدخلات وصلاحية التيننت المختار، ثم ترفض التنفيذ برسالة تطلب استخدام الواجهة الجديدة، قبل قراءة الاعتمادات أو قفل الموارد أو الاتصال بالمزوّد أو الكتابة.

حُذف تنفيذ المزامنة القديم؛ بقي تصدير توافق يرفض الاستدعاء حتى لا يتمكن مستدعي قديم من تجاوز المراجعة والإيصال الدائم. أضيفت قدرة الإصدار `calendly-dashboard-reviewed-writes-0192` لمنع تشغيل إصدار قديم يكتب عبر هذه المداخل. أمر التحديث المعتمد لم يتغير.

## التحقق

- 360 حالة وحدات ناجحة عبر التشغيل الأساسي وإعادة مجموعة الأمان المتأثرة. التشغيل الأول سجل فشل تأكيدين نصيين كانا يبحثان عن التنفيذ المحذوف؛ حُدثا ليفحصا الربط المراجع، ثم نجحت المجموعة كاملة: 12/12. كانت 115 حالة قاعدة بيانات متخطاة في التشغيل المعزول، وليست حالات ناجحة.
- 50/50 حالة MySQL ناجحة للصلاحيات والسلطة والربط والمزامنة والإعدادات. أثبتت رفض المداخل المتقاعدة دون تغيير البيانات، واستمرار حفظ الإعدادات المراجع للتيننت المختار.
- 126/126 حالة انتقال إصدار وتحديث ناجحة، بما فيها إيقاف الإصدار غير المتوافق قبل الهجرة عبر المداخل الثلاثة.
- TypeScript ناجح، وبناء الإنتاج ناجح (14.95 ثانية). بقي تنبيه أحجام بعض الحزم الكبير الموجود مسبقًا.
- `git diff --check` ناجح.

الأدلة المحلية: `.tmp/tenant-ux/phase347-unit.json`، `phase347-pentest-final.json`، `phase347-mysql.json`، `phase347-release.log`، `phase347-types.log`، `phase347-build.log`.

هذه اختبارات محلية موجهة، وليست اختبار اختراق شاملًا أو إثبات Safari/iPhone فعلي أو تشغيل مزوّد حي. لم يحدث نشر. متابعة بقية الملاحظات موثقة في سجل العمل العام.
