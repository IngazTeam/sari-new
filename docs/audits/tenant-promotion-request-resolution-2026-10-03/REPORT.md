# المرحلة 381 — حسم طلب الحفظ غير المؤكد

أضيف إجراء صريح لحسم الطلب: يعيد نتيجة الحفظ الموجودة، أو يسجل إيصال إغلاق دائمًا لمفتاح الطلب تحت قفل التيننت. أي تنفيذ متأخر للمفتاح المغلق يُرفض، دون حذف عرض محفوظ أو التراجع عنه. قراءة الإيصال وحدها لا تغيّر الطلب.

تعرض الواجهة شرحًا وزر «حسم هذا الطلب»، وتفتح الكتابة الجديدة فقط بعد إيصال مطابق للمستخدم والتيننت والمفتاح. تبقى مقفلة عند خطأ أو نتيجة مخالفة. يمكن استعادة نتيجة الحسم بعد فقدان تأكيده، كما يمكن استعادة الحفظ.

نجحت58حالة وحدة وواجهة وصلاحيات، و40MySQL على تيننتات مؤقتة، و22للإصدار، دون فشل أو تخطي. شملت السباق بين الحفظ والحسم بالترتيبين، وإغلاقًا متزامنًا، وصلاحيات ملغاة، وإيصالًا محرّفًا، وفقدان تأكيد الحسم. نجحت الأنواع والترجمة13152استدعاء/854مفتاحًا والبناء25.04ثانية. فحص واجهة الحسم هنا باختبارات المكونات؛ محاكاته البصرية ستدخل الموك أب في المرحلة التالية.

تستخدم السجلات جدول0196 دون تغيير هجرته المطبقة، مع قدرة إصدار `promotion-request-resolution-v1`. التالي اختيار الأهداف بالأسماء ثم الموك أب وإغلاق المداخل القديمة ودليل المساعد. لا نشر أو إرسال خارجي أو Safari/iPhone فعلي.
