# المرحلة 331 — طلبات WooCommerce ومراجعة الأفعال

استُبدلت صفحة الطلبات القديمة بواجهة التصميم المشترك: بحث كامل وفلاتر الحالة والتاريخ وصفحات 25، مع مبلغ وعملة كل طلب وتاريخ المصدر. تعرض نافذة التفاصيل كل البنود على صفحات، والضرائب والشحن والخصم والدفع والملاحظة وحالة المزامنة. يبقى العرض متاحًا للمشاهد دون أفعال الكتابة.

أصبحت الحالة والملاحظة وإشعار العميل أفعالًا بمراجعة مستقلة داخل النافذة نفسها. يُعاد التحقق من بصمة التفاصيل وصلاحية الفعل والربط قبل التنفيذ. يمكن حفظ الملاحظة أو مسحها صراحة، ويظهر رقم الإرسال للقراءة فقط مع النص النهائي. لا يتاح الإرسال دون قناة نشطة، ولا تعني موافقة القناة وصول الرسالة. رُبطت استعادة نتيجة العملية بمعرّف الطلب المستهدف أيضًا. يعود التركيز إلى زر فتح الطلب، أو عنوان القائمة إذا اختفى الزر.

التحقق: 346 اختبارًا معزولًا، و35 اختبار MySQL لعمليات الطلب والإشعار، و74 اختبار تراجع للمزامنة والإشعارات والأقفال، كلها ناجحة. حُدثت خمسة توقعات مصدرية كانت تشير إلى التصميم المحذوف، مع إبقاء فحوص الأمان. نجح TypeScript والترجمة (12705 استدعاءات، 880 مفتاحًا ديناميكيًا، صفر أخطاء) والبناء النهائي (20.79 ثانية؛ 424167 بايت / 126787 gzip) وgit diff --check. تحذير حجم بعض الحزم السابق باقٍ.

في Chromium والتيننت المحلي المستقل: ثبت البحث عن طلب عبر معرّف المزوّد، وعرض 25 بندًا ثم البند 26، ومراجعة تغيير الحالة مع مسح الملاحظة، وتعطيل الإشعار دون قناة نشطة، واستعادة التركيز. سبعة قياسات للقائمة والتفاصيل والمراجعة والإشعار عند 320/390/480 بكسل بلا تجاوز أفقي أو مفاتيح ترجمة ظاهرة أو عناصر تحكم نصية أقل من 44 بكسل. الأدلة المحلية: .tmp/tenant-ux/phase331-responsive.json وphase331-status-review.png.

التالي إغلاق إجراءات التنفيذ القديمة التي تجاوزتها الصفحات الأربع، ثم ربط الموك أب بالمكونات الفعلية. لا إرسال حقيقي إلى المزوّد ولا اختبار Safari/iPhone فعلي ولا نشر. هذا تحقق محدد النطاق، وليس إثباتًا لاكتمال كل صفحات النظام.
