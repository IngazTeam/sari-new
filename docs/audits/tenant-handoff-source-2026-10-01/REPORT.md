# المرحلة 219 — مصدر تسليم المحادثة والأدلة

كان ملخص التسليم يقرأ المسؤول وآخر رسالة ثم ذاكرة العميل والرسائل والعروض عبر قراءات منفصلة. أصبحت هذه القراءات داخل معاملة MySQL للقراءة فقط بعزل REPEATABLE READ، مع استخدام قارئ الذاكرة المتحقق من أدلته في الاتصال نفسه. وصول رسالة أو تغير المسؤول أثناء القراءة لا يخلط الحالة الأولى بالأدلة اللاحقة. لا يتغير مسار الكتابة أو قفل تغيير المسؤول أو التحقق من آخر رسالة قبل الاستئناف.

أضيف مصدران يحملان هوية الحساب والمتجر، ويميزان ملخص المحادثة عن الرسالة المصدر. العقود تتحقق من المعرّفات والحدود والتواريخ وقيم حقائق الذاكرة وترتيب الأدلة ومطابقتها للمحادثة وآخر رسالة. لا تُمرر بيانات داخلية إضافية. بقي getHandoff وgetHandoffSource بعقديهما السابقين؛ ربط الواجهة بالمصدرين الجديدين هو المرحلة التالية.

- نجحت 220 حالة للصلاحيات والعقود وحفظ وظائف الفريق، و24 حالة MySQL لتسليم المحادثة، و136 حالة لحصر الميزات؛ المجموع 380 دون فشل أو تخطٍ.
- تغطي حالات MySQL الجديدة تغيير المسؤول ووصول رسالة بين أول قراءة وقراءة الأدلة، وفشل قراءة يتبعه rollback وإعادة الاتصال بنجاح. بقيت اختبارات النسيان ومصدر الرسالة خارج نافذة الملخص والتيننت الآخر وتعارض الاستئناف ناجحة.
- نجح TypeScript وبناء المشروع. لا نصوص أو مفاتيح ترجمة جديدة في هذه المرحلة. لا تغيير مرئي أو لقطة متصفح جديدة؛ لذلك لا تُحسب هذه المرحلة اختبارًا بصريًا أو اختبار Safari/iPhone.

اللقطة متسقة لصفوف قاعدة البيانات عند القراءة، وليست ضمانًا بأن الحالة لم تتغير بعدها؛ تحقق الإصدار وآخر رسالة وقت الكتابة يظل ضروريًا. لا إرسال خارجي؛ النقل في الاختبارات محاكى. لا نشر. التالي عزل نافذة التسليم ومصادرها ومنع النتائج المتأخرة ثم نوافذ التصعيد والعروض وبقية التصميم.
