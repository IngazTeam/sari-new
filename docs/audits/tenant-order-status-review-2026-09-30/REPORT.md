# مرحلة61 — مراجعة حالة الطلب وإيصالها

2026-09-30. التنفيذ على main محليًا، ولا دفع أو نشر أو إرسال خارجي.

أضيف إلى `orders.workspace` عقد مراجعة الحالة والحفظ واستعادة الإيصال وسجل العمليات المرقم. المراجعة تعرض هوية الطلب وحالتي الطلب والدفع والعملة والإجمالي والإشعار الكامل والمستلم إن اختير الإشعار. بصمة المحتوى تشمل النية والمستخدم وبيانات الطلب والبنود والملاحظات والعنوان والإشعار المحسوب. لا تحفظ المراجعة الحالة ولا تجهز إرسالًا بمفردها.

الحفظ يتحقق مجددًا من المستخدم وعضويته وصلاحيته والتيننت داخل المعاملة، ثم يقارن المحتوى المقفول بالمراجعة. تحفظ الحالة والإشعار في الصندوق والإيصال في معاملة واحدة. إعادةUUID نفسه تعيد الإيصال نفسه حتى لو تقدمت حالة الطلب لاحقًا؛ استعماله لمحتوى أو مستخدم مختلف يرفض. فقد إقرار commit لا يعد نجاحًا، وتُغلق الوصلة غير المؤكدة حتى يستعلم العميل عن الإيصال.

الحالات اليدوية هي التجهيز والشحن والتسليم والإلغاء، مع منع الرجوع والحالات النهائية. حالة مدفوع تبقى لمسار الدفع؛ حالة الطلب وحدها لا تثبت الدفع. الطلب ذو مرجع منصة خارجية لا يغيّر محليًا عبر هذا العقد. الفاتورة التي تنتظر الاعتماد أو حُرر خصمها لا تتقدم بالتجهيز، ويمكن إلغاؤها دون اعتماد أو دفع. هذه القيود تخص العقد الجديد؛ إغلاق المسارين القديمين مرتبط بمرحلة الواجهة التالية.

الإلغاء يتطلب سببًا يحفظ بالإيصال، ويحافظ على الملاحظات الأصلية. التتبع الجديد يقبل للشحن والتسليم، ويحفظ التتبع الموجود عند عدم تغييره. اختيار الإشعار صريح، ويلزم قالب مفعّل ورقم صالح ومحتوى ضمن4096؛ لا تفعيل تلقائي ولا إرسال مباشر. تغير النص أو العملة أو العميل أو البنود أو الملاحظات أو القالب يلغي المراجعة السابقة. المبلغ غير القابل للعرض يعاد كشرط يحتاج مراجعة قبل الكتابة.

سجل العمليات20صفًا في الصفحة مع مؤشر استمرار ومعرف التيننت والطلب. الإيصال الشخصي مقيد بالمستخدم وصلاحية الإدارة، بينما سجل الطلب بصلاحية القراءة. تبقى الإيصالات عند حذف الطلب وتُحذف مع التيننت، ولا يعرض سجل طلب غير موجود أو تابع لغيره.
