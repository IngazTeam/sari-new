# مصدر مساحة التقويم — المرحلة 278

أضيف مصدران مشتركان بين الراوتر الرئيسي والمنفصل: calendar.workspace وcalendar.details. الوصول يستند إلى عضوية الحساب في التيننت المختار، ويعيد هوية الحساب والتيننت وصلاحيتي إدارة المواعيد والتكاملات ووقت القراءة. رفض حقول الهوية المحقونة وأخطاء المصادر مغطى بالاختبارات.

القائمة تبحث جميع المواعيد المطابقة دون حد500، وتعيد صفحات25 وعدًا كاملًا حسب حالة الموعد والمزامنة وعددًا لكل يوم. الفترة حتى93يومًا بحدود أيام كاملة، والبحث حرفي بالاسم والهاتف والخدمة والموظف أو المعرف؛ تشمل الفلاتر الحالة والمزامنة والخدمة والموظف. جميع العلاقات والأسماء والفلاتر مقيدة بالتيننت. السجلات غير النشطة تبقى قابلة لاستعراض تاريخها.

العدادات والأيام والصفوف والعلاقات تُقرأ في معاملة واحدة ذات لقطة ثابتة. العقد يرفض اختلاف العد أو الصفحة أو هوية الصفوف أو الأيام أو الفلاتر. المواعيد القديمة ذات حالات غير معروفة أو أوقات تالفة تظهر بإشارة تحتاج مراجعة بدل إسقاط القائمة. التفاصيل تضم الملاحظات والإلغاء والربط والتذكيرات والتواريخ؛ لا تعرض بيانات اعتماد التكامل أو بصمة هويته، وتخفي عنوان التقويم عند تعارض ملكية الربط.

- نجحت212حالة معزولة للمصادر والصلاحيات والعقود وانحدار مراجعة التقويم والتذكيرات والسعة.
- نجحت51حالةMySQL، منها10للمصدر الجديد:503موعد، بحث وصفحات كاملة، حد اليوم الأخير23:59:59، بيانات قديمة، علاقات متقاطعة، عضوية مسحوبة، ولقطة متسقة أثناء إدراج موعد وتغيير اسم الخدمة.
- نجح TypeScript وبناء الإنتاج13.32ثانية. لا ترحيل قاعدة بيانات. أزيلت بيانات الاختبار عبر مساعد التيننتات المؤقتة. السجلات phase278-* في .tmp/tenant-ux.
