# مصدر مقدمي الخدمات — المرحلة 272

استُبدل الراوتر المكرر بمدخل واحد مشترك. تعتمد القراءة على عضوية المتجر المحدد، والكتابة على صلاحية `products.manage` لأن هذه السجلات مقدمو خدمات وحجوزات، وليست حسابات أعضاء الفريق. تتضمن القراءة هوية الحساب والمتجر وإذن الإدارة وبصمة الحقول القابلة للتعديل.

وُحدت حدود الاسم والتواصل والدور ومعرّف التقويم والمعرّفات وساعات الأسبوع. يدعم التعديل الجزئي إبقاء الحقول غير المرسلة ومسح الاختيارية صراحة. ساعات العمل تقبل فترات صحيحة داخل اليوم؛ لا تدعي هذه المرحلة أن محرك الحجز يطبقها، إذ كانت بيانات محفوظة ولم يظهر استخدام لها في مسار التوفر المحلي.

الحفظ يقفل سعة المتجر ثم سجل مقدم الخدمة داخل معاملة. البصمة الاختيارية تكشف تغير السجل منذ المراجعة، والتيننت مثبت في استعلام القفل والتعديل. مسار `delete` أصبح تعطيلًا يحفظ السجل وروابط الخدمات والحجوزات، ويمكن إعادة التفعيل عبر `update`. صُحح وصف الإجراء الحالي حتى لا يعد بإلغاء الروابط. أزيلت دوال الكتابة القديمة غير المستخدمة وغير المعزولة؛ أخطاء القراءة لم تعد تُخفى كقوائم فارغة، ولا يوجد إيصال إنشاء بمعرّف صفر عند تعذر المصدر.

- نجحت 320 حالة معزولة، تشمل حدود الراوترين ومقدمي الخدمات والحجوزات وكتالوج الخدمات.
- نجحت 22 حالة MySQL محلية، تشمل البصمة والتزامن وعزل التيننت والتعديل الجزئي والمسح والتعطيل وإعادة التفعيل وحفظ التاريخ. التيننتات المؤقتة نُظفت.
- نجح TypeScript كامل وبناء الإنتاج في 12.82 ثانية، مع تحذير حجم الحزم القائم. نجح فحص مفاتيح الترجمة.
- لا ترحيل لقاعدة البيانات ولا نشر. السجلات `phase272-*` في `.tmp/tenant-ux`.

التالي واجهة مقدمي الخدمات: قائمة ومحرر متجاوبان، صلاحيات القراءة، إظهار الأخطاء والنسخة، إعادة التفعيل، والحقول الحالية ومنها ساعات العمل ومعرّف التقويم. الواجهة القديمة لا ترسل البصمة بعد، لذلك لا تُنسب لها حماية مراجعة النسخة حتى استبدالها. الحقول الإضافية القديمة في قاعدة البيانات (`specialization`, `serviceIds`, `avatar`, `bio`) تبقى محفوظة؛ ليست حقول كتابة في API الحالي ويجب إظهار وضعها دون ادعاء تطبيق وظائف غير موصولة.
