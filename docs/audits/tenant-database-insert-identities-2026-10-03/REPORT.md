# المرحلة426: إصلاح معرّفات السجلات الجديدة

كشف تتبع خللcreateWebsiteAnalysis أن ثماني دوال أخرى تقرأinsertId من مصفوفة نتيجةDrizzle بدل ترويسة النتيجة. لذلك تُحفظ سبعة أنواع من السجلات ثم يعادundefined؛ بينما سجل الإشعارات كان يفشل قبل الإدراج أيضًا بسبب تمرير نص إلى عمود يتوقعDate.

## الإصلاح

| الدالة | الخاصية المتأثرة |
|---|---|
| createServiceReview | معرّف تقييم الخدمة |
| createGoogleIntegration | معرّف تكامل Google |
| createTimeSlot | معرّف فترة الحجز |
| createWebsiteInsight | معرّف ملاحظة تقرير الموقع |
| createExtractedProduct | معرّف المنتج المستخرج |
| createCompetitorAnalysis | معرّف تقرير المنافس الذي يربط التحديثات والمنتجات |
| createCompetitorProduct | معرّف منتج المنافس |
| createNotificationRecord | معرّف سجل الإشعار ونوع قيمةsentAt |

تُفكك ترويسة النتيجة ويُعاد معرّف رقمي. أزيل تجاوزنوع عمود سجل الإشعار، ويمرDate إلىDrizzle وفق تعريف المخطط. لا تغيير للبيانات القديمة أو شكل الصفحات أو مفاتيح الترجمة أو صلاحياتAPI. هذه الدوال ليست كلها مداخل واجهة نشطة؛ الإصلاح لا يعيد تفعيل مدخل متقاعد.

## الاختبار

أُضيفت اختباراتMySQL فعلية قبل الإصلاح: فشلت الحالات التسع بسببundefined في المعرّف أوtoISOString في سجل الإشعار. نجحت بعدها9/9، ثم أضيف تحقق دقيق من وقت سجل الإشعار؛ نجحت10/10. كل نوع ينشئ سجلين ويتحقق من اختلاف المعرّفين ومطابقتهما للسجل والتيننت الفعلي. تتحقق حالة مترابطة من إنشاء تقرير منافس ثم منتجه وتحديث التقرير بالمعرّف المعاد.

نجحت39 حالةMySQL إجمالًا تشمل الحالات العشر وتراجع تقارير المواقع والحجوزات ومساحات الإشعارات، و92حالة لواجهاتها وصلاحياتها وتفويضGoogle. نجحت الأنواع والبناء وفحصdiff. البيانات مصطنعة في قاعدة محلية وتنظف بعد كل حالة. لم يُرسل إشعار أو يُتصل بـGoogle أو موقع خارجي.

## المتابعة

هذه مراجعة عقد الحفظ فقط، وليست إثباتًا لاكتمال أمن مسار المنافسين أو تشغيل مزود خارجي. لا نشر أو دفعGit. كشفت مراجعة مسار المعرفة طباعة أجزاء من محتوى الملفات ونتائج النموذج في السجلات؛ تليها مرحلة إزالة هذه النسخ غير اللازمة مع الاحتفاظ بتشخيص عددي مفيد.
