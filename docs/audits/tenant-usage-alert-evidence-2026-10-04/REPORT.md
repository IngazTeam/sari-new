# المرحلة 486 — دليل تنبيهات الاستخدام وإزالة المصدر القديم

أعيد ربط تنبيهات الاستخدام وإحصاءاتها بمصدر workspace المتحقق. المسار القديم كان يقرأ `conversationsUsed` و`voiceMessagesUsed` وحقول حملات ومنتجات من كائن لا يحتويها، فينتهي إلى نسب NaN وعداد تنبيهات صفر مضلل. المصدر الجديد يعتمد على عدادات الاشتراك المسجلة للمحادثات والرسائل والصوت فقط، ويستبعد المقاييس غير المتاحة مع إعلان نقص التغطية صراحة. الاشتراك المنتهي أو الغائب لا يولد تحذير سعة؛ الحالات المتعارضة وغير المؤكدة لا تُصنف فحصًا مكتملًا.

التذكير بنهاية التجربة يستخدم النهاية الفعلية الأسبق ووقت قراءة المصدر، وروابط التنبيهات تشير إلى صفحات الباقات والاستخدام الصحيحة. كل تنبيه يحدد رقم المتجر لأن صندوق الإشعارات يتبع الحساب. زال ادعاء أن بلوغ العداد يثبت منع التشغيل أو المبيعات. استدعاء الجدولة يجمع المصدر مرة واحدة دون إنشاء سياق مدير مصطنع.

كتابة التنبيه في صندوق الحساب تمر بمعاملة وصلاحية المالك الحية، ثم `INSERT ... SELECT` مقيد بمعرف المتجر ومالكه الحالي. لا إقرار دون affectedRows=1 ومعرف إدراج صحيح وإتمام المعاملة. رُفض المالك السابق حتى عند بقاء عضوية بدور owner. النتيجة المجهولة لا تُعاد تلقائيًا ولا تظهر نجاحًا. هذه كتابة إشعار داخلي فقط؛ لا بريد أو واتساب أو push.

حُذف `getMerchantCurrentUsage` ومساعد تخمين الحدود `buildUsageMetric` بعد زوال آخر مستهلكيهما. لم تعد هذه القراءات القديمة موجودة في الكود التشغيلي. أضيف حارس إصدار `usage-notifications-evidence-v1`، وأزيلت تجاهلات TypeScript من راوتر التنبيهات المعاد بناؤه.

## التحقق

- أثبتت الحزمة أولًا **19 إخفاقًا من23** لسلوك الراوتر القديم، ثم نجحت **120/120** حالة تشمل دليل الأرقام والنطاق والبيانات المجهولة والمصادقة والمدخلات المزورة وإيصال الحفظ والواجهات المرتبطة.
- **13/13 MySQL** للمصدر والكتابة المحلية: حفظ للحساب الصحيح، منع حساب متجر آخر، سحب عضوية المالك، وتبدل مالك المتجر رغم بقاء العضوية. العينات منشأة خصيصًا ثم نُظفت.
- **57/57** حالة لحارس الإصدار، وTypeScript وبناء التطبيق وفحص فروق Git. لا تغيير بصري أو مفاتيح ترجمة أو ترحيل في هذه المرحلة.

حدود النطاق: دفعة التنبيهات ليست معاملة واحدة لكل المتاجر، ولا تضيف هذه المرحلة سجل جدولة دائمًا أو مفتاح منع تكرار بين استدعاءات مدير متكررة. عند تعذر حفظ لاحق قد تكون تنبيهات سابقة في الدفعة محفوظة؛ الرسالة تطلب المراجعة قبل إعادة المحاولة. الأدلة لوقت القراءة، وليست وعدًا ببقاء الاشتراك دون تغير. عامل البريد المنفصل `jobs/usage-alerts.ts` ليس هذا الراوتر ويظل ضمن مراجعة الأتمتة. بقيت صفحات الباقات والمقارنة والشراء وبقية السجل للمراحل التالية.

لا تشغيل لدفعة تنبيهات على تيننت المستخدم، ولا إرسال خارجي أو push أو نشر. لا ادعاء فحص اختراق شامل أو توافق Safari/iPhone فعلي.
