# واجهة إعدادات التقويم — المرحلة 281

استُبدلت CalendarSettings القديمة بمكوّن فعلي متوافق مع تصميم لوحة التاجر. يعرض حالة الإعدادات المحفوظة وهدف التقويم وآخر مزامنة مسجلة وعدد المواعيد، دون اختلاق بريد الحساب أو تأكيد وصول Google أو إرسال التذكيرات. الربط يتم في التبويب نفسه، دون نوافذ منبثقة أو مؤقتات مراقبة. يُتحقق من عنوان Google قبل الانتقال، ولا تعد معلمة العودة في الرابط دليل نجاح.

مراجعة الفصل تصف أثره بدقة وتحفظ المواعيد؛ تتطلب إقرارًا وبصمة النسخة. لا تظهر رسالة النجاح إلا بعد قراءة حالة جديدة، وتُمنع إعادة الإجراء عند النتيجة غير المؤكدة حتى التحديث. يُمنع النقر المتكرر وتُهمل النتائج بعد تبديل الحساب أو التيننت. أُضيفت ترجمة كاملة بالعربية والإنجليزية، وعودة التركيز بعد إغلاق المراجعة، وتسمية زر الإغلاق بالعربية.

- نجحت 100 حالة معزولة للواجهة والمصدر والصلاحيات، ثم 63 حالة متأثرة بعد تحسين الإغلاق والتركيز. تشمل الحالات الخمس، رفض البيانات ذات الهوية المختلفة، تكرار النقر، النتائج المتأخرة، الرابط الخارجي غير الموثوق والغموض. نجح فحص TypeScript النهائي.
- نجح تدقيق 12128 استدعاء ترجمة و880 مفتاحًا ديناميكيًا، دون نقص أو خطأ متغيرات. نجح بناء الإنتاج النهائي خلال 14.31 ثانية؛ تحذير أحجام الحزم القائم فقط.
- نجحت تجربة الفصل الفعلية محليًا على اتصال اختبار ذي بيانات وهمية. قُرئت الحالة الجديدة ثم تحققت قاعدة البيانات من إزالة بيانات الوصول وتعطيل الاتصال وحفظ معرّفه وهدفه. نُظف السجل التجريبي 597 بعد التحقق من عدم وجود روابط مواعيد إليه. حفظ المواعيد الموجودة مغطى باختبارات MySQL في المرحلة 280؛ كانت التجربة الحية هنا بلا مواعيد.
