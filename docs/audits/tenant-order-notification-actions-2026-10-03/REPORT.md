# حفظ قوالب وإغلاق إشعارات بمراجعة محددة

المرحلة 411، بتاريخ 2026-10-03. أضيف مساران جديدان للكتابة، تمهيدًا لنقل الشاشة إليهما وإغلاق المسارين القديمين في المرحلة التالية.

حفظ القالب مرتبط ببصمة النسخة والمستخدم والتيننت. يعاد التحقق من العضوية وصلاحية واتساب وحالة المستخدم والمالك والمتجر داخل معاملة، مع قفل يمنع تعديلين متزامنين أو إنشاءين متزامنين لحالة غائبة. إذا تغير المصدر، يُرفض الحفظ حتى يقرأ التاجر النسخة الحالية. النص المطابق المحفوظ بالفعل يرجع نتيجة «موجود حاليًا» ولا يدعي أن الطلب الحالي كتبه. المتغيرات غير المدعومة والقوالب الفارغة والطويلة تُرفض. لا يؤدي الحفظ إلى إرسال أو إعادة توليد رسالة موجودة بالطابور.

إغلاق المراجعة يتطلب معرف وبصمة كل سجل، بحد أقصى 25 سجلًا ومنع التكرار. تقفل المعاملة السجلات ومراجعها وإيصالاتها، وتتحقق من حالتها ثم تغلق المجموعة كاملة أو تتراجع كاملة. لا تدخل الحالات الجديدة ضمن المجموعة. يسجل الإغلاق المستخدم والتوقيت ولا يعيد الإرسال. فشل تأكيد المعاملة يرجع نتيجة غير مؤكدة ويتلف الاتصال، دون إعادة محاولة كتابة تلقائية. يجب قراءة الوضع الحالي قبل أي قرار جديد.

صُحح أيضًا قارئ تجهيز القالب القديم ليقبل التفعيل `1` تحديدًا، بدل اعتبار أي قيمة غير صفرية تفعيلًا.

## التحقق

- نجحت 93 حالة للمدخلات، والقوالب، والمعاملات، وإرجاع الخطأ غير المؤكد، والصلاحيات، والعقود والتنسيق.
- نجحت 35 حالة MySQL: إنشاء وحفظ واستدعاء مطابق، تعديلان متزامنان لا ينجح منهما إلا واحد، بصمة من مستخدم أو تيننت مختلف، إغلاق المجموعة المحددة مع بقاء حالة جديدة، منع الإغلاق الجزئي عند تغير سجل، مراجع أجنبية أو حدث مفقود، وسحب العضوية/صلاحية الكتابة وتعليق الحساب أو المتجر. تشمل المجموعة إعادة اختبارات المصدر ودليل الإيصال. نُظفت البيانات المؤقتة.
- نجحت أنواع التطبيق والبناء؛ لا ترحيل أو إرسال خارجي أو نشر.

هذه المرحلة تضيف المسارات المحمية. المداخل القديمة لا تزال موجودة مؤقتًا حتى انتقال الشاشة التالي؛ لذلك لا تُعد حماية التزامن مطبقة على الواجهة القديمة بعد. تبقى مراجعة حارس النقل والعامل والموك أب والهاتف ضمن العمل المتبقي.
