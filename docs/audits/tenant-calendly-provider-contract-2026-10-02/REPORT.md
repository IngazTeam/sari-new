# المرحلة 337 — حدود مصدر Calendly وروابط الحجز

2026-10-02، main؛ جميع طلبات المزوّد في الاختبارات محاكاة محلية، دون رفع أو نشر.

## الإصلاح

- تُقرأ الاستجابة تدريجيًا بحد 2 MiB، ويُلغى جسمها عند تجاوز الحجم المعلن أو المستلم؛ لا تُحمّل استجابة غير محدودة قبل فحص حجمها.
- لا تُعرض مجموعة مقصوصة على أنها مكتملة. حد المجموعات 1–2000 سجل بحسب المستدعي، مع 20 صفحة كحد أقصى، وكشف الدورة ومؤشرات التصفح غير الصالحة. يظل المسار ومعطيات اختيار المجموعة الأصلية ثابتة بين الصفحات.
- يُقبل فقط رابط مورد Calendly القياسي المطابق لنوعه؛ يتحقق الرد من هوية الموعد أو المدعو المطلوب. إنشاء الاشتراك يتطلب حسابًا ومنظمة صالحين، والحذف مقيد بمورد اشتراك webhook.
- روابط الحجز قابلة للنقر فقط عبر HTTPS على calendly.com أو www.calendly.com بلا اعتماد أو منفذ خاص أو معطيات أو fragment. الخادم والواجهة يتحققان من الرابط؛ تظهر رسالة مترجمة عندما يكون غير متاح أو غير صالح.
- بلوغ حد المدعوين مع وجود مواعيد لاحقة لا يعيد نجاحًا صامتًا للمزامنة القديمة.

## التحقق

209 اختبارات ناجحة وصفر فشل أو أخطاء تحميل مجموعات، و13 حالة MySQL ناجحة. فحص الأنواع والبناء ناجحان؛ البناء 16.48 ثانية ضمن الميزانية. الترجمة: 12715 استدعاء و880 مفتاحًا ديناميكيًا بلا نقص أو اختلاف interpolation. جُدد سجل الصفحات والخصائص.

تشمل الاختبارات الرد المتدفق الكبير وإلغاؤه، حد content-length قبل القراءة، اكتمال الصفحات ورفض الصفحة الزائدة، روابط javascript وانتحال النطاق، رد مورد مختلف، رفض حذف مسار API عام، بقاء الصلاحية أثناء قراءة الرد، ورسالة الرابط غير المتاح في مكون الصفحة الفعلي.

## الحدود والمتابعة

التحقق محافظ: روابط الحجز ذات معطيات أو fragment لا تُعرض كرابط. لم يُجرّب حساب Calendly حي أو Safari/iPhone فعلي. المزامنة القديمة لا تزال قد تحفظ بعض المواعيد قبل فشل لاحق؛ لا تعد هذه المرحلة ترحيلًا إلى لقطة ذرية أو إيصال دائم. التالي مصدر محلي كامل للمواعيد وحالات webhook والربط ثم العمليات المراجعة والواجهة والموك أب. يبقى خطأ مراقب الغلاف المركزي في334 مفتوحًا.
