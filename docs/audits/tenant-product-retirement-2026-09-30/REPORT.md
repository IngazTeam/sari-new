# المرحلة83: إغلاق كتابات المنتجات القديمة

حُذفت الإجراءات products.create/update/delete/bulkDelete من موجه التيننت بعد التأكد من عدم وجود مستهلك لها في client/src. المسار الحالي يستخدم products.editor للحفظ والمراجعة والإيصال. الاستدعاء القديم يعود NOT_FOUND ولا يصل إلى كاتب بيانات؛ لا تحويل ضمني لطلب قديم إلى حذف أو حفظ جديد.

أُزيلت دالتا deleteProduct غير المستخدمتين من db.ts وdb/products.ts. بقيت createProduct/updateProduct لأن الاستيراد والمزامنة وREST والإعداد الأولي تستعملها. لم تُحذف بيانات منتجات أو خيارات أو متغيرات.

## التحقق

-87 اختبارًا ناجحًا للموجه والصلاحيات والكتالوج والمحرر والحذف. اختبارات الإغلاق تؤكد غياب العمليات الأربع وبقاء إجراءات القراءة والاستيراد والمزامنة والخيارات، وتفحص جميع مصادر الواجهة بحثًا عن مستهلك قديم.
-34 اختبار MySQL ناجحًا: دقة الأسعار والعملة والصفر والقيم التاريخية والمتغيرات، عزل التيننت واختيار المتجر والأدوار، معاملات المحرر والحذف والإيصالات. اختبارات العملة والصلاحيات انتقلت إلى API الفعلي الجديد دون ابتلاع أخطاء أو اعتبار غياب قاعدة البيانات نجاحًا.
-نجح TypeScript وبناء التطبيق والخادم والعامل. أُعيد تشغيل خادم3018 المحلي تحت حظر الشبكة الخارجية؛ لا مزوّد أو نشر.
-استُبدل ملف products.test.ts القديم الذي كان يمسك الأخطاء ويعتبر الاختبار ناجحًا بفحص فعلي لحدود الموجه. لا يدّعي هذا إصلاح بقية الاختبارات القديمة المبنية على قيم ثابتة في ملفات أخرى.

## ما بقي

لا تغيير لتغطية التصميم:78 عامة و31 جزئية و9 تفصيلية و8 تحويلات. الاستيراد القديم وكتابات المزامنة وREST والإعداد الأولي والمتغيرات والخيارات والفئات ليست ضمن إغلاق CRUD هذا. إنشاء المتغيرات والخيارات ما زال له إجراءات منفصلة؛ لا يوجد مستهلك واجهة لها حاليًا، لذلك تصميمها وتنفيذ حفظها الآمن ما زالا مسجلين للمتابعة.

المرحلة التالية معاينة استيراد واضحة: دعم CSV/XLSX، أخطاء لكل صف وعمود، دون سعر صفر مختلق أو استدعاء ذكاء/Google Sheets تلقائي أثناء المعاينة. ثم اعتماد مراجع وإيصال ومطابقة الشاشة والموك أب. Safari/iPhone وبقية الحصر مفتوحة. لا دفع أو نشر.
