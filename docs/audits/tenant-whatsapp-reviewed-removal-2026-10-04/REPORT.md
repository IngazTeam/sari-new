# المرحلة509 — حذف اتصال واتساب بمراجعة ومعاملة متحققة

حُذف تنفيذ مدخل deleteInstance القديم من الراوتر الرئيسي والمستقل، وأصبح يرفض الكتابة قبل الوصول إلى التخزين. تستخدم شاشة الاختبار والموك أب deleteReviewedInstance ببصمة اللقطة المعروضة وهوية التيننت والسجل، مع إقرار يطابق الحساب والمتجر والهدف.

## المعالجة

- بصمة إزالة معزولة بالحساب والمتجر وجميع الاتصالات في اللقطة، تشمل تغير الرقم والحالة والمفتاح والبيانات المرتبطة. يحسب SQL بصمة السجل؛ لا يخرج المفتاح أو metadata الخام من قاعدة البيانات لهذا الغرض. يخرج HMAC معتم فقط إلى العميل. القائمة غير الكاملة لا تمنح بصمة حذف.
- قفل التاجر المعتمد قبل أقفال الصفوف، ثم معاملة واحدة وصلاحية مالك حية وحساب نشط ونسخة مطابقة. نُقلت آلية فحص الصلاحية المشتركة إلى دالة قابلة للاستخدام على الاتصال نفسه، دون تغيير قواعدها.
- حذف Green API فقط، مع اشتراط affectedRows=1، وانتخاب الأساسي بالدالة المعتمدة، والتحقق من غياب الهدف وبقاء هويات بقية السجلات وعددها ومن أساسي واحد عندما يوجد اتصال نشط.
- إقرار النجاح بعد commit فقط. فقدان رد commit لا يعيد اتصالًا مشكوكًا فيه إلى المجمع ولا يعلن النجاح. الأقفال تحرر على الاتصال نفسه، والفشل غير القابل للتحقق يعرض نتيجة غير مؤكدة دون تفاصيل قاعدة البيانات.
- الواجهة ترسل البصمة المثبتة عند فتح المراجعة، وترفض إقرار حساب أو متجر مختلف، ثم تقرأ القائمة لتأكيد الغياب. المحاكاة ترفض المراجعة المتقادمة أيضًا. لم يتغير تصميم المقاسات المفحوص في507.
- أضيفت قدرة إصدار whatsapp-reviewed-removal-only-v1 لمنع الرجوع إلى كاتب التشخيص القديم. لا ترحيل جديد؛ أمر تحديث الخادم المعتمد محفوظ.

## الفحص

نجحت مجموعات المصدر والصلاحية والواجهة والتقاعد واختبارات الأقفال والأساسي، مع فحص الحصر والحفاظ على126مسارًا، وحارس الإصدار63حالة. نتائج المجموعات وأعدادها النهائية في [checks.json](checks.json)؛ المجموعات المعادة متداخلة ولا تُجمع مرتين.

MySQL:43حالة مميزة عبر الحذف14 والتشخيص18 والملف11. شملت تأكيدين متزامنين لا ينجح منهما إلا واحد، تغير المفتاح والرقم والسجل المجاور، سحب المالك، تيننت آخر، حساب غير نشط، Meta وقائمة101سجل، وانتخاب الأساسي وحذف آخر رقم. فشلت عينة واحدة أولًا لأنها استخدمت حالة حساب غير موجودة؛ صُححت إلى deletion_pending وأعيدت مجموعة الحذف14/14. كل العينات مؤقتة ونُظفت.

نجح TypeScript وبناء الإنتاج والمعاينة. لم تتغير مفاتيح ترجمة في هذه المرحلة. جُربت مراجعة وحذف سجل داخل الموك أب المحلي، وظهرت نتيجة متحققة وبقي الاتصال الآخر؛ [الدليل المصور](local-preview-removal.png). قرأ التطبيق المحلي الفعلي القائمة الفارغة بالعقد الجديد. لا حذف لحساب العرض أو اتصال مزود ولا رسائل خارجية.

الحصر592ملفًا و2780موضع تحكم و126مسارًا، دون مسارات محذوفة أو روابط حرفية غير مطابقة أو ملفات يتيمة. بقي حفظ اتصال التشخيص القديم بحاجة تحقق وذرية مستقلة، وإيصال دائم لاستعادة الإرسال، ومراجعة كتابات إدارة الأرقام الأخرى. لا ضمان تعافٍ دائم للحذف بعد انقطاع الشبكة؛ يعاد فحص السجل. لا Safari/iPhone فعلي أو اختبار اختراق شامل أو push أو نشر.
