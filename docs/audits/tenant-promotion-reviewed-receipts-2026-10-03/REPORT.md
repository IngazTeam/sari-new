# المرحلة 379 — مراجعة قرارات العروض وإيصال الحفظ

أضيفت مراجعة للإنشاء والتعديل والتفعيل المطلق والإيقاف والحذف. ترتبط بالشروط المقترحة وتعريف العرض والخصم المرتبط والتيننت والمستخدم وحالة المدة وعدد الأماكن المشغولة، وتنتهي بعد خمس دقائق. تغيّر العدادات وحده لا يبطل المراجعة. تُعرض القيم القديمة والمقترحة وأثر القرار صراحة؛ لا تُعتبر العدادات دليل مبيعات أو عملة مثبتة.

الهجرة 0196 تحفظ إيصال النتيجة مع العرض والكود في معاملة واحدة، بمفتاح طلب فريد لكل تيننت. إعادة الطلب المقبول تعيد الإيصال بعد إعادة فحص الصلاحية الحالية، حتى بعد حذف العرض أو انتهاء المراجعة. تغيير مضمون مفتاح مستخدم يُرفض. يمكن قراءة نتيجة الطلب بمعرّفه بعد فقدان الرد. لا يُحذف أو يُعدّل الخصم المرتبط بسبب تعديل العرض أو حذفه.

أعيد استخدام نفس التحقق والأقفال والكتابة الذرية للمداخل المتوافقة والمداخل المراجعة لتجنب اختلاف التنفيذ. تبقى مداخل الواجهة القديمة مؤقتًا حتى نقلها في المرحلة التالية؛ وجود هذه المرحلة لا يعني إغلاقها أو استكمال تجربة المستخدم.

التحقق: نجحت 108 حالات وحدة وصلاحيات، و37 حالة MySQL تشمل مصدر البيانات والكتابة السابقة والمراجعة والإيصال، و21 حالة إصدار، دون فشل أو تخطي. شملت التزامن، فقدان تأكيد الحفظ، فشل الإيصال والتراجع، انتهاء المراجعة أثناء الكتابة، تغير التعريف والجدولة والحصة، رفض النطاق أو المراجع المخالف، منع تسريب خصم تيننت آخر، واستعادة الحذف دون تكراره. نجح TypeScript والبناء في 14.10 ثانية.

طُبقت الهجرة على قاعدة الفحص المحلية المعزولة فقط، وحُفظت قدرة الإصدار `promotion-reviewed-receipts-0196`. لا نشر أو إرسال خارجي. التالي واجهة العروض الجديدة والموك أب والهاتف وإغلاق المداخل القديمة، ثم تصحيح استخدام العروض ودليلها في عقل ساري.
