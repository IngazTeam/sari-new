# المرحلة352 — مصدر شاشة أكواد الخصم

أضيف `discounts.workspace` لقراءة لقطة واحدة معزولة تشمل هوية الحساب والتيننت والصلاحية، والعدد الكامل وعدد المطابقات وصفحات25 والبحث بالكود أو المعرّف ومرشحي الحالة والمصدر. لا يُحوّل رقم صفحة قديم بصمت إلى صفحة أخرى. تُحسب النتائج والملخص من المجموعة نفسها، وتبقى بيانات العملاء المرتبطة بالأكواد الآلية محفوظة.

تُفصل الحالات بترتيب صريح: بيانات غير سليمة، غير مفعّل، منتهي، استُهلك حده، ثم متاح وفق القيود المحفوظة. «متاح» هنا لا يثبت إرسال العرض أو أهلية طلب بعينه أو نجاح البيع. تُعرض القيم غير الصالحة كقيمة غير متاحة مع سبب، ولا تتحول إلى صفر أو صلاحية استخدام. عدد الاستخدامات مجموع العدادات الصحيحة مع عدد العدادات المستبعدة. يُحفظ النص كما هو للعرض الآمن كنص، وتضم بصمة السجل محتواه واستخدامه لإمكان مراجعة النسخة في المرحلة التالية.

نجحت **235 حالة معزولة و10 MySQL**، وفحص الأنواع والبناء. تشمل الاختبارات61سجلًا للوصول لما بعد الصفحة الأولى، و31سجلًا بقاعدة البيانات، عزل تيننت آخر، صلاحية المشاهد وسحب العضوية، منتصف الليل والتاريخ غير الصحيح، الأكواد الآلية، العدادات الفاسدة، والفلاتر. الأدلة `.tmp/tenant-ux/phase352-tests.json` و`phase352-mysql.json` وسجلا الأنواع والبناء.

الاستجابة محدودة25سجلًا، لكن القراءة الداخلية الحالية تجمع سجلات المتجر كاملة لحساب التصنيفات والملخص. لذلك لا يُدّعى اختبار أداء لملايين الأكواد أو ترقيمSQL كامل. الواجهة القديمة لم تتحول بعد إلى هذا المصدر، ولا تُعد الصفحة أو الموك أب مكتملين. التالي ربط الشاشة الجديدة والأفعال المراجعة وأخطاء الحقول بهذا العقد، ثم المحاكاة المطابقة والهاتف. لا نشر أو اتصال خارجي أو Safari/iPhone فعلي.
