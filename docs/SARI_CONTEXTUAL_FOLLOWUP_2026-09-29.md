# المتابعة المطلوبة من العميل عبر فهم المحادثة — 2026-09-29

أصبحت **جدولة متابعة جديدة بطلب العميل** تعتمد على التحليل السياقي المحفوظ عبر OpenAI أو ZahyPi المختار مركزيًا من السوبر أدمن. لا تستدعي هذه المرحلة نموذجًا إضافيًا، ولا تعود إلى مطابقة «ذكرني/كلمني» عند غياب التحليل أو فشله. هذه متابعة تنفيذية للخطة، خصوصًا G2/G7/G8/G9، وليست اعتمادًا لجودة النموذج أو درجة 10/10.

## السلوك المنفذ

| النقطة | التنفيذ والتحقق |
|---|---|
| فهم الطلب | حقل `followup` يميز الطلب المحدد، والحاجة إلى توضيح الموعد، وعدم طلب جدولة. يقرأ كلام الطرفين؛ موافقة مثل «هذا الوقت مناسب» ترتبط بموعد المساعد السابق. |
| مصدر الزمن | يتلقى المحلل وقت كل رسالة ومنطقة سياسة التاجر. ترتبط التواريخ النسبية بالرسالة الأصلية، ويُحفظ وقت الرسائل ضمن دليل التحليل. تغيير الوقت أو المحتوى يبطل الدليل الجديد. |
| الموافقة | لا تكفي الكلمة أو ثقة النموذج وحدها. يُشترط مصدر حالي من العميل، واقتباسات موجودة في الحوار، وثقة ≥0.85، وعدم الشرط أو الغموض أو الرفض أو تعارض التصعيد/الشراء/الحجز. |
| الموعد | يتحقق الكود من التاريخ الحقيقي، والساعة، والمنطقة، والمستقبل، وحد 90 يومًا من المصدر، وساعات الإرسال. فجوة التوقيت الصيفي والساعة المكررة تستلزمان توضيحًا. لا ينتقل الموعد تلقائيًا ليوم أو ساعة أخرى. |
| الحفظ | يعيد المسار قراءة التحليل المختوم داخل معاملة قصيرة بعد قفل ملكية المحادثة. تُرفض هوية مختلفة، أو رسالة أحدث، أو فقدان الذاكرة/الدليل. يتسلسل الحفظ على التاجر ويمنع التكرار ويحترم سقف المتابعات. |
| العلامة الدائمة | يضع الخادم `contextual_customer_request` بنفسه. لا يحدد المستدعي مصدر الإثبات أو الموعد أو نص الرسالة لهذا النوع. حذف التحليل لاحقًا لا يحوّل الطلب إلى موافقة قديمة. |
| الإقرار | لا يظهر نجاح الحفظ إلا بعد وجود متابعة محفوظة وإعادة التحقق من إثباتها. إعادة معالجة الرسالة تستخدم الموعد والمنطقة المحفوظين؛ تغيير منطقة السياسة لا يغير الموعد المتفق عليه. |
| التنفيذ المؤجل | العامل يعيد التحقق من التحليل والموعد ويلغي المهمة عند تغير الإثبات. لا يفسر رفض الشراء داخل عبارة تقبل متابعة مؤجلة بقاعدة كلمات منفصلة عن التحليل. |
| قبل واتساب | حارس النقل يعيد فحص الموافقة والملكية والرسائل الأحدث والهدوء والحد الأسبوعي، ثم الإثبات والموعد المطابق، قبل قبول حجز إرسال جديد أو إعادة استخدام حجز قديم. لا يحتفظ بقفل SQL أثناء اتصال المزوّد. |
| نطاق الموافقة | طلب المتابعة يجيز رسالة واحدة، ولا ينشئ اشتراكًا تسويقيًا عامًا. انسحاب أحدث أو رد جديد يمنع الإرسال. |

اختلاف المنطقة الزمنية المذكورة عن منطقة التاجر يطلب توضيحًا في هذه النسخة، ولا ينفذ تحويلًا مفترضًا. الساعات غير المحددة مثل «بعد الظهر» أو «الساعة خمسة» دون سياق يحسمها تحتاج توضيحًا. التعليمات والمخرجات الاصطناعية لا تثبت أن المزوّد الحي يفهم كل هذه الحالات بدقة؛ هذا جزء من التقييم المتبقي.

## التوافق وحدود التنفيذ

- لا توجد مهاجرة جديدة. تُستخدم جداول التحليل والمتابعة والسياسة وسجل الإرسال القائمة؛ يلزم وجود مهاجرات الخطة السابقة ومنها `0150`.
- حقلا المتابعة وتاريخ دليل الرسالة اختياريان **دون قيم افتراضية**؛ اجتاز اختبار قراءة ختم قديم لا يحتويهما. التحليل القديم بلا حقل متابعة لا يجيز إنشاء متابعة جديدة بالكلمات.
- المتابعات الموجودة قبل هذا الإصلاح تحتفظ بعقد الموافقة والحماية القديم. لا تُنقل أو تُلغى تلقائيًا. علامة المتابعات الجديدة تجعل إثبات التحليل إلزاميًا طوال عمرها.
- محلل الوقت اللفظي القديم باقٍ لاختبارات الانحدار التاريخية، ولا يستدعيه أي مسار إنتاج لإنشاء متابعة مطلوبة؛ الاعتماد عليه من الملف الجديد هو استيراد نوع فقط.
- متابعة التسويق الآلية، وتذكير المواعيد، ومسار المجموعات، وإثراء الذاكرة ليست مغلقة بالكامل بهذا التغيير. تحتاج الفروع المتبقية مراجعة مستقلة لاستبعاد القرارات اللفظية.
- لا توجد استدعاءات AI حية أو إرسال واتساب حقيقي أو قراءة محادثات إنتاج ضمن الفحوص. تعذر اعتماد المزوّد الحي سابقًا بسبب رفض اتصال قاعدة التطبيق؛ لم تُعد هذه الجولة الاتصال بها أو تطلب أسرارًا.

## التحقق والأدلة

نجح **849 اختبارًا في 40 ملفًا** بحسب أحدث نتيجة لكل ملف: 717 اختبارًا دون قاعدة بيانات و132 على MySQL محلي اصطناعي. لم تُتجاوز اختبارات ضمن هذه الجولات. تشمل النتائج:

- 35 حالة SQL جديدة لدورة المتابعة، مع نقل واتساب الحقيقي داخل التطبيق ومزوّد خارجي مصطنع، وتكرار الحفظ، وعدم منح اشتراك تسويقي، وموافقة حوارية بلا كلمة تذكير.
- رفض المصدر أو التيننت/الهاتف/هوية المعاينة غير المطابقة، والتلاعب بالتحليل أو الرسائل أو توقيتها، وفقدان الذاكرة، والرد الأحدث، وتغير الملكية أو المنطقة أو الموعد.
- إبطال حجز إرسال سبق قبوله إذا تغير الإثبات، وإعادة الفحص بعد تحميل حساب واتساب وقبل نداء المزوّد، وإلغاء العامل لمتابعة حُذف تحليلها.
- عدم الجدولة عند فشل المزوّد، أو JSON غير صحيح، أو دليل مختلق، أو شرط، أو وقت مرجعي مزور، أو تغير السياق أثناء التحليل.
- التوافق مع التحليلات القديمة، والمعاينة، والشخصيات، ومسارات البيع، وحوكمة OpenAI/ZahyPi والميزانية، وفحوص أمنية محلية سابقة ضمن الانحدار.

نجحت الأنواع، وفحص مفاتيح الترجمة، والبناء. تفاصيل العدد والأوامر والبصمات ونتيجة الترجمة الحالية في [الدليل الآلي](SARI_CONTEXTUAL_FOLLOWUP_EVIDENCE_2026-09-29.json). استمر تحذير البناء القائم لبعض الحزم الكبيرة؛ اجتازت حزمة الدخول ميزانيتها.

توسعت مجموعة تقييم النموذج إلى **42 حوارًا**، منها 8 للمتابعة: موافقة على اقتراح سابق، وصياغة غير مباشرة، واقتباس، ونفي، وشرط، وغموض الساعة، واختلاف المنطقة، والتمييز بين موعد الدورة وطلب التواصل. أصبح مقياس التقييم يعتبر جدولة غير مقصودة خطأً حرجًا حتى لو كان `action=respond`، ويتحقق من التاريخ والوقت المتوقعين ومن قابلية تنفيذ الموافقة الصحيحة. شُغلت المجموعة بوضع `dry-run` فقط.

هذه اختبارات هندسية واختبارات اختراق محلية على حالات مصطنعة؛ لا تمثل اختبار اختراق شاملًا للإنتاج ولا قياسًا للإقناع أو التحويل أو دقة المزوّد الحي.
