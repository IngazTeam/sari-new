# تفويض إطلاق تجربة المبيعات وإلغاؤه — 25 سبتمبر 2026

استكمال بعد `ecf33c92` للبنود B044 وB045 وB065. أضيفت طبقة تفويض وإلغاء على الخادم؛ لا تشغّل رسائل واتساب أو توزع العملاء بذاتها.

## التنفيذ

- أربع عمليات API محمية بصلاحية `bot_settings.manage`: تجهيز أساس التفويض، حفظه صراحة، قراءة حالته الحالية، وإلغاؤه نهائيًا. هوية النشاط والمستخدم تأتي من العضوية والجلسة؛ ترفض العقود إدخال هوية بديلة أو ساعة أو حالة تشغيل أو فائز.
- يعيد تجهيز التفويض وحفظه قراءة الخطة والعينة المثبتة والتأهيل والسياسة والقطاع وأحدث تشغيل للردود وأحدث تقييم بشري والمراجعة المستقلة. تحفظ بصمة المراجعة كاملة ونافذة القياس وسبب المشغّل وإقراراه؛ لا تكفي إشارة نجاح قديمة أو ثقة نموذج.
- تفويض واحد غير قابل للاستبدال لكل خطة، مع قفل نشاط داخل معاملة وقيد تفرد SQL. يجب حفظه قبل وقت بداية الإدخال بساعة قاعدة البيانات. قراءة الحالة بعد ذلك تتحقق من الأدلة مجددًا وتميز `scheduled` و`enrollment_open` و`enrollment_closed`؛ لا تعدل نافذة الخطة أو تفعل السياسة.
- تظل مراجعة التخطيط نفسها ممنوعة عند بداية الإدخال وبعدها. المسار الجديد يفصل قراءة صلاحية الاعتماد القائم أثناء النافذة عن صلاحية إنشاء مراجعة جديدة بعد الموعد.
- اختلاف مراجعة أو تشغيل أو مصدر أو نموذج أو قطاع يجعل التفويض غير صالح حاليًا. فشل قراءة إعدادات المزوّد لا يتحول إلى نجاح. `authorizationCurrent` يصف مطابقة الأدلة عند القراءة فقط، وليس تصريح إرسال يمكن تخزينه أو استعماله لاحقًا؛ النافذة المفتوحة شرط مستقل لأي توزيع مستقبلي.
- الإلغاء يسجل السبب والمستخدم والوقت مع انتقال الحالة في معاملة واحدة. يعمل بعد تقادم المصادر أو سحب الخطة أو حذف حساب المراجع، ويمنع إعادة التفويض لنفس الخطة. لا يعلن فائزًا، ولا يعيد فتح التفويض بمفتاح جديد.
- استرجاع الطلب المطابق بعد فقد إقرار الحفظ يعيد السجل نفسه، بما فيه حالة الإلغاء الحالية. تغيير المستخدم أو المعنى تحت UUID نفسه يرفض. الإيصال المسترجع تاريخي و`eligibility=not_checked`؛ لا يتجاوز التحقق الحالي.
- السجلات تحفظ هوية المشغّل الأصلية بعد حذف حسابه، ويصبح التفويض غير صالح حاليًا إذا حذف حساب صاحبه. تبقى قراءة الإلغاء التاريخي ممكنة بعد حذف صاحبه، مع تمييز غياب الحساب.
- الترحيل `0112_sales_experiment_launches` يضيف جدولي التفويض والإلغاء، دون ترحيل تلقائي للموافقات السابقة إلى تفويض. مرجع المراجعة محفوظ ضمن اللقطة التاريخية؛ حذف المراجعة لا يمحو ذلك السجل ويمنع صلاحيتها الحالية.

## المتبقي

هذه الدفعة تنفذ تفويض الإطلاق وإلغاءه وقراءة صلاحيته على الخادم. لم تُضف واجهة التفويض، أو تُوصل التجربة بمسار توزيع العملاء وإرسال الردود. تظل `activationAllowed=false` و`experimentStarted=false` و`assignmentCreated=false`؛ لا يجوز استخدام نتيجة القراءة كتصريح مؤجل للإرسال.

الخطوات التالية: واجهة التفويض والإلغاء، ثم تخصيص دائم للعميل داخل معاملة تعيد التحقق عند الاستخدام، وتسجيل التعرض بناءً على إيصال واتساب المقبول، وربط المدفوعات والاستردادات وتحليل الأثر داخل النافذة المثبتة. قراءة التراجع أو استعادة إعداد سابق ليست سجل تشغيل أو إيقاف تلقائي؛ الإلغاء الصريح هو الحالة النهائية المثبتة في هذه الدفعة.

حالة الخطة **4 مكتملة / 59 جزئية / 8 مفتوحة**. لا قياس جودة على نموذج حي أو أثر تجاري بعد. سقف المنصة اليومي 100 دولار واختيار OpenAI/ZahyPi المركزي مستمران.
