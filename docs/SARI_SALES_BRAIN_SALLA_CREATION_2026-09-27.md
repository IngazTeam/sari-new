# منع تكرار إنشاء طلب سلة — استكمال B037 وB041

التاريخ: 27 سبتمبر 2026. أساس التنفيذ `0720d0cc` على `main`.

## النتيجة

صار مسار `orders.createFromChat` يحفظ عملية دائمة قبل تحليل الرسالة أو الاتصال بسلة. إعادة الطلب بالمعرّف نفسه تعيد النتيجة المحلية المثبتة، أو تعرض حالة معلقة/مراجعة؛ ولا ترسل POST جديدًا. رقم العملية مرتبط بالتاجر والمستخدم وبصمة بيانات الطلب. إذا نجح حفظ الطلب وفُقد إقرار المعاملة، تستعاد النتيجة من الحفظ الذري نفسه.

**تغيير عقد API:** حقل `requestId` بصيغة UUID مطلوب. ينشئه المستدعي مرة عند بدء العملية ويحفظه مع بياناتها؛ يعيد المعرّف والبيانات نفسها عند انقطاع الاتصال. لا يولّد معرّفًا جديدًا تلقائيًا عند المهلة. لا يوجد مستدعٍ لهذا المسار في واجهات `client` الحالية، وفق البحث في المستودع؛ أي مستدعٍ خارجي يجب تحديثه قبل النشر.

## التنفيذ

1. جدول `salla_order_creations` ذو مفتاح فريد `(merchant_id, request_id)` وحالات `preparing / dispatching / completed / rejected / review`. يحفظ الفاعل وبصمة الطلب والمتجر والنتيجة؛ لا يحفظ نص المحادثة أو العنوان أو رمز اتصال سلة. رابط الدفع محفوظ ضمن النتيجة كما هو محفوظ في الطلب.
2. حجز العملية يسبق تحليل الذكاء الاصطناعي؛ الطلب المتكرر لا يعيد التحليل. تستخدم البصمة تمثيلًا ثابتًا بعد التحقق من الحقول وتطبيعها، ولا تتأثر بترتيب مفاتيح العنوان أو حالة أحرف UUID.
3. جلسة المستخدم وصلاحية `orders.manage` تحددان الفاعل والتاجر. إعادة استخدام المعرّف ببيانات أو مستخدم مختلف مرفوضة. المعرّف نفسه لدى تاجر آخر يمثل نطاقًا مستقلًا ولا يكشف نتيجة التاجر الأول.
4. قبل POST تُعاد مطابقة اتصال سلة، ويثبت الانتقال إلى `dispatching` بمعاملة. عامل آخر أو محاولة أخرى لا يستطيعان امتلاك الانتقال مرة ثانية. لا يُحتفظ بقفل قاعدة بيانات أثناء HTTP.
5. الطلب المحلي ودليل متجره ونتيجة العملية تنتقل إلى `completed` في معاملة واحدة. فشل الكتابة يرجع الثلاثة؛ فقد إقرار commit بعد نجاحه يسترد النتيجة المحفوظة دون POST آخر.
6. فشل التحضير قبل حجز الإرسال يسجل `rejected`. المهلة أو الرد المشوه أو تغير الربط بعد محاولة الإرسال يسجل `review`. تعطل العملية وهي `preparing` أو `dispatching` لا يجعل الزمن وحده إذنًا لإعادة تشغيلها.
7. استعادة النجاح تتحقق من التاجر النشط والطلب المحلي ودليل المتجر والاتصال النشط وتطابق الرقم ورابط الدفع مع النتيجة المحفوظة. حذف الطلب أو تعديل هويته لا يحرر رقم العملية لإعادة الإنشاء؛ يبقى سجل العملية محفوظًا حتى حذف التاجر.
8. استعادة نتيجة قديمة لا تعيد البريد أو إشعار لوحة التحكم أو المزامنة الجانبية إلى Sheets. هذه الآثار الجانبية لا تملك في هذه الدفعة صندوق إرسال متينًا؛ انقطاع العملية بعد حفظ الطلب قد يفقد إشعارًا، ولا نزعم ضمان وصوله.
9. فحص مخطط العمليات قبل الاستخدام غير مخزن كنجاح دائم؛ غياب الجدول أو قيد التفرد يوقف التحضير والإرسال. الترحيل `0138` إضافي، ولا يعيد تصنيف طلبات قديمة أو يغير ميزانية الذكاء الاصطناعي.

## التشغيل والتوافق

طبّق الترحيل قبل الكود. تكرار نفس العملية يتطلب المستخدم نفسه، ومعرّفها، وبياناتها بعد التحقق. الإرجاع الناجح يتضمن `replayed` لتمييز استعادة النتيجة. حالات التعارض تعرض رسالة واضحة ولا تعيد إنشاء الطلب.

عند التراجع إلى إصدار سابق لا يقرأ هذا السجل، يجب إيقاف مسار إنشاء سلة القديم عن استقبال محاولات إعادة تنفيذ هذه العمليات إلى أن تتم تسويتها؛ احتفاظ قاعدة البيانات بالسجل وحده لا يجعل الكود القديم يحترمه. لا تُسقط جدول العمليات عند التراجع، ولا تعتبر الإشعارات الجانبية دليلًا على اكتمال الطلب.

يمكن حصر الحالات التي تحتاج مراجعة باستعلام قراءة محدود، دون إظهار بيانات الطلب أو رابط الدفع:

```sql
SELECT id, merchant_id, actor_user_id, request_id, state,
       store_id, local_order_id, error_code, created_at, updated_at
FROM salla_order_creations
WHERE state IN ('preparing','dispatching','review')
ORDER BY id DESC LIMIT 100;
```

لا تغير الحالة إلى `preparing` ولا تحذف السجل لحل التعليق. النتيجة المجهولة لدى سلة تحتاج مرجعًا موثوقًا وتسوية مستقلة؛ تشابه الهاتف أو المبلغ أو محتوى السلة لا يثبت أنها العملية نفسها. يحظر توليد معرّف جديد كوسيلة آلية لتجاوز التعليق. عند `rejected` المثبت قبل الإرسال، يمكن للمستخدم بدء عملية جديدة بعد تصحيح سبب الرفض.

## المتبقي وحدود القبول

- هذه حماية من تكرار **نفس رقم العملية في المسار المحلي**. إنشاء معرفين مختلفين يظل عمليتين؛ ربط العملية باتفاق بيع وموافقة عميل ثابتة ومنع تعدد المسارات لنفس الموافقة مطلوب لاحقًا.
- لا تدعي الدفعة دعم idempotency من سلة نفسها أو تنفيذ تسوية تلقائية لطلب قُبل خارجيًا ولم يصل رده. لم نضف مرجعًا خارجيًا غير مثبت في عقد المزوّد، ولا إعادة POST بعد timeout.
- حفظ بصمة المدخلات لا يمثل اتفاق بيع كاملًا أو موافقة على السعر النهائي. هوية منتجات سلة عند تبديل المتجر، والعروض والخيارات والموافقة الصريحة تظل بنودًا مفتوحة.
- لا تُنشأ حقيقة قبض مالي أو إيراد أو تعلم من نجاح إنشاء الطلب. ربط اتفاق البيع والعميل ونتائج الدفع وByaan والموظف، وتسوية طلبات سلة القديمة، ما زال ضمن B041.
- السلوك القائم لطلبات سلة القديمة غير الموثقة بالمتجر باقٍ: تحتاج مراجعة قبل استئناف متابعتها الآلية. لم تعد هذه الدفعة إتاحتها بالتخمين.
- B037 وB041 جزئيان. الحصيلة **4 مكتملة / 61 جزئية / 6 مفتوحة**. لا اعتماد 10/10 أو قبول مزوّد حي. لم تتغير الأسعار أو اختيار OpenAI/ZahyPi أو سقف المنصة 100 دولار يوميًا.
- الاختبارات محلية على بيانات صناعية. لم يُنفذ Push أو نشر أو اتصال بحسابات العملاء.
