# استعادة نتائج التعلّم وحالتها التشغيلية — 24 سبتمبر 2026

استكمال بعد `71eac452`. كانت الاستجابة المحفوظة تنتظر رسالة أخرى أو استدعاء تحليل يدوي لكي تُسقط كمقترحات. كما كان الاستدعاء اليدوي يعلن بدء التحليل من خمس إشارات رغم أن المحرك يشترط عشرًا، ويعيد نجاحًا قبل معرفة النتيجة.

## التنفيذ

- عامل مستقل يبدأ مع runtime الواتساب وينفذ عند البدء وكل دقيقة. يعالج **الاستجابات المحفوظة فقط**؛ لا يستورد محرك التحليل أو المزوّد أو خدمة الإشعارات، ولا يرسل للعميل أو ينشئ اتصال AI جديدًا.
- دفعة بحد أقصى 20 مهمة، بحجز SQL عبر `SKIP LOCKED` ومدة ثلاث دقائق. رمز الاستعادة منفصل عن هوية التحليل؛ إعادة استخدام رمز قديم أو تغيير هوية النشاط أو المهمة لا يسمح بإسقاط نتيجة جديدة.
- تُترك مهلة 60 ثانية بعد حفظ الاستجابة لإكمال المسار الأمامي. بعد ذلك يمكن استعادتها دون عتبة إشارات أو رسالة جديدة. يُعاد فحص المصادر والملكية والبصمة عند الاستعادة، ويُعاد فحص الحجز قبل معاملة الإسقاط.
- الفشل يرجع المقترحات وتعليم المصادر معًا ويحتفظ بالاستجابة. يُؤجل الحفظ بتدرج من دقيقة إلى ساعة؛ لا تحجب مهمة معطلة بقية الأنشطة. فقد إقرار commit الناجح لا يُعيد جدولة النتيجة المكتملة. الحجز المنتهي يُستعاد برمز جديد، والعامل القديم لا يغيّر المهمة الأحدث.
- الحالات `reserved/dispatched/uncertain` لا تدخل هذا العامل؛ لا يمكن لمرور الوقت أن يطلق طلبًا مدفوعًا جديدًا. يبقى اختيار OpenAI/ZahyPi وسقف المنصة اليومي 100 دولار في مسارهما المركزي.
- يتوقف العامل مع runtime وينتظر عمله الجاري. عند فشل تهيئة عامل لاحق، تُوقف بقية العمال الذين بدأوا؛ فشل إيقاف عامل واحد لا يمنع محاولة إيقاف الآخرين.
- شاشة المخ تعرض 11 حالة تشغيلية باللغة العربية والإنجليزية. تعرض آخر تحديث وموعد أهلية الاستعادة وعدد مقترحات الدورة، بما فيه الصفر. زرها يحدّث القراءة فقط؛ لا يوجد زر لإعادة إرسال طلب مجهول. لا تعرض نجاحًا قديمًا عند فشل جلب الحالة الحالية.
- API الحالة يستمد النشاط من العضوية الموثقة، ويرجع حقولًا محددة فقط: الحالة والتوقيت ومحاولات الاستعادة وعدد المقترحات. لا نصوص مصدرية أو استجابة أو بصمات أو رموز حجز أو رسائل أخطاء داخلية. لا يقبل مدخلات أو أوامر إضافية.
- الاستدعاء اليدوي للتحليل يحتفظ بصلاحية `bot_settings.manage` وينتظر النتيجة الفعلية. لا نجاح قبل الحفظ، ولا وعد بظهور النتيجة خلال دقيقة، ولا ادعاء أن سبع إشارات تكفي؛ الاستعادة من استجابة موجودة تسبق شرط الإشارات الجديدة.

## الترحيل والتشغيل

ترحيل `0101_learning_analysis_recovery` يضيف حقول الحجز والجدولة والمحاولات والخطأ المصنف ووقت الاستعادة، وفهرس الاستحقاق. يُؤهل `responded` القائمة فقط، دون إطلاق `reserved/dispatched/uncertain` أو تغيير إشارات ومقترحات سابقة. يلزم تحديث المخطط والويب وجميع العمال معًا. لم يحصل دفع أو نشر في هذه الدفعة.

يعتمد التأجيل والحجز على ساعة MySQL. زمن الأهلية المعروض ليس وعدًا بوقت إنجاز؛ مدة التنفيذ وحالة قاعدة البيانات والعمال تؤثر فيه. تعطّل تسجيل التأجيل يترك الحجز ليستعاد عند انتهائه. القراءة التشغيلية لا تعدّل المهام.

## الحدود والمتبقي

- لم تُنفذ تسوية الطلبات `dispatched/uncertain` أو ربط هوية طلب المزوّد بدفتر المهام؛ تبقى محجوبة إلى أن يتوفر دليل على نتيجتها. الشاشة توضح الحالة ولا تمنح إذن إعادة الإرسال.
- لا يعيد العامل حجز تحليل لم يصل ردّه، ولا يعيد تشغيل الحجوزات المنتهية أو رفض الميزانية من تلقاء نفسه. يعالج `responded` وحدها.
- لا يرسل العامل إشعار اكتمال أو ملخص فجوات. تظهر المقترحات بعد نجاح الحفظ؛ ضمان الإشعار يحتاج outbox مستقلًا لاحقًا. المسار الأمامي يحتفظ بإشعاراته السابقة بعد الحفظ.
- لا تُنسخ المصادر إلى سجل المهمة. يبقى JSON الاستجابة حتى الإتمام أو الإبطال أو حذف النشاط؛ لا توجد مدة احتفاظ تلقائية جديدة أو محو شامل لكل عميل. خانة المهمة تحفظ آخر تحليل فقط.
- واجهة المتصفح المختبرة تستعمل API fixtures وChromium، وليست قبولًا إنتاجيًا موثقًا أو اختبار Safari/iPhone فعليًا. اختبارات الأمان محلية؛ لم تُجرَ اتصالات مدفوعة أو رسائل حية أو اختبارات على بيانات العملاء.
- تقييم الإقناع والتحويل، والتجربة المضبوطة، واعتماد سياسة التعلّم والتراجع عنها ما زالت مفتوحة. الحالة **4 مكتملة / 57 جزئية / 10 مفتوحة**؛ لا ادعاء جاهزية 10/10.
