# ثبات طلب سلة بين الاستخراج والتنفيذ

استكمال خطة مخ ساري والمبيعات في 28 سبتمبر 2026 فوق `8a910924` على `main`. تعالج هذه الدفعة أجزاء B034 وB035 من تفاصيل الاتفاق والتحقق قبل الأثر، داخل مسار `orders.createFromChat` الذي ينفذه مستخدم النشاط بصلاحية `orders.manage`. لم يتحول هذا المسار إلى إنشاء طلب آلي بمجرد قول عميل واتساب «نعم».

## الفجوات التي أُصلحت

كان سجل إنشاء سلة يحفظ بصمة الطلب الأصلي ويمنع تكرار معرف العملية، لكن الانتقال من `preparing` إلى `dispatching` يتحقق من رمز المحاولة والمتجر والمنتجات فقط. لم يكن يعيد مقارنة بيانات المستلم والعنوان والنص الفعلية بالبصمة المحفوظة. لذلك لم تكن حماية إعادة المحاولة وحدها كافية لمنع تمرير تفاصيل أخرى داخل تنفيذ العملية الأولى.

كذلك كان الاستخراج يعيد فحص الكتالوج بعد انتهاء النموذج، لكنه يعيد الاسم والمعرف والكمية دون السعر والإصدار اللذين قرأهما. كان الإنشاء اللاحق يقبل نسخة المنتج الحالية حتى إن تغير السعر بعد رجوع الاستخراج. وفحص المنتج عند الإنشاء كان يقيد النشاط والمتجر دون اشتراط اتصال إسقاط المنتج نفسه. أخيرًا، كان نشاط التاجر يُفحص عند حجز العملية، وملكية التفاعل قبل انتظار حارس الإرسال؛ لم تكن هاتان القراءتان تغطيان فترة الانتظار اللاحقة.

## السلوك الحالي

1. **ربط الأثر بالطلب المحفوظ:** يعيد الإنشاء تكوين المدخل الصارم نفسه، بما فيه اسم المستلم ورقمه ونص الطلب وكامل العنوان الوطني والإحداثيات. يحسب حارس الإرسال البصمة بالطريقة نفسها المستخدمة عند الحجز، ويشترط تطابق `request_hash` داخل UPDATE الانتقال الوحيد إلى `dispatching`. اختلافها يمنع POST، ثم تصبح العملية مرفوضة قبل الإرسال. لا يُستهلك كوبون أو ينشأ طلب محلي أو أثر إشعار أو Sheets.
2. **حمل دليل الكتالوج:** ينتج الخادم `catalogEvidence` بهوية النشاط والمتجر والاتصال وبصمة النص، وبالمنتجات المختارة وأسمائها وكمياتها وأسعارها وإصداراتها. لا يقبله مخطط خرج النموذج أو مدخل API العام. يشترط الإنشاء وجوده ومطابقته، ثم يقارن كل منتج بقراءته الحالية. غياب الدليل أو تغير السعر أو الإصدار أو المصدر أو الكمية يوقف الإنشاء. لا يعاد الاستخراج أو إرسال الطلب تلقائيًا لتجاوز الاختلاف.
3. **تثبيت المدخلات أثناء الانتظار:** تُحلل المحاولة والعنوان والمنتجات والدليل إلى نسخ مستقلة قبل أول انتظار. وكذلك ينسخ حارس الإرسال هويته وسلته ومدخله قبل فحص المخطط وأقفال SQL. تعديل المراجع التي يحتفظ بها المستدعي أثناء الانتظار لا يغير ما يجري التحقق منه أو ما يُرسل ويُحفظ.
4. **إعادة تحقق الأهلية:** يقفل حارس الإرسال التاجر النشط بقفل مشاركة قبل فحص الاتصال والمنتجات. تعليق النشاط بعد الحجز يوقف الأثر. اختيار المنتج يشترط الآن تطابق `connection_id` مع الاتصال الجاري، إضافة إلى النشاط والمتجر والهوية المحلية والخارجية.
5. **ملكية التفاعل قبل POST:** بعد نجاح حجز الإرسال، يعاد فحص ملكية تفاعل واتساب مباشرة قبل استدعاء عميل سلة. فقد الملكية في انتظار قاعدة البيانات يمنع الاتصال. تظل المحاولة المحجوزة للمراجعة ولا تُعاد إلى حالة قابلة للإرسال تلقائيًا.

عقد API العام وأسماء مفاتيح الترجمة لم تتغير. يستمر نجاح المسار المعتاد: استخراج موثق، إرسال واحد، حفظ الطلب وهوية متجره ومهام ما بعد الإنشاء في المعاملة القائمة، ثم إعادة النتيجة المحفوظة عند تكرار المعرف نفسه. الاختلافات في الفراغات الخارجية وترتيب مفاتيح العنوان لا تسبب رفضًا كاذبًا لأن الحجز والتنفيذ يستعملان التطبيع نفسه.

## الاختبار والأدلة

**809 اختبارًا ناجحًا** (120 لأدوات النشر، و391 وحدات وأمن، و298 على MySQL)، دون فشل أو تخطٍّ، و**54 سيناريو متصفح**. نجحت الأنواع والمخطط والترجمة والبناء. فحص الترجمة: 7681 استدعاء و248 مفتاحًا ديناميكيًا دون أخطاء. [أسماء الحالات وبصمات المصدر والبوابات](./audits/sales-brain-implementation-2026-09-23/salla-intent-verification.json)، و[أدلة المتصفح](./audits/sales-brain-implementation-2026-09-23/salla-intent-ui/results.json). اختُبرت قاعدة 8a910924 مع ملفات الدفعة، وطابقت الملفات المحلية بصماتها قبل الكوميت.

تستخدم حالات MySQL الخدمات الفعلية للحجز وحارس الإرسال والكتالوج وإسقاط الطلب، وقاعدة محلية منفصلة على 33089. يُحاكى النموذج وHTTP فقط في الرحلة التي تبدأ من الاستخراج وتنتهي بالإنشاء. يستخدم جزء من اختبارات الإنشاء دليل كتالوج اصطناعيًا مطابقًا لصفوفه، وتوجد حالات مستقلة تمر بدالة الاستخراج نفسها لإثبات إنتاج الدليل وحمله ورفض تغيره بين المرحلتين.

تشمل اختبارات الهجوم والانحدار:

- تبديل الاسم والرقم والنص والدولة والمدينة وكل حقول العنوان الوطني وخطي الإحداثيات بعد حجز المعرف؛ لا POST ولا طلب محلي ولا آثار لاحقة.
- محاولة حقن الأسعار أو المنتجات أو `catalogEvidence` في مدخل API أو خرج النموذج.
- غياب دليل الاستخراج وتبديل نشاطه أو متجره أو اتصاله أو نصه أو كميته أو سعره أو إصداره أو اسم المنتج وتكرار عناصره.
- تغير السعر والإصدار والاتصال بعد انتهاء الاستخراج بنجاح، وتعليق النشاط بعد حجز العملية.
- تغيير المراجع الأصلية أثناء انتظار الخدمة؛ يظل الجسم المرسل والإسقاط المحلي مطابقين للنسخة التي تحققت منها الخدمة.
- فقد ملكية المعالجة بعد حجز الإرسال؛ تبقى المحاولة للمراجعة دون اتصال أو إعادة إرسال عند التكرار.
- الحالات القائمة للتزامن، وفقد إقرار commit، والنتيجة غير المؤكدة بعد POST، والكتالوج غير الموثق، وعزل الأنشطة، وأثر الإشعارات وSheets ومراجعتها.

بوابة التحقق: `node scripts/testing/verify-salla-intent.cjs` على Node 22.23.2 وpnpm 10.4.1، مع `SARI_TEST_DATABASE_URL` لقاعدة الاختبار المحلية. تستبعد البوابة بيئة الإنتاج وتحظر الشبكة الخارجية، وتثبت بصمات المصدر قبل الفحص وبعده. اختبارات المتصفح انحدار لواجهة مراجعة آثار سلة القائمة بالعربية والإنجليزية؛ لا تمثل واجهة اتفاق شراء جديدة أو جلسة إنتاج أو اختبار Safari/iPhone فعلي.

## التوافق والحدود والمتبقي

- **لا ترحيل جديد:** لم يتغير مخطط 0143 أو سجل الترحيلات أو أمر النشر. يستخدم الحارس `request_hash` الموجود بالفعل. يستمر عرض نتائج الإنشاء المكتملة سابقًا وفق التحقق القائم؛ لا تعاد كتابة التاريخ ولا توليد أدلة استخراج قديمة. تغير التوقيع داخلي فقط؛ الاستدعاء الذي لا يحمل النص الأصلي ودليل الاستخراج يُرفض قبل الإرسال.
- دليل الاستخراج نسخة داخل دورة الخدمة، **وليس عرضًا محفوظًا أو إثبات موافقة عميل**. لا يحتوي مفتاح اتصال أو نصًا سريًا من المزوّد. تتطلب الموافقة المستقبلية سجل عرض مستقلًا بمعايير الخطة، ولا يكفي تمرير هذا الكائن إليها.
- السعر المثبت هنا هو **سعر المنتج في الكتالوج المحلي الموثق**. لا يثبت السعر الحي بعد POST، ولا يحجز المخزون عند المزوّد، ولا يحدد الضريبة والشحن والإجمالي النهائي قبل إنشاء سلة. لا يبقى قفل قاعدة بيانات عبر HTTP؛ تغيّر مزوّد خارجي بعد آخر قراءة يظل بحاجة إلى تسعير/اتفاق موثق مستقل.
- لا يضيف هذا الفحص توقيعًا على سجل قاعدة البيانات، ولا يحمي من كود داخلي متعمد يعيد تصنيع الدليل. فائدته منع انحراف المدخلات والكتالوج في المسار الموجود، مع حدود عامة صارمة تمنع المستخدم والنموذج من إدخال هذا الدليل.
- راجعت [إنشاء الطلب في توثيق سلة](https://docs.salla.dev/5394145e0) و[فهرس واجهاته الرسمي](https://docs.salla.dev/llms.txt) في 28 سبتمبر 2026. يوثق الفهرس إنشاء مسودة، لكن تعذر جلب عقد صفحة المسودة ومخرجاتها خلال هذه المراجعة. لم يُخترع endpoint أو يُستخدم إنشاء طلب فعلي كتجربة تسعير. ما زال يلزم تثبيت طريقة معتمدة للحصول على الإجمالي النهائي وشروط الشحن والدفع قبل موافقة العميل، ثم تنفيذ الموافقة بإثباتها وإيصالاتها.
- لا اتصال حي بسلة أو واتساب أو نموذج ذكاء اصطناعي، ولا push أو نشر. لم تتغير إدارة OpenAI/ZahyPi أو سقف 100 دولار يوميًا للمنصة.
