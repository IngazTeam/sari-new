## ما أُنجز

- صفحة `/admin/sales-evidence` داخل غلاف الإدارة الحالي، مع بند «أدلة المبيعات» في القائمة ورابط من تفاصيل التاجر يملأ معرّفه. صلاحية القراءة الفعلية يعيد API التحقق منها في SQL، بما في ذلك نشاط حساب المسؤول.
- تسجيل الصفحة في قائمة مسارات الخادم أيضًا، حتى يعمل فتح رابطها مباشرةً وتحديث المتصفح بحالة HTTP 200. كشف فحص الأمان غياب هذا التسجيل في المحاولة الأولى؛ أُصلح وأُضيف تحقق HTTP فعلي للرابط مع معرّف التاجر.
- نموذج قراءة صريحة يتقبل الأرقام العربية والفارسية واللاتينية، ويرفض الكسور والترميز العلمي والمدخلات الجزئية والقيم غير الآمنة والنطاق المقلوب. التصفية بمعرّفات **أدلة الطلبات** وليست أرقام الطلبات أو التواريخ. النهاية الاختيارية تقرأ حتى أحدث دليل داخل لقطة الخادم؛ حد 200 لا يقتطع الإجماليات.
- عرض عدد الطلبات المحلية وزد، وما لديه قبض مثبت أو استرجاع كامل أو دفع غير مقاس أو ربط خارجي غير مثبت. الاسترجاع جزء من الطلبات ذات القبض؛ لا يجمعهما العرض كفئتين مستقلتين.
- عرض القبض والاسترجاع والصافي المرصود، وتفاصيل مبلغ الإنشاء ومرجعه وفرق الفاتورة لكل طلب، والربط بزد وسلسلة الدفع والتوقيت UTC وبصمات الأدلة. الصفر المثبت بعد الاسترجاع يظهر صفرًا؛ غياب الدليل يظهر نصًا صريحًا. يحفظ تنسيق العملة آخر هللة حتى `Number.MAX_SAFE_INTEGER`، وكذلك الفرق السالب.
- بيان حدود النتيجة في الصفحة: ليست كل مبيعات النشاط، ولا ربحًا أو قياسًا لأثر ساري أو سياسة فائزة. حالة تنفيذ الطلب والتدخل البشري واكتمال المصادر غير مقاسة، والاسترجاع الجزئي غير مدعوم في هذا المصدر. لا دمج بين لقطات أو نطاقات متداخلة.

## حماية القراءة من النتائج القديمة

تعديل أي حقل أو الانتقال إلى تاجر آخر يُخفي النتيجة ويفصل استعلامها. يستخدم المكوّن hooks `tRPC` و`React Query` الفعلية، ويلغي القراءة عند إزالة المكوّن، ولا يعرض بيانات محفوظة أثناء إعادة القراءة أو بعد فشلها. إعادة تركيز النافذة تعيد التحقق، والتحديث المتوقف بسبب انقطاع الشبكة يخفي النتيجة حتى يستأنف الاتصال. لا إعادة محاولة تلقائية بعد رفض الخادم؛ رسالة الواجهة لا تكشف تفاصيل الخطأ الداخلية.

تفحص الواجهة توافق الإصدار والنطاق والتاجر وهوية كل صف وحدود الأعداد والتوقيت قبل العرض. هذا فحص توافق للعرض؛ لا يستبدل صلاحية الخادم أو تحقق البصمات في قاعدة البيانات. React يعرض النصوص كنصوص، دون إدخال HTML من النتيجة.

في التشغيل الأول نجحت 3264 حالة MySQL، وفشل تجهيز حالة واحدة في `beforeEach` لتجاوز مهلة 10 ثوانٍ قبل دخول اختبار رفض بيانات مزوّد مزوّرة. أُعيد ملفها كاملًا (371 حالة) من المصدر المجمد نفسه وبالمهلة والإعدادات نفسها، فنجح دون فشل. نتائج قبول MySQL تجمع تلك الإعادة مع 2894 حالة ناجحة من بقية الملفات؛ ليست نتيجة تشغيل واحد متصل خالٍ من الإخفاقات. حُفظت بصمات التقريرين وسبب المصالحة في دليل هذه الدفعة، ولم يُعدَّل الكود أو تُرفع المهلة لتجاوز الفشل.
