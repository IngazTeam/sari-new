# تسوية محاولات التوافق النصية والصوتية دون إعادة إرسال

التاريخ: 27 سبتمبر 2026. أساس الدفعة: `81889805`. تكمل [حماية الصوت](./SARI_SALES_BRAIN_VOICE_AUTHORITY_2026-09-27.md) و[حماية النص](./SARI_SALES_BRAIN_TEXT_AUTHORITY_2026-09-27.md) ضمن [خطة الإصلاح](./SARI_SALES_BRAIN_10_OF_10_PLAN_2026-09-23.md).

## المشكلة والسلوك الجديد

كان قبول نقل نص المجموعة أو صوتها قد يُحفظ في outbox، ثم يفشل إسقاط الرسالة أو حفظ نتيجة التوافق. بقيت المحاولة معلقة عند إعادة التحقق رغم وجود دليل نقل محفوظ. منع التكرار كان يعمل، لكن النتيجة لم تُستعد.

أضيفت تسوية SQL فقط للحسابات المسجلة ذات نية `v2`. يستخدم الإرسال الجديد من هذه الحسابات التسوية نفسها بعد النقل، وتستدعيها إعادة التحقق بالطلب الأصلي. لا تستدعي التسوية التخزين أو المزوّد، ولا تعيد حجز المحاولة أو تفعيل الملكية. يبقى UUID والنص أو التسجيل الأصلي مطلوبين عبر واجهة الرد الحالية؛ لم يضف هذا الإصلاح شاشة مستقلة أو endpoint لتجاوز محتوى الطلب.

| الحالة | السلوك |
|---|---|
| نص أو صوت v2 من حساب مسجل، مع طلب نقل مطابق وحالة sent/delivered/read وإيصال صالح بلا خطأ متناقض | تسوية النتيجة والإسقاط مرة واحدة |
| النقل queued/failed/received، حتى لو احتوى إيصالًا | يبقى معلقًا، دون إعادة إرسال |
| طلب نقل مفقود أو منقّى أو متعارض أو إيصال غير صالح | لا نجاح مستنتج ولا إعادة نقل |
| صوت لم يثبت رابط ملفه بعد الرفع | يبقى معلقًا، ولا يعاد الرفع |
| اتصال قديم بلا outbox أو سجل v1 بلا حساب مثبت | تُقرأ نتيجته القديمة أو يبقى معلقًا |
| نجاح محفوظ سابقًا، ثم حذف المحادثة أو outbox أو الرسالة | تُقرأ النتيجة؛ لا يعاد إنشاء الرسالة أو إرسالها |

## التحقق من الدليل والحفظ

- تربط التسوية الصف بالتاجر والموظف الأصلي وهوية المحاولة. يجب أن يبقى المستخدم نشطًا وصاحب صلاحية رد في التاجر الحالي؛ موظف آخر مخوّل لا يستطيع الاستيلاء على محاولة غيره.
- يجب أن يطابق outbox الحساب المسجل المثبت ومزوّد Green API والاتجاه الصادر ومفتاح المحاولة. تطابق بصمة كامل `request_json` الطلب المتوقع، بما فيه الوجهة والنص أو الرابط واسم الملف وحارس المحاولة وبصمة أساسها. أي حارس إضافي أو حقل مختلف يمنع التسوية.
- لا تكفي رسالة موجودة بالمحادثة لإثبات النقل. يلزم سجل النقل المطابق وحالة قبول محفوظة وإيصال بصيغة صحيحة دون `error_code` متناقض.
- تُقفل المحاولة والنقل، ثم يحفظ إسقاط الرسالة ونتيجة المحاولة وملخص الدليل بمعاملة واحدة. فشل أي جزء يتراجع عن إسقاط تلك المعاملة؛ المحاولة التالية تستعيد النتيجة من الدليل نفسه دون أثر خارجي.
- الرسالة الموجودة بالإيصال نفسه يجب أن تطابق الاتجاه والنوع والكاتب والمحتوى، ورابطي الوسائط والصوت للصوت. لا يستبدل النظام رسالة متعارضة؛ يبقى الإصلاح اليدوي أو مراجعة التعارض مطلوبًا.
- عند تغيير هوية العميل أو حذف المحادثة، تحفظ نتيجة النقل مع `persisted:false` ولا تسقط على وجهة مختلفة. لا يجدد النظام الملكية أو فترة إيقاف الروبوت أثناء التسوية.

لا يعتمد إثبات إرسال سابق على بقاء مفتاح الحساب الحالي كما كان، أو استمرار الحساب نشطًا أو استمرار ملكية الموظف للمحادثة. لذلك لا تمنع هذه التغييرات تسوية الدليل السابق؛ وهي أيضًا لا تعطي إذنًا بإرسال جديد. التحقق من صلاحية المستخدم الحالية يظل إلزاميًا.

## ملخص الدليل والتوقيت

يحفظ الحقل الاختياري `settlement` داخل أساس التوافق نوع الرسالة ومعرف outbox والحساب وبصمة الأساس الأصلي والطلب وإيصال المزوّد ووقت التحقق المحلي. يبقى نطاقه `compatibility_result_only`. يربط القارئ بصمة الأساس الأصلي بطلبه قبل إضافة النتيجة، ويرفض ملخصًا لا يطابق النوع أو الحساب أو الطلب. لا يرسل هذا الملخص للعميل ضمن استجابة الرد، ولا يحفظ مفاتيح واتساب الخام.

الوقت هو وقت التسوية المحلي، **وليس وقت الإرسال أو التسليم عند المزوّد**. تسجل الرسالة المستعادة بهذا الوقت المحلي؛ لا يُعاد بناء وقت تاريخي مفقود، ولا تُستخدم التسوية لإثبات أن الرسالة سبقت دفعًا أو سببت بيعًا.

لا تكتب هذه التسوية في `ai_sales_staff_acceptances` ولا تحول المجموعة أو الاتصال القديم إلى مساعدة بيعية مقاسة. البصمات تحقق اتساق وليست توقيعًا ضد مسؤول يعيد كتابة البيانات كاملة. الدليل مصدره outbox المحلي المحفوظ؛ لا تستعلم التسوية من المزوّد عن إيصال مفقود.

تستمر التنقية في حفظ طلب النقل غير المحسوم. بعد التسوية يسمح بتنقية محتوى outbox مع بقاء النتيجة وملخص الدليل داخل المحاولة. لا يتطلب استرجاع نجاح سبق حفظه إعادة وجود المصدر أو إعادة إسقاط رسالة حُذفت.

نجحت **327 رحلة متصفح**: 113 لتقرير التجربة و48 لأدلة الطلبات و118 للرد النصي والمسودات و48 للصوت. تشمل العربية والإنجليزية والجوال ولوحة المفاتيح وحالات الغموض والتسجيل والإلغاء وإعادة التحقق. لم تتغير الواجهة في هذه الدفعة.

## النشر والتراجع والمتبقي

لا ترحيل SQL جديد، وآخر مخطط يبقى `0132`. لا تعديل في مفاتيح الترجمة أو مدخلات العميل أو سقف المنصة اليومي 100 دولار. يجب تحديث الويب والعمال معًا وفق دليل النشر. قارئ الإصدار السابق لا يفهم `settlement` ويعترض النتيجة الجديدة بدل إعادة إرسالها؛ لا تحذف المحاولات أو دليلها لتجاوز خطأ القراءة عند التراجع. سجلات v2 السابقة بلا هذا الحقل تبقى مقروءة، وسجلات v1 لا تُرقّى بأثر رجعي.

المتبقي المباشر: سجل نقل دائم للاتصال القديم الذي لا يملك outbox، وعرض إداري للمحاولات غير المحسومة لا يتطلب إعادة إرسال التسجيل من المتصفح، وسياسة مراجعة التعارض والرفض، وتنظيف ملفات الرفع غير المرتبطة. لا عامل خلفي جديد أو إعادة إرسال تلقائية في هذه الدفعة. حالات غياب الدليل تحتاج مراجعة أو دليلًا موثوقًا إضافيًا؛ لا تتحول إلى نجاح لمجرد مرور الوقت.

مصفوفة الخطة **4 مكتملة / 59 جزئية / 8 مفتوحة**. هذه دفعة استعادة محلية واختبارات أمان وتراجع للمسارات المتأثرة، لا اختبار اختراق مستقل شامل أو اعتماد تجاري 10/10. لم يجر اختبار iPhone فعلي أو إرسال إلى العملاء أو دفع التغييرات أو نشرها على الإنتاج.
