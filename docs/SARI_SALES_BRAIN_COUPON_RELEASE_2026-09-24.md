# تحرير استخدام الكوبون بعد إلغاء طلب محلي قبل التحصيل

التاريخ: 24 سبتمبر 2026. أساس الدفعة `3c22c58`. امتداد لسجل جلسات الدفع وتسوية Tap المحلية؛ النطاق هنا إعادة استخدام واحد من رصيد الكوبون بعد تحقق محلي ومراجعة موظف. لم ينفذ نشر أو اتصال بمزوّد أو إشعار عملاء أو استرداد أموال.

**الخطة مستمرة: 4 مكتملة، 55 جزئية، 12 غير مغلقة.** هذه الدفعة تطور B034 وB037 وB057 وB064 وB065، ولا تمنح تقييم 10/10. [الخطة](./SARI_SALES_BRAIN_10_OF_10_PLAN_2026-09-23.md)، [مصفوفة القبول](./audits/sales-brain-implementation-2026-09-23/acceptance-matrix.md)، [الأدلة](./audits/sales-brain-implementation-2026-09-23/evidence.json).

## السياسة المنفذة

التحرير عملية صريحة تتطلب `orders.manage` وسببًا من 10 إلى 500 حرف ومراجعة للدليل الحالي. لا يحدث تلقائيًا بمجرد الإلغاء أو الاسترداد، ولا يطلب خصمًا أو استردادًا لدى Tap.

- الطلب محلي، فاتورته معتمدة، حالته ملغاة وغير مدفوعة، وقيم الخصم والمجموع والكود تطابق سجل الاستهلاك الأصلي بالهللة.
- الاستخدام صدر تحت نسخة السياسة المحمية `release_policy_version=1` التي تسجلها نسخة الكود الجديدة عند الاستهلاك. الترحيل يُبقي الاستخدامات السابقة عند صفر؛ غياب سجل دفع قديم لا يثبت عدم وجود عملية خارجية فقد التطبيق ردها.
- تفحص جميع روابط الدفع والمحاولات والمدفوعات المرتبطة بالطلب. إما لم تبدأ محاولة دفع، أو لكل محاولة دفع محلي مطابق انتهى بحالة نهائية موثقة من الحالات المسموح بها.
- لا أثر تحصيل في حالة الطلب أو المدفوعات أو توقيتاتها أو عدادات الرابط. التحصيل الذي استُرد لاحقًا يظل خارج هذه السياسة.
- الكوبون الأصلي موجود بنفس المعرف والنشاط والكود؛ لا تعديل لكوبون بديل أعيد إنشاؤه بالاسم نفسه. انقضاء صلاحية الكوبون أو تعطيله لا يمنع تصحيح استخدام مثبت، لكن التحرير لا يمدد صلاحيته ولا يعيد تفعيله.
- العداد صحيح وموجب ويغطي جميع الاستهلاكات المحلية التي لم تحرر. لا يُستعمل `GREATEST` لإخفاء نقص العداد، ولا تصفّر استخدامات قديمة أو خارجية لا يملك هذا السجل تفسيرًا لها.

## التسلسل الذري والتزامن

1. يقفل الخادم الطلب ثم سجل الاستهلاك والتحرير وروابطه ومحاولاته ومدفوعاته، ثم صف الكوبون. هذا يتسلسل مع إنشاء جلسة الدفع وتسويتها واعتماد الفاتورة، دون الاتصال بالشبكة أثناء الأقفال.
2. تحت قفل الكوبون، يقرأ عدد الاستهلاكات غير المحررة بقراءة `READ COMMITTED` دون قفل طلبات أخرى بترتيب معاكس. بذلك لا يضيع اعتماد أو تحرير متزامن لطلب آخر يشترك في الكوبون.
3. يقارن بصمة الدليل المعروض مع البيانات بعد الأقفال. تغير الطلب أو العداد أو نتيجة دفع أو مراجعة يتطلب تحديث الدليل.
4. يخفض `usedCount` بمقدار واحد وبشرط مطابقته القيمة المقروءة. يعطل روابط الدفع الحالية للطلب، ويضع `checkout_discount_released=1` ويمسح رابط الدفع المعروض من الطلب.
5. يسجل المراجع والسبب والوقت ومعرف الاستهلاك والكوبون والعداد قبل وبعد وبصمة الدليل، بقيد فريد لكل طلب ولكل استهلاك. كل ذلك في معاملة واحدة؛ فشل أي كتابة يتراجع عن جميعها.
6. إعادة الاستدعاء أو فقد تأكيد commit لا يخفضان العداد ثانية. الاتصال الذي فُقد تأكيد اعتماده يُغلق بدل إعادته إلى التجمع بحالة مجهولة.

تبقى الفاتورة بالقيمة المتفق عليها وسجل الاستهلاك الأصلي كما هما. الحاجز الدائم يفحصه اعتماد الفاتورة وإصدار رابطها وفتح جلسة Tap؛ إعادة حالة الطلب إلى pending من كاتب قديم لا تعيد له أهلية الدفع. أي شراء جديد يحتاج اتفاقًا وطلبًا جديدين واختبار أهلية الكوبون الحالي.

## قرارات الحالات غير الآمنة

| الدليل | النتيجة |
|---|---|
| طلب جديد محمي وملغى قبل بدء أي دفع | تحرير استخدام واحد بعد مراجعة صريحة |
| جميع المحاولات انتهت إلى FAILED/DECLINED/RESTRICTED أو CANCELLED/ABANDONED/VOID موثقة ومتطابقة | يسمح بالتحرير إذا نجحت بقية الشروط |
| dispatching أو unknown أو INITIATED أو AUTHORIZED | محجوب؛ ربما ما زالت العملية قابلة للتحصيل |
| UNKNOWN أو TIMEDOUT أو انتهاء الجلسة وحده | محجوب؛ لا استنتاج للفشل من الزمن |
| CAPTURED أو REFUNDED أو توقيت/عداد تحصيل سابق | محجوب؛ سياسة تحرير المبيعات المحصلة أو المستردة لم تُنفذ |
| دفع بلا محاولة محفوظة أو محاولة بلا دفع مطابق | محجوب حتى تسوية موثقة؛ لا تخمين |
| استخدام سابق بإصدار صفر | محجوب؛ لا رفع ثقة التاريخ القديم تلقائيًا |
| كوبون محذوف أو منتقل لنشاط آخر أو استبدل بمعرف جديد | محجوب؛ لا خصم من عداد كود آخر |
| عداد أقل من الاستهلاكات المحلية المثبتة | محجوب للمراجعة دون تعديل |
| تحرير سابق موثق | نتيجة idempotent دون تخفيض جديد |

## الواجهة والصلاحيات

داخل تفاصيل الطلب المحلي الملغى يظهر سجل تحرير الاستخدام عند وجود خصم. تعرض الواجهة الكود وسبب الحجب، أو السبب والمراجعة والزر عند الأهلية، أو سجل التحرير وتغير العداد بعد الحفظ. يتغير وصف تفصيل الخصم إلى وصف تاريخي بدل الادعاء أن الاستخدام ما زال مستهلكًا بعد تحريره.

تغيير السبب أو الدليل يلغي التأكيد، ويمنع الحفظ أثناء التنفيذ. فشل الحفظ يتطلب تحديث السجل والمراجعة من جديد. النصوص عربية وإنجليزية، السبب الطويل يلتف، والواجهة قابلة للتشغيل بلوحة المفاتيح وتعرض السبب كنص آمن. لا يقبل المسار هوية تاجر أو مراجع أو كوبون أو عداد أو نسخة سياسة من المتصفح.

## أدلة التحقق والنشر

الفحص على نسخة مستقلة من الفهرس، تستبعد تعديلات أخرى جارية في مساحة العمل. لا أسرار إنتاج في الاختبارات، والشبكة الخارجية محظورة في مشغلها:

- **4,112 حالة فريدة ناجحة، دون فشل أو تخطٍّ**؛ مجموع نتائج المجموعات **5,043** يتضمن حالات مكررة بينها.
- Unit: 672، MySQL: 756، Regression: 972، Legacy sales: 229، Budget: 11، Security: 2,403.
- **60 اختبار تحرير على MySQL** يبدأ من عرض حقيقي وموافقة واعتماد واستهلاك الكوبون؛ يغطي التحرير والتزامن مع طلبات أخرى والدفع، وتغير الدليل والعداد والملكية، وغياب التتبع القديم، والحالات الغامضة والتحصيل والاسترداد، وفشل كل كتابة وفقد تأكيد commit.
- **16 حالة إضافية لصلاحيات المسار الحقيقي** تشمل العضوية والهوية المستمدة من الجلسة والمدخلات المالية المحقونة والأخطاء المنقحة. فحوص الأمان محلية سلوكية وتعاقدية؛ ليست شهادة اختبار اختراق إنتاجي مستقل.
- TypeScript والبناء وDrizzle check نجحت. الترجمة: **6,104 استدعاء و224 مفتاحًا ديناميكيًا** دون مفقود أو أخطاء interpolation أو تعبيرات غير محسومة.
- **223 حالة واجهة و28 صورة** للمكونات الفعلية في Chromium مع API مصطنع، بالعربية والإنجليزية بعروض 320 و375 و390 و768 و1440. لا أخطاء JavaScript؛ لا تمرير أفقي أو مفاتيح ترجمة خام في الحالات المفحوصة. تشمل تغير الدليل والسبب والرفض والحجب وفشل الحفظ وXSS. راجعت [صورة الهاتف](./audits/sales-brain-implementation-2026-09-23/ui/coupon-release-375.png). لم يعتمد Safari أو iPhone فعلي.
- **226 ملف مصدر** موثق ببصمات SHA-256 وGit blob ومطابق للفهرس والنسخة المختبرة قبل الكوميت. بقية ملفات مساحة العمل لا تدخل هذا الاعتماد.

الترحيل `0080_checkout_discount_releases` مطبق على قاعدتي MySQL محليتين، وطابقت بصمة SQL مع سجل كل قاعدة والقيم الافتراضية صفر والقيدين الفريدين. بصمة SQL المطبق بنهايات LF: `d7acb3b95bbe61938b78bf848d68f30f2cfbeaca7265ea59f41ffeee6e043676`. طابقت نسخة SQL المستقلة بعد توحيد نهايات الأسطر؛ Git يطبق CRLF على SQL في نسخة Windows، وهوية Git المفلترة نفسها. لم تعدل سجلات ترحيل سابقة أو أعداد استخدام تاريخية.

قبل تشغيل الميزة بالإنتاج يلزم تطبيق الترحيلات حتى 0080 وتحديث الويب والعمال وإيقاف النسخ القديمة التي لا تسجل المحاولات أو الحاجز الجديد. لا تنفذ backfill يرفع الاستخدامات السابقة من صفر إلى 1 اعتمادًا على غياب المدفوعات فقط. سعر الفاتورة وسقف المنصة اليومي 100 دولار واختيار المزوّد المركزي لم تتغير.

المتبقي: تحرير استخدامات الموصلات الخارجية والحجوزات والروابط العامة، وتسوية التاريخ القديم والاستردادات وفق سياسة مستقلة، وإثبات التكاملات وجودة النموذج في بيئة حية مخصصة. نجاح هذه الدفعة لا يغلق بقية مراحل خطة المبيعات.
