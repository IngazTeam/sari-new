# نتائج إشعارات سلة بحسب القناة والمستلم

استكمال خطة المخ والمبيعات، 28 سبتمبر 2026، فوق `eea07710` على `main`. النطاق هو آثار إشعار الإدارة وإشعار النشاط بعد إنشاء طلب سلة، في B037 وB065 وB070. لا يشمل تعميم سجل الإيصالات على جميع إشعارات المنتج أو إرسال طلبات فعلية إلى العملاء.

## ما أُصلح

كان خيار «القناتين» يعتبر نجاح Push أو البريد وحده نجاحًا للمهمة كاملة. وكان تعطل تحديث سجل محلي بعد قبول المزوّد قد يمحو أثر النجاح من القيمة الراجعة. أصبح عامل سلة يشترط خطة مستلمين محفوظة ونتيجة مستقلة لكل مستلم، ولا يكتفي بالقيمة المنطقية التي ترجعها الدالة.

يُجمَّد اختيار القناة وقائمة أجهزة المتصفح والبريد المتحقق منه قبل أول نقل. تحفظ الخطة هوية النشاط والمهمة والطلب ومحاولة الإنشاء ورمز المحاولة وبصمة السياق، وبصمة المستلم والمحتوى لكل هدف. غياب القناة أو تعطيلها يُسجل بدل اختزال كل الحالات في «فشل». بعد الخطة يفحص المسار التفضيلات والمالك والبريد والجهاز وإعدادات النقل مجددًا، ثم يحفظ علامة بدء الهدف قبل HTTP.

| النتيجة | معناها |
|---|---|
| لم يبدأ نقله | مستلم في الخطة؛ لا توجد له علامة نقل |
| بدأ نقله | توجد علامة نقل؛ لا توجد نتيجة محفوظة بعد |
| قبله المزوّد | استجابة قبول متحققة ومربوطة بالهدف |
| رفضه المزوّد | استجابة رفض ضمن العقد المعروف للمزوّد |
| نتيجة غير مؤكدة | مهلة أو استجابة ناقصة أو متناقضة أو حالة غير محسومة |
| تغير التفويض | رفض الفحص الحالي قبل علامة نقل الهدف |
| معطل | تفضيلات النشاط أو إعداد عام أو ساعات هدوء |
| غير مهيأ | مفاتيح القناة غير متاحة |
| غير متاح | لا مستلم صالح أو جهاز مدعوم؛ أو تجاوز حد قائمة الأجهزة |

نجاح المهمة يتطلب قبول **كل** المستلمين المحددين. قبول بعضهم يبقى قبولًا جزئيًا مع سجل نتائجهم، ولا يصبح نجاحًا كاملًا. لا تتوسع المحاولة القديمة عند إضافة جهاز أو تغيير بريد لاحقًا. تكرار نقطة Push نفسها بمعرفَي اشتراك مختلفين، بما فيه اختلاف الكتابة المكافئ للعنوان، يوقف القناة بدل نقل الإشعار مرتين. تحفظ إشعارات النشاط سجل العرض القائم؛ فشل تحديثه لا يمحو إيصال القبول.

## عقد كل قناة

**SMTP2GO:** يرسل المسار إلى عنوان واحد مرتبط بمالك نشط وبريد متحقق منه. يثبت `fastaccept:false` ويشترط HTTP 200 و`request_id` صالحًا، ونجاح مستلم واحد وصفر فشل وقائمة إخفاقات فارغة ومعرف `email_id` صالحًا، دون حقول خطأ متناقضة. HTTP 200 وحده لا يكفي بحسب [مرجع SMTP2GO](https://developers.smtp2go.com/reference/send-standard-email)، وتوضح [أمثلة الاستجابة الرسمية](https://developers.smtp2go.com/docs/send-an-email) حقول النتيجة. يحفظ السجل بصمة مرجع الطلب والرسالة؛ لا ينسخ العنوان أو الجسم أو المفتاح.

**Web Push:** تستخدم المكتبة المثبتة `web-push 3.6.7` لتشفير الحمولة وتكوين VAPID، ثم ينفذ المسار طلب HTTP واحدًا محدد المهلة دون تحويلات. يعاد فحص مفاتيح الاشتراك ونقطة الوصول قبل النقل. يحتاج القبول HTTP 201 وLocation صالحًا؛ وهو قبول لخدمة Push وليس دليل تسليم للجهاز، وفق [RFC 8030، القسم 5](https://www.rfc-editor.org/rfc/rfc8030.html#section-5). لا تطلب هذه الدفعة إشعار تسليم أو قراءة من المتصفح.

يُسمح بنقاط Google FCM، وApple `web.push.apple.com`، وMozilla ضمن `push.services.mozilla.com`، وWindows ضمن `notify.windows.com` فقط. تُرفض نقاط HTTP والعناوين الخاصة والمنافذ الأخرى وبيانات المستخدم في URL والنطاقات المتشابهة المخادعة. النقاط غير المدعومة تصبح «غير متاح» دون نقل. هذا حصر تطبيقي للأصول المدعومة، وليس اعتمادًا حيًا لكل متصفح أو خدمة.

**إشعار إدارة المنصة:** يحفظ إقرار HTTP ناجحًا من الموصل المضبوط، بما فيه 204 فارغ، دون ادعاء إيصال مستلم أو قراءة. مرجع هذه القناة بصمة الاستجابة؛ لا يوجد عقد موثق من هذا الموصل يثبت وصول الرسالة إلى مستلم بعينه. هذا الحد ظاهر في الواجهة.

الطلبات الخارجية في المسار الجديد تستخدم HTTPS و`redirect:error` ومهلة 20 ثانية وحد استجابة 64KB. لا توجد إعادة محاولة نقل داخل الموصل. قائمة الأهداف محدودة بـ64 إجمالًا، منها 63 جهاز Push كحد أقصى عند وجود البريد؛ تجاوز حد الأجهزة لا يؤدي لإرسال قائمة مبتورة. النقل متسلسل ويتقيد بمهلة العامل، وقد يمنع انتهاء المهلة نقل بقية الأهداف. لا تُحفظ مفاتيح النقل أو عناوين المستلمين في سجل الأدلة.

## الأعطال والاسترداد

نية المستلمين محفوظة قبل الإرسال، وعلامة كل مستلم تُحفظ مع علامة المهمة داخل معاملة واحدة. فقد إقرار العلامة يمنع استدعاء النقل. إذا قبل المزوّد ثم تعذر حفظ النتيجة، يبقى الهدف غير محسوم ولا يعاد تلقائيًا. وإذا حُفظت النتائج ثم فشل تحديث المهمة، يستطيع العامل تسويتها من SQL عندما تكون جميع النتائج قبولًا موثقًا.

الخطة المتجمدة لا تعود إلى طابور المحاولة بمستلمين جدد عند تعطل التحضير أو انتهاء المهلة. يحتفظ العامل برمز المحاولة للمراجعة. الهدف لا يبدأ مرتين، والنتيجة المحفوظة لا تُستبدل؛ إعادة النتيجة المطابقة فقط عملية لا تغير السجل. تحقق القراءة يربط الأعمدة بالسياق والخطة والنتائج والبصمة وعلامة الاكتمال. الدليل المتناقض لا يمنح قبولًا، وقراءة واجهة المراجعة تفشل مغلقة عند عدم اتساقه.

هذه بصمات اتساق تطبيقي وليست توقيعات مستقلة من المزوّد. لا تمنع مسؤول قاعدة بيانات قادرًا على تعديل المحتوى والبصمات معًا. المراجع محفوظة كبصمات، لا كمعرفات خام قابلة للبحث في API المزوّد؛ لا تنفذ هذه الدفعة استعلام مزوّد لإثبات وصول لاحق أو لتسوية استجابة لم تُحفظ.

## الواجهة والترجمة

تعرض صفحة `/merchant/salla` القبول الكامل أو الجزئي ونتيجة كل مستلم بحسب القناة، دون كشف البريد أو نقطة Push أو بيانات العميل. قائمة المستلمين قابلة للتمرير بلوحة المفاتيح وعلى الهاتف. تُسجل هذه التفاصيل في لقطة الفحص التاريخية؛ لا تتغير لقطة قديمة بتغير النتيجة لاحقًا. لقطات v1 السابقة تظل قابلة للقراءة لأن ملخص الإشعار اختياري.

أضيفت النصوص العربية والإنجليزية إلى كتالوج المكوّن القائم. اختبار الإنجليزية يستخدم كتالوجها في بيئة الاختبار، ولا يغيّر اللغات المعلنة في التطبيق. السجلات السابقة التي لا تملك خطة أو إيصالًا لا تُعرض باعتبارها موثقة بالعقد الجديد. الفحص لا يرسل ولا يعتمد نتيجة يدويًا.

[أسماء الحالات وبصمات المصدر ونتائج البوابات](./audits/sales-brain-implementation-2026-09-23/salla-notice-receipts-verification.json)، و[أدلة المتصفح](./audits/sales-brain-implementation-2026-09-23/salla-notice-receipts-ui/results.json). اختُبرت قاعدة eea07710 مع هذه الملفات، وتحققت مطابقة ملفات الدفعة للبصمات قبل الكوميت.

تضم الاختبارات: القبول الجزئي وقائمة عدة أجهزة، وتغير البريد والمالك والتفضيلات والاشتراك، والتعطيل وساعات الهدوء، والتشفير الحقيقي لمكتبة Push مع HTTP محاكاة، وردود SMTP المتناقضة والمهل والحدود، ومنع النقاط الخادعة أو المحلية. تضم MySQL تجميد الخطة قبل النقل، وانتهاء المهلة، وتكرار البداية والنتيجة، وفقد commit قبل الحفظ وبعده، وفشل تحديث المهمة، والتلاعب بسبعة حقول تربط الدليل بهويته، وتراجع معاملة الخطة وفقد المخطط.

الترحيل مختبر على قاعدة جديدة وترقية 0142، مع حفظ عشرة جداول، وإعادة DDL غير المسجل والمهاجرات، والتفرد والقيود وبقاء التاريخ بعد حذف المصدر. المتصفح يختبر المكوّن الفعلي مع API محاكاة، بالعربية والإنجليزية وعروض 320 و375 و390 و430 و768 و1440، وحفظ نتائج المستلمين في سجل الفحص ورفض قبول كامل مزيف. لا يمثل ذلك اختبار Safari أو iPhone فعليًا.
