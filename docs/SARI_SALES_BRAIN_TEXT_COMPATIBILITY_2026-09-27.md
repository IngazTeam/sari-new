# منع تكرار الرد النصي في مسار المجموعات والاتصال القديم

استكمال بعد `252b250a` على `main`. حالة الخطة **4 مكتملة / 59 جزئية / 8 مفتوحة**؛ هذا الإصلاح يغلق ثغرة تكرار محددة ضمن B059 وB064، ولا يعتمد التغطية البيعية أو تشغيل المزوّد الفعلي.

## المشكلة التي أُصلحت

كان `trySendDashboardStaff` يعيد `null` للمجموعات وللحسابات دون صف مسجل في `whatsapp_instances`. عندها كان كل من مساري `conversations.sendReply` في `routers.ts` و`routers-conversations.ts` ينفذ النقل القديم مباشرة. لم يكن UUID المحاولة محفوظًا لهذا الفرع، ولذلك قد تعيد الطلبات المتزامنة أو إعادة الطلب بعد فقد الاستجابة إرسال النص نفسه.

أصبح كل رد نصي يحجز هويته في `ai_sales_staff_replies` قبل أي نقل. تستعمل المجموعات والاتصالات القديمة عقدًا مستقلاً `staff-text-compatibility.v1` في حقول الأساس الموجودة، مع `instance_id=0` وموعد استعادة فارغ. لا يضيف الإصلاح جدولًا أو ترحيلًا؛ تبقى آخر هجرة 0132.

## السلوك والضمانات

- تُراجع صلاحية الموظف الحالية من SQL قبل الحجز أو قراءة نتيجة قديمة. يرتبط UUID بالتاجر والموظف والمحادثة والنص والوجهة المحفوظة، ولا يستطيع موظف آخر إعادة استعماله حتى إن كان مخولًا بالرد.
- تفرد `(merchant_id, request_id)` وقفل التاجر يجعلان استدعاء النقل ملكًا للحجز الجديد وحده. الطلب المتزامن أو المعاد يقرأ النتيجة أو يرجع `pending`، ولا يعيد النقل. يمكن لتاجرين استخدام UUID نفسه دون خلط السجلات.
- تحفظ نتيجة نجاح المرسل القديم وبصمتها في معاملة لاحقة. إذا حُفظت النتيجة وفُقد إقرار الحفظ، تقرأ المحاولة التالية النتيجة دون إرسال جديد. فشل حفظ النتيجة قبل الالتزام يبقي المحاولة معلقة.
- إذا فُقد إقرار حجز المحاولة، أو فشل النقل، أو رجعت نتيجة غير صالحة، فلا تسمح إعادة الطلب بإرسال ثانٍ. قد يبقى حجز لم يُرسل فعليًا في حالة معلقة؛ الغموض ليس إذنًا لإعادة أثر خارجي.
- يبقى هذا المنع بعد إعادة إنشاء اتصال MySQL أو تغيير رقم المحادثة أو حذفها أو تسجيل حساب واتساب لاحقًا. التاريخ المحفوظ لا يُنقل إلى الوجهة الجديدة.
- ينفذ مسارا API فرع التوافق داخل callback يملكه الحجز، ويفحصان تطابق الوجهة الحالية مع المحفوظة قبل النقل. لا يستدعي المسار هذا callback عند نجاح مخزن أو نتيجة معلقة.
- لا تعود `persisted: true` لمجرد أن `createMessage` انتهت دون استثناء؛ تحتاج رجوع الرسالة المحفوظة. أخطاء النقل والتخزين لا تكشف التفاصيل الداخلية للعميل.
- يبقى حساب فردي مسجل لكنه غير نشط أو غير مختار غير مؤهل للرجوع إلى الاتصال القديم.

## الفصل عن أدلة المبيعات

نتيجة التوافق تحفظ رد المرسل القديم فقط. لا تثبت إيصال المزوّد أو التسليم أو القراءة أو التأليف البشري. لا يكتب الفرع في `ai_sales_staff_acceptances` ولا يظهر كقبول موثق في تقرير التجربة. يرفض قارئ الأساس الموثق هذا العقد، ولا يحوله عامل الاستعادة إلى قبول أو يرسل منه.

تحمي البصمات من عدم اتساق السجل المحفوظ؛ ليست توقيعًا يحمي من إعادة كتابة مسؤول قاعدة البيانات لكامل التاريخ المتسق.

## التحقق

نجحت **2,248 حالة دون فشل أو تخطٍ**: 1,353 للعقود والصلاحيات والأمان و895 على MySQL. تتضمن 24 اختبار عقد جديدًا و28 اختبار MySQL جديدًا و20 حالة إضافية لمساري API، مع إعادة اختبارات الرد المسجل والصوت والتصعيد والدفع والتجارب المتأثرة.

نجحت **327 رحلة متصفح**: 113 لتقرير التجربة و48 لأدلة الطلبات و118 للرد النصي والمسودات و48 للصوت. تشمل العربية والإنجليزية والجوال ولوحة المفاتيح واحتفاظ المحاولة عند الغموض. الواجهة لم تتغير في هذه الدفعة، وواجهات API في اختبارات المتصفح محاكاة.

نجحت الأنواع والبناء وفحص **7,496 استدعاء ترجمة و248 مفتاحًا ديناميكيًا** دون تعديل مفاتيح الترجمة، و9 اختبارات لحارس النشر وسجل الترحيلات وقاعدة جديدة حتى 133 ترحيلًا وترقية 0131→0132. ثبتت بصمات **1,968 ملف مصدر** قبل التحقق وبعده وعند حفظ الأدلة.

## التراجع والمتبقي

لا يوجد تغيير في مخطط SQL أو مدخلات العميل أو مفاتيح الترجمة. أصبحت استجابة فرع التوافق تستخدم `success/status/persisted` مثل الرد المسجل، بدل استجابة `success/messageId` القديمة؛ لا يعيد هذا الفرع معرّف رسالة المزوّد للعميل. تبقى المحاولات الموثقة القديمة قابلة للقراءة. قارئ الإصدار السابق للأساس الموثق يرفض سجل التوافق الجديد بدل إعادة إرساله؛ وتظل سجلات التوافق خارج جدولة الاستعادة. يجب الاحتفاظ بالمحاولات عند التراجع، لا حذفها لتجاوز حالة الغموض.

حد المنع هو UUID نفسه. لا يشمل طلبًا جديدًا بهوية مختلفة أو طلبات سبق أن بدأت عبر الإصدار القديم دون حجز. لا يثبت الإصلاح هوية حساب المزوّد أو صلاحية النقل طوال تنفيذ callback القديم، ولا يقيس تغطية الرسائل اليدوية. تبقى مراجعة المحاولات المعلقة، وتثبيت هوية الحساب والملكية لمسار التوافق، والاحتفاظ، وتجربة مزوّد فعلي ضمن المتبقي.

لم يُجر اتصال بالإنتاج أو إرسال إلى العملاء أو اختبار iPhone فعلي. هذه دفعة إصلاح محلي مع فحوص أمان وتراجع، وليست اختبار اختراق مستقلًا أو اعتمادًا تجاريًا لـ10/10. لم تُدفع التغييرات أو تُنشر.
