# تشخيص نتائج ردود الفريق غير المحسومة

التاريخ: 27 سبتمبر 2026. أساس الدفعة: `011aa74b`. تستكمل [المراجعة الإدارية](./SARI_SALES_BRAIN_TEAM_REVIEW_2026-09-27.md) ضمن [خطة مخ المبيعات](./SARI_SALES_BRAIN_10_OF_10_PLAN_2026-09-23.md).

## المشكلة والإصلاح

كانت قائمة المحاولات تعرض الفشل المحفوظ كحالة تحتاج إلى تحقق، ثم يعيد الفحص إظهار الفشل مؤقتًا. كذلك كانت تسوية ردود المجموعات ترجع حالة انتظار حتى مع وجود رفض محفوظ أو إيقاف بحارس الصلاحية. وفي مسار الحساب المسجل كان الفشل المصحوب بإيصال يصنف فشلًا، وكان يمكن لحالة نجاح تحمل خطأ متعارضًا أن تنشئ قبولًا جديدًا.

أصبح التصنيف موحدًا في تسوية النص والصوت والمجموعات. تفحص قراءة القائمة أساس المحاولة وهوية التاجر والحساب والوجهة والمحتوى والحارس قبل استخدام حالة النقل. تطابق حالة الفشل أو الإيقاف واجهة الموظف والمراجعة الإدارية ونتيجة الفحص وسجل التدقيق.

| الدليل المتاح | ما يعرض للمستخدم | الإجراء |
|---|---|---|
| نية تسجيل صحيحة بلا أساس رفع مكتمل | رفع غير موثق | مراجعة إدارية؛ لا تكرار تلقائي للرفع |
| أساس صحيح بلا سجل نقل أو إيصال قديم | نقل غير موثق | مراجعة القناة قبل أي رسالة بديلة |
| طلب مطابق قيد الإرسال بلا خطأ أو إيصال | نتيجة منتظرة | تحديث أو تحقق لاحق؛ لا إعادة تلقائية |
| فقد إقرار، خطأ نقل غامض، إيصال مع فشل، أو نجاح يحمل خطأ | نتيجة غير مؤكدة | مراجعة واتساب مع المدير قبل إرسال بديل |
| قبول محفوظ مطابق ولم تستكمل تسويته | دليل قابل للتحقق | تسوية SQL باستخدام زر التحقق |
| فشل مطابق بلا إيصال أو علامة غموض | فشل مسجل | مراجعة السبب والقناة؛ لا ادعاء أن الرسالة لم تصل |
| فشل مطابق يحمل رمز الحارس الخاص بهذا المسار | إيقاف قبل الاتصال بالمزوّد | مراجعة الصلاحية والملكية والحساب |
| طلب أو حساب أو اتجاه أو بصمة غير مطابقة | دليل يحتاج إلى مراجعة | مراجعة إدارية دون فرض النجاح |

تستخدم الواجهة رموزًا محددة فقط؛ لا تعيد رسائل الخطأ الخام أو رقم العميل أو رابط التسجيل أو بيانات الحساب. القراءة لا تسوي ولا تغير المحاولة، وتبقى الصفحات محدودة بعشرين عنصرًا. تبقى محاولات التوافق التاريخية بلا دليل نقل محفوظ غير محسومة.

## حدود السلوك والتوافق

- لا إرسال جديد أو رفع أثناء القراءة أو التحقق. حالات الفشل والإيقاف قابلة لفحص SQL لاحقًا لأن دليلًا جديدًا قد يصل؛ لا يؤدي ذلك إلى إعادة تشغيل الطلب.
- لا يتحول الخطأ الغامض إلى رفض مؤكد. تحتفظ التسوية بالقبول الذي سبق توثيقه؛ فشل التسليم اللاحق لا يمحو واقعة قبول المزوّد السابقة.
- تبقى المراجعة الإدارية القديمة ثابتة. تكرار UUID مراجعتها يعيد ملاحظتها الأصلية؛ مراجعة جديدة لاحقة تستطيع تسجيل قبول وصل بعد تلك الملاحظة.
- التشخيص يصف الأدلة المحفوظة وقت القراءة. ليس استطلاعًا حيًا للمزوّد ولا سجلًا جديدًا لتسليم الرسالة أو قراءتها أو أثرها البيعي. الإرشاد التشغيلي لا يغلق قضية تلقائيًا ولا يفوض فرض نتيجة.
- لا ترحيل قاعدة بيانات جديد. يستخدم الإصلاح المخطط القائم حتى `0133`. يجب تحديث صفحة المتصفح بعد نشر الواجهة الجديدة؛ عقود العملاء القديمة الصارمة قد ترفض الحالات أو الحقل الإضافي بدل عرض بيانات غير مفهومة.
- لا تتغير صلاحيات المالك والمدير والموظف أو عزل التجار، ولا سقف المنصة اليومي 100 دولار أو اختيار OpenAI/ZahyPi.

## التحقق

نجحت **3,160 حالة دون فشل أو تخطٍ**: 1,665 للعقود والصلاحيات والأمان و1,495 على MySQL. تضم 81 حالة جديدة (75 على MySQL و6 لعقد بيانات الواجهة)، مع إعادة اختبارات المسارات المتأثرة السابقة.

نجحت **443 رحلة متصفح**، منها 32 رحلة جديدة للتشخيص، و116 إجمالًا لسجلي الموظف والإدارة. تشمل الحالات الثماني باللغتين وأحجام الجوال وسطح المكتب، مع بقاء عدم الإرسال والضوابط السابقة. راجعت لقطة التشخيص بالعربية على عرض 375.

نجحت الأنواع والبناء وفحص **7,591 استدعاء ترجمة و248 مفتاحًا ديناميكيًا** دون مفاتيح مفقودة أو أخطاء متغيرات. نجحت 9 فحوص لحارس النشر وثلاث حالات للترحيلات القائمة حتى 134 ترحيلًا، دون إضافة ترحيل جديد. ثبتت بصمات **2,001 ملف مصدر** قبل التحقق وبعده وعند حفظ الأدلة.

اختبارات الخادم تستخدم MySQL محليًا مصطنعًا مع نقل واتساب ورفع الملفات المحاكيين. تختبر إساءة ربط الطلب والحساب والاتجاه، وتنقية الطلب قبل توثيق قبوله، والغموض والتعارض وفقد الإقرار والرفع غير المؤكد والدليل المتأخر وبقاء التدقيق. لا تعني هذه الاختبارات اختبار اختراق إنتاجي مستقلًا.

رحلات المتصفح تستخدم مكونات المحادثات الفعلية وAPI محاكى بالعربية والإنجليزية، وعروض 320 و375 و430 و1440. لا تعادل اختبار جهاز iPhone أو Safari فعليًا.

إعادة الفحص: `node scripts/testing/verify-sales-experiment-readout.cjs --with-ui --attempt-diagnostics` مع `SARI_TEST_DATABASE_URL` و`SARI_STAFF_MIGRATION_DATABASE_URL` لقاعدتين محليتين مصطنعتين. يعيد التحقق المسارات المتأثرة والأنواع والترجمة والبناء وسجل الترحيلات وحارس النشر، ويحفظ بصمات المصدر قبل الاختبارات وبعدها.

## المتبقي

يظل التحقق الحي من النتيجة لدى المزوّد ومعالجة الحالات التي لم تحفظ دليلًا أصلًا عملًا تشغيليًا؛ لا يمكن استنتاج نتيجتها من الصمت أو اختراع إيصال لها. يمكن للمدير استخدام المراجعة المسجلة، ولا يوجد إجراء لاعتماد نجاح يدويًا.

تنظيف الصوت غير المرتبط يحتاج عقد حذف فعليًا من مخزن الملفات، وسياسة احتفاظ، وتسجيل ملكية الكائن وحالة الرفع قبل التنفيذ، وحماية من سباق الرفع المتأخر. التكامل `server/storage.ts` المتاح يوفر الرفع ورابط التنزيل فقط؛ لا عقد حذف أو جرد أو تحقق من إصدار الكائن. لم نخمن نقطة حذف ولم نحذف تسجيلات. غياب أساس الرفع وحده لا يثبت أن كائنًا مهجورًا موجود أو أن حذفَه آمن.

مصفوفة الخطة تبقى **4 مكتملة / 59 جزئية / 8 مفتوحة**. تبقى أدلة التكامل الحي وقياس التحويل البيعي وبوابة المشروع الشاملة مطلوبة للاعتماد. لم تُدفع هذه التغييرات أو تُنشر على الإنتاج.
