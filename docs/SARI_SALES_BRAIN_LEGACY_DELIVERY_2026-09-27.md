# حفظ قبول النقل للاتصال القديم واستعادته دون تكرار

التاريخ: 27 سبتمبر 2026. أساس الدفعة: `ba1ff4af`. تكمل [سجل ردود الموظف](./SARI_SALES_BRAIN_STAFF_ATTEMPT_REVIEW_2026-09-27.md) ضمن [خطة الإصلاح](./SARI_SALES_BRAIN_10_OF_10_PLAN_2026-09-23.md).

## المشكلة والسلوك الجديد

كان اتصال واتساب القديم يرسل النص أو الصوت، ثم يحفظ رسالة المحادثة والنتيجة معًا. إذا قبل المزوّد الإرسال وفشلت معاملة الحفظ، بقيت المحاولة غير محسومة لعدم وجود دليل نقل دائم. الحماية السابقة من التكرار منعت إرسالها مجددًا، لكنها لم تستطع استعادة نتيجتها.

أصبح المسار: **حجز المحاولة وتثبيت صلاحية الإرسال → إرسال واحد → حفظ إيصال القبول بمعاملة مستقلة → تسوية الرسالة والنتيجة عبر SQL**. يبقى الحجز قبل أي أثر خارجي، ولا يرفع الصوت أو يرسل إلا المنفذ الذي أنشأ الحجز. إعادة الطلب أو زر «تحقق من النتيجة» يقرأ الدليل المحفوظ فقط.

لا جدول أو ترحيل جديد. يحفظ الدليل `staff-legacy-delivery.v1` داخل أساس المحاولة الموجود للنص والصوت. لا يُختلق حساب في `whatsapp_instances`، ولا يستعمل معرف الاتصال القديم مكان معرف حساب مسجل في outbox. يبقى مسار الحساب المسجل ودليله القائم مستقلين.

| موضع الفشل | النتيجة المتوقعة |
|---|---|
| قبل استدعاء المزوّد بعد حفظ الحجز | لا إعادة إرسال تلقائية؛ تبقى المحاولة غير محسومة |
| قبول المزوّد، ثم تراجع معاملة حفظ الإيصال | لا دليل دائم يمكن الاعتماد عليه؛ لا إرسال جديد |
| حفظ الإيصال فعليًا وفقد إقرار المعاملة | يستعيد التحقق النتيجة من SQL دون تكرار النقل |
| فشل إنشاء الرسالة أو حفظ النتيجة | يتراجع الإسقاط والنتيجة معًا، ويبقى إيصال القبول صالحًا لإعادة التحقق |
| فقد إقرار معاملة التسوية بعد نجاحها | يعاد إرجاع النتيجة المحفوظة؛ رسالة واحدة فقط |
| تغيّر العميل أو حُذفت المحادثة بعد الإرسال | قبول محفوظ مع `persisted:false`، دون إسقاط الرسالة على عميل مختلف |
| حذف رسالة بعد اكتمال النتيجة | لا يعيد التحقق إنشاء الرسالة؛ نتيجة الحفظ تصف العملية السابقة |

## سلامة الدليل والصلاحيات

- يرتبط الدليل بنوع الرسالة والتاجر ومعرف المصدر ومعرف الاتصال وبصمة حسابه وأساس المحاولة الأصلي وبصمة طلب النقل الكامل. يشمل طلب الصوت رابط الملف واسمه، ويشمل النص محتواه، مع الوجهة في الحالتين.
- تتطلب القراءة تطابق البصمات والحقول المحفوظة. يعاد بناء الأساس الأصلي بإزالة الدليل وإرجاع النتيجة إلى `null`؛ فلا تصبح بصمة الأساس الجديدة بديلًا عن هوية الطلب الذي أرسل فعليًا. تبقى صيغة v1 والتاريخ السابق دون دليل قابلين للقراءة وفق قواعدهما السابقة، ولا يجري تشغيلهما من جديد.
- لا يكفي إيصال أو قيمة truthy. يلزم `accepted:true` وحالة مقبولة وإيصال صالح، ولا يسمح بنتيجة `rejected` أو `unknown` أو خطأ مرافق. أصلح ذلك أيضًا حالة قبول متناقضة كان فحص النص القديم يسمح بها.
- يحفظ إقرار النقل حتى إذا سُحبت صلاحية الموظف خلال استدعاء المزوّد؛ فهو يسجل أثرًا وقع بالفعل. أما تسوية المحادثة فتتطلب الصلاحية الحالية وملكية المحاولة وربط المحادثة داخل معاملة التسوية نفسها. استعادة النتيجة لا تجدد ملكية الموظف للمحادثة.
- بعد حفظ الدليل، يرفض فحص الإرسال منح صلاحية نقل أخرى للمحاولة. تدوير مفاتيح الحساب أو حذفه لاحقًا لا يمحو الإقرار المحفوظ، ولا يخول إرسالًا من حساب بديل.
- يظل السجل المعروض مختصرًا: لا يظهر الإيصال الخام أو المفاتيح أو المحتوى أو رابط التسجيل. لا تحفظ مفاتيح واتساب في الدليل؛ تحفظ بصمة الحساب فقط.
- البصمات تكشف عدم الاتساق؛ ليست توقيعًا يحمي من مدير قاعدة بيانات يستطيع إعادة كتابة جميع الحقول والأدلة معًا. لا يوجد ادعاء بتحقيق exactly-once لدى مزوّد خارجي.

## التحقق

نجحت **2,889 حالة دون فشل أو تخطٍ**: 1,597 للعقود والصلاحيات والأمان و1,292 على MySQL. تشمل 64 حالة جديدة لعقد دليل الاتصال القديم و66 حالة MySQL جديدة للنص والصوت، مع إعادة اختبارات المسارات السابقة.

نجحت **365 رحلة متصفح** لسجل المحاولات والمحادثات والرد النصي والصوتي وتقرير التجربة وأدلة الطلبات، بالعربية والإنجليزية وعروض 320 و375 و430 و1440. نجحت الأنواع والبناء وفحص **7,522 استدعاء ترجمة و248 مفتاحًا ديناميكيًا**، و9 اختبارات لحارس النشر وفحص سجل الترحيلات وقاعدة جديدة حتى 133 ترحيلًا وترقية 0131→0132. ثبتت بصمات **1,989 ملف مصدر** قبل البوابة وبعدها وعند حفظ الأدلة.

- [رحلات سجل المحاولات](./audits/sales-brain-implementation-2026-09-23/legacy-delivery/staff-attempt-review-ui/results.json).

اختبارات MySQL تستخدم قاعدة فعلية محلية مصطنعة ومزوّد واتساب وتخزينًا محاكيين. تشمل التنافس بعد إعادة الاتصال، وعطل كل معاملة وفقد إقرارها، وسحب الصلاحية أثناء النقل، والتلاعب بالدليل مع إعادة حساب بصمة الصف، وتغيير الطلب أثناء استدعاء المزوّد، وعزل الموظف والتاجر، وحذف الحساب أو المحادثة وتعارض الرسالة، ومنع النقل والرفع المتكرر. اختبارات المتصفح تختبر المكونات الفعلية مع API محاكى؛ الشبكة الخارجية محظورة.

أظهرت الجولة الأولية ثماني توقعات قديمة كانت تشترط بقاء الاتصال القديم معلّقًا بعد فشل الإسقاط. حدّثت لتشترط الاستعادة الناجحة مع رسالة واحدة واستدعاء نقل واحد، مع بقاء اختبارات غياب الدليل والفشل والرفض غير محسومة. نجحت الجولة المركزة بعد ذلك بـ493 حالة قبل البوابة الأوسع. لم تُخفف شروط منع التكرار أو الصلاحيات.

أمر إعادة الفحص: `node scripts/testing/verify-sales-experiment-readout.cjs --with-ui --legacy-delivery` مع متغيري `SARI_TEST_DATABASE_URL` و`SARI_STAFF_MIGRATION_DATABASE_URL` لقاعدتين مصطنعتين محليتين. أضيفت الاختبارات الجديدة أيضًا إلى مشغّل اختبارات مخ المبيعات.

## النشر والتراجع والمتبقي

يبقى مخطط قاعدة البيانات حتى `0132`. يحتاج الخادم إلى الإصدار الجديد لقراءة حقل الدليل الجديد؛ الإصدار السابق ذو العقود الصارمة سيرفض تلك المحاولات بدل إعادة إرسالها. عند التراجع، احتفظ بقدرة قراءة الدليل وتسويته من هذه الدفعة، ولا تحذف الحقل أو تصفّر النتيجة ولا تعِد الإرسال بمعرف طلب جديد لتجاوز المشكلة. لا تغيير في الواجهة أو مفاتيح ترجمتها أو سقف الذكاء الاصطناعي اليومي 100 دولار أو اختيار المزوّد.

أغلق هذا العمل فجوة **قبول محفوظ مع فشل إسقاط رسالة الاتصال القديم**. لا يستطيع استعادة إيصال لم يحفظ أصلًا، ولا يثبت تسليم الرسالة أو قراءتها أو نجاح البيع. لا يضيف إلى `ai_sales_staff_acceptances` واقعة بيعية مقاسة، ولا يغيّر تدريب المخ أو نتائج التجارب.

يبقى: مسار إداري مدقق لمحاولات موظف غادر العمل أو محادثات متعددة، وسياسة معالجة الدليل المتعارض والرفض والنتائج المجهولة، وتنظيف ملفات الصوت غير المرجعية، والتحقق الحي من المزوّد وقياس الأثر البيعي. لا يتضمن هذا العمل اختبار iPhone/Safari فعليًا أو اختبار اختراق إنتاجي مستقلًا.

مصفوفة الخطة تبقى **4 مكتملة / 59 جزئية / 8 مفتوحة**. الأدلة تخص الإصلاح والمسارات المتأثرة؛ لم تُعد بوابة المشروع الشاملة ولم يُعتمد المنتج تجاريًا بدرجة 10/10. لم تُدفع التغييرات أو تُنشر على الإنتاج.
