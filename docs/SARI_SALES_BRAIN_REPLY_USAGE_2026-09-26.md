# احتساب استخدام الرد المعتمد على الاشتراك

التاريخ: 26 سبتمبر 2026. الأساس: `5992a5fd`، الفرع `main`.

أُنجزت هذه الدفعة بعد مراجعة متطلبات إتاحة قرار الإرسال. كان مسار الرد المعتمد يحمي النقل ويسترجع المحادثة، لكنه لا يحجز سعة الرسائل ولا يسوّي عداد الاشتراك. أُغلق هذا النقص في المسار المعتمد قبل ربط زر الإرسال به.

## التنفيذ

1. يضيف الترحيل `0122_sales_reply_usage` حالة استخدام منفصلة ومرجع الاشتراك والفترة والوحدات ووقت الحجز وبصمته ووقت التسوية. تبدأ السجلات القديمة بحالة `legacy` دون خصم أو احتساب تاريخي مفترض؛ تبدأ التفويضات الجديدة بحالة `pending`.
2. عند آخر فحص قبل الاتصال بمزوّد واتساب، يُحجز استخدام وحدتين وفق قاعدة المسار الحالي: الواردة والصادرة. يُقفل الاشتراك المرتبط بالنشاط، وتُفحص حالته وملكيته وبدايته ونهايته ونهاية التجربة والفترة والعداد وحد الباقة، وتُحتسب الحجوزات المعلقة في الفترة نفسها. لا يتصل هذا العمل بمزوّد الذكاء الاصطناعي.
3. يجري استهلاك تفويض الإرسال وحجز السعة في المعاملة نفسها. يُعاد فحص انتهاء التفويض والاشتراك عند كتابة الحجز، بعد الأقفال والقراءات. فشل الحجز يلغي استهلاك التفويض داخل المعاملة ولا يسمح باستدعاء المزوّد. الباقة غير المحدودة والتجربة بلا باقة تستمران وفق قواعد الاشتراك الحالية.
4. يُربط الحجز ببصمة التاجر والرد والتفويض والاشتراك والفترة والوحدات ووقت بدء النقل. لا يستطيع سجل ناقص أو متناقض أن يتجاوز التسوية ويُسجّل محادثة مكتملة. اشتراك تاجر آخر أو عداد سالب أو حد غير صالح أو تجاوز عددي يمنع العملية.
5. عند وجود إيصال نقل مطابق، ينتقل الاستخدام إلى `charged` مرة واحدة في معاملة حفظ المحادثة. فقد إقرار الالتزام أو إعادة التشغيل أو المنافسة لا يزيد العداد ثانية. القبول ثم فشل الوصول لا يلغي استخدام إرسال وقع بالفعل؛ لا يعني الاحتساب إثبات وصول أو قراءة أو شراء.
6. الرفض المؤكد أو الحجب يحرر الحجز دون زيادة العداد. النتيجة المجهولة تبقي الحجز دون وصفها استخدامًا مؤكدًا، ولا تتيح إعادة الإرسال. الحالة التي تحتاج مراجعة تبقى بحاجة إلى معالجة تشغيلية؛ لم يُضف قرار يدوي لإطلاق الحجوزات الغامضة.
7. يُسوّى الإيصال مع الاشتراك والفترة المحفوظين وقت الإرسال. إذا أُلغي الاشتراك أو استُبدل، يبقى احتسابه على سجله الأصلي. إذا تغيّرت فترة العداد أو حُذف الاشتراك، يُحفظ الاستخدام المؤكد بوصفه `historical` ولا يُحمّل على العداد الجديد. لا تستبدل الخدمة مرجع الاشتراك تلقائيًا.
8. يستخدم عامل استرجاع المحادثة السابق التسوية نفسها. تُفحص مهلة العامل داخل كتابة التسوية نفسها أيضًا عند الرفض أو فشل الوصول، وتُلغى زيادة العداد إذا انتهت المهلة قبل هذه الكتابة. تشترط بوابة التفويض والنقل والاسترجاع اكتمال مخطط الاستخدام قبل العمل. لا تُحتسب السجلات `legacy` آليًا.
9. كشف اختبار قاعدة جديدة أن مفتاح الرد المعتمد ذو معرّفي متجر ورد من رقم واحد أقصر من حد قناة واتساب. أُضيف لاحق ثابت لهذه المفاتيح القصيرة فقط؛ بقي كل مفتاح سابق مقبول كما هو. تغطي الحالة حدود المعرّفات وعدم التصادم.

## المتبقي والحدود

هذه ضمانات لمسار الرد المعتمد وحجوزاته. مسارات الإرسال العادية تستخدم فحوصًا واحتسابًا منفصلين؛ لم تُوحّد جميع مسارات المنصة في حجز ذري مشترك في هذه الدفعة. يلزم إكمال ذلك قبل ادعاء ضمان سقف رسائل شامل لكل المسارات. لا تتغير سياسة سعر الباقة أو سقف الذكاء الاصطناعي البالغ 100 دولار يوميًا للمنصة.

واجهة قرار الإرسال وصلاحيات API العامة، وعرض السعة المحجوزة في واجهة الاشتراك، وواجهة معالجة الحالات الغامضة، وربط التعرض التجريبي والدفع والاسترداد بنتائج البيع والتعلم، والتنسيق الأوسع للردود وآثار الأعمال، ما زالت مفتوحة. كذلك يلزم استكمال سياسة الاحتفاظ بالأدلة وتقييم نموذج حقيقي ومراجعة عمياء وتشغيل ظل ونشر محدود وقياس أثر تجاري. لا يعني نجاح الاختبارات المحلية إثبات تحسن التحويل.
