# صحة العروض واتساق قرار مخ المبيعات

استكمال خطة المخ بعد إصلاحات `9bc8b21`، على أساس Git `9f3de79` الذي يتضمن تحديث السنترال المنفصل. لم يجر نشر أو إرسال إلى عملاء حقيقيين أو تعديل الإنتاج. إعداد OpenAI/ZahyPi من السوبر أدمن وسقف المنصة كلها 100 دولار يومياً كما هما.

## النتيجة

كانت تعليمات البيع تعطي إشارات متعارضة: اعتراض السعر يتحول إلى خصم، وسؤال كيفية الشراء إلى جاهزية إغلاق، والرضا إلى بيع إضافي. وكانت بعض قراءات الخصومات تستخدم أسماء أعمدة غير صحيحة أو تسمح بعرض كود مخصص لعميل آخر. أصبحت سلطة القرار الحالي للعميل أعلى من هذه الإشارات، وأصبحت العروض تمر بتحقق مشترك قبل إدراجها في السياق أو إرسالها كإجراء إضافي.

هذه الدفعة تعالج عيوباً فعلية في التنفيذ؛ لا تمنح 10/10 ولا تقيس معدل التحويل. وضع الخطة يبقى **4 بنود مكتملة، 55 جزئية، 12 غير مغلقة**. لم نغلق بنداً مركباً لمجرد إصلاح جزء منه.

## الإصلاح ودليل التحقق

| المشكلة | السلوك بعد الإصلاح | الدليل |
|---|---|---|
| استعمال `discountType/discountValue` بدلاً من `type/value` | نوع الخصم وقيمته من مخطط البيانات الفعلي؛ الثابت والحد الأدنى بالريال، والنسبة مئوية | `sales-offer-evidence.test.ts` و`sales-offer-evidence.mysql.test.ts` |
| كود عميل أو تاجر آخر يصل إلى السياق | تحقق من التاجر والرقم الموحد؛ لا كود خاص لمجموعة أو رقم مفقود/غير صالح | اختبارات القارئ وMySQL للمسارات السريع والكامل والقديم وNBA والإجراء |
| SQL يعيد `customer_phone` بينما المنطق يقرأ `customerPhone` | alias صريح، مع رفض سجل ناقص أي قيد ملكية أو حد استخدام أو حد طلب أو انتهاء | اختبار إسقاطات ناقصة واختبار SQL فعلي |
| عرض قديم يبقى خمس دقائق في المسار السريع | إزالة cache سياق العروض والولاء؛ فحص النشاط والانتهاء UTC وعدد الاستخدامات عند كل قراءة | تغيير `isActive/usedCount/expiresAt` فعلياً ثم إعادة القراءة |
| توليد/عرض كود بناء على قرار النموذج وحده | يلزم طلب خصم من العميل، مع احترام الرفض، ثم دليل صالح له أو سياسة توليد مفعلة؛ يعاد الاستعلام بعد التوليد قبل مشاركة الكود | `sales-persuasion-consistency.test.ts` و`auto-discount-authority.test.ts` واختبار حذف الكود قبل تنفيذ الإجراء |
| حد التاجر الأقل من 5% يرتفع تلقائياً إلى 5% | لا تتجاوز النسبة السقف المعتمد، وترفض الإعدادات غير الصحيحة بدلاً من استبدال صفر بـ15%؛ مدة 1–168 ساعة وفق عقد الإعداد الحالي | 21 حالة لسلطة سياسة الخصم |
| «غالي» يستدعي خصماً أو سلة قديمة أو شهادة اجتماعية | معالجة السبب والقيمة أو المقارنة أولاً؛ الخصم ليس الرد الافتراضي، ولا تعويض لمجرد الغضب | اختبارات اتساق الإقناع والاستراتيجي وNBA |
| «كيف أطلب/أدفع؟» و«نعم» لعرض تفاصيل يصبحان موافقة شراء | شرح الخطوات وربط الإجابة بالسؤال السابق؛ لا ترقية النية القديمة أو الشعور الإيجابي إلى موافقة تنفيذ | حالات عربية وإنجليزية عبر كشف النية والهدف وNBA والإغلاق والاستراتيجي |
| كثرة الرسائل أو تكرار سؤال السعر أو الوقت يدفع إلى الإغلاق والندرة | لا تستعمل هذه الإشارات كدليل موافقة أو ندرة، ولا تفتح upsell بعد اتفاق؛ الإغلاق الصريح يبقى عند طلب شراء فعلي | اختبارات الإغلاق الجديدة وحالات الشراء الصريح السابقة |
| توصية مكمل من أول الكتالوج أو بناء على الرضا فقط | مرشح متاح من فئة معروفة ولم يشتره العميل، عند سؤال مناسب؛ تطابق الفئة وحده لا يثبت التوافق | حالات محرك المبيعات التكيفي؛ سياسة المشاعر لا تفرض إضافة |
| وعود بحجز المخزون أو اتصال موظف دون تنفيذ | تراجع الخطوة المناسبة والدليل الفعلي؛ رسالة رابط سابقة لا تثبت استمرار صلاحيته أو عدم الدفع | اختبارات القرار وعقود الانحدار |
| تكرار لا نهائي في بحث WooCommerce القديم | فصل اسم الدالة المحلية عن اسم عميل الكتالوج المستورد | تشغيل مولد الرد القديم بقاعدة فعلية وLLM محاكى، مع تأكيد غياب أخطاء التنفيذ |
| مدقق الترجمة يعد النص الثنائي المحلي مفتاح i18next | إعادة تسمية مساعد النصوص إلى `localizedText` في ملفي السنترال؛ لا تغيير للنص أو تعطيل لفحص المفاتيح | فحص الترجمة و14 اختباراً موجوداً لتفاعلات السنترال ومساراته |

تبقى أسماء بعض الاستراتيجيات القديمة في عقود TypeScript والسجلات للتوافق؛ لا تعني أسماؤها إتاحة الضغط أو تنفيذ خصم دون تحقق.

## الاختبارات والنسخة المختبرة

الأعداد النهائية وبصمات المصادر في [ملف الأدلة](./audits/sales-brain-implementation-2026-09-23/evidence.json)، وتفاصيل البنود في [مصفوفة القبول](./audits/sales-brain-implementation-2026-09-23/acceptance-matrix.md).

نجح فحص TypeScript والبناء وتاريخ Drizzle. فحص الترجمة راجع 5924 استدعاءً و213 مفتاحاً ديناميكياً دون مفتاح ناقص أو خطأ interpolation أو استدعاء ديناميكي غير محسوم. تحفظ الأدلة بصمات 171 ملف مصدر، مع مطابقة Git blobs للنسخة المجهزة للكوميت.

أضيفت 101 حالة وحدة و12 حالة MySQL في أربعة ملفات جديدة، مع تحديث الحالات القائمة التي كانت تتوقع السلوك الخاطئ. اختبارات المزوّد في هذه الدفعة تستخدم محاكاة، واختبارات MySQL تشغل القارئ والسياق والإجراء الفعليين على القاعدة المحلية.

جرى الاختبار على نسخة مستقلة من الملفات المجهزة في Git، مع MySQL محلي ببيانات صناعية ومزوّدات محاكاة وشبكة خارجية محظورة. أُعيدت الحزم المتأثرة عند تصحيح توقعات قديمة، واستُكملت الميزانية والأمان بعد نجاحها. لا توجد اختبارات معطلة أو متجاوزة في أدلة القبول النهائية.

لم تُخفَّ حالات الفشل الأولى: بعضها كشف التباس مساعد النصوص، وبعضها كان يشترط السلوك الجاري إصلاحه: حد خصم أدنى 5%، واعتبار سؤال طريقة الطلب شراءً، وبيعاً إضافياً لمجرد السعادة. حُدثت هذه التوقعات لتختبر السياسة الجديدة، مع إبقاء الشراء الصريح واختبارات SQL والملكية وشروط الصلاحية. عُززت بعقد عروض مشترك واختبارات سلوكية فعلية؛ لم يخفض حد قبول اللمس أو يعطل فحص الترجمة أو الأمان.

التحقق من الواجهة يخص مكونات React الفعلية وCSS المبني وAPI مصطنع عبر Chromium. أُعيد تشغيل 69 سيناريو على 320 و375 و390 و768 و1440 بكسلاً؛ لا يمثل Safari أو iPhone فعلياً أو رحلة حساب إنتاج كامل.

لا ترحيل جديد في هذه الدفعة. سجل المخطط المحلي حتى `0070_escalation_reconciliation`؛ لا تطبيق ترحيلات على الإنتاج.

## حدود الضمان وما بقي

- عرض الكود لقطة من وقت القراءة، وليس حجزاً أو استهلاكاً له. التنفيذ النهائي يحتاج إعادة تحقق من السعر والأهلية والشروط وموافقة العميل. لم تُبنَ في هذه الدفعة آلية حجز خصومات ذرية موزعة.
- حد إصدار الكود اليومي ومعدل مشاركته ما زالا في ذاكرة العملية؛ لا يغطيان وحدهما عمالاً متعددين أو إعادة تشغيل. سياسة هامش الربح والتفويض الموحدة ما زالت ضمن B028/B057 المفتوحين.
- لا توجد هنا ضمانة بأن كل نص حر يولده النموذج محصن من ذكر كود قديم؛ الإصلاح يضبط مصدر العروض وتعليمات الصياغة والإجراء الإضافي، مع بقاء بوابة مراجعة الرد الحالية. اختبار المزوّد الحقيقي متعدد الأدوار ما زال مطلوباً.
- أزيل cache لتجنب استمرار الحقيقة القديمة؛ لم يُقَس أثر زيادة القراءات تحت حمل إنتاجي. الاستعلامات الحالية تقرأ أكواد التاجر قبل تصفيتها، ولا ندعي تحسين زمن الاستجابة أو الحمل.
- القواعد اللغوية عالجت الحالات المثبتة، وليست مصنفاً شاملاً لكل لهجة أو صياغة. لا يزال قياس جودة الإقناع والذاكرة والتعلم على GPT وZahyPi الحقيقيين والقياس التجاري المضبوط مطلوبين.
- خارج هذه الدفعة: بقية توحيد أدوات سلة وبيان والحجوزات، ترحيل وسائط التصعيد، تعيين موظف حصري ودفتر انتقالات شامل، خطة الخطوة التالية بمصدر، وتجربة تعلم بإصدار وتراجع وأثر تجاري. لا تعني نجاحات الاختبارات إغلاق هذه البنود.

الاختبار الأمني المرفق سلوكي محلي وعقود مصدر، وليس اختبار اختراق مستقلاً لحساب إنتاج مسجل الدخول.
