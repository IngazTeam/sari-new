# صلاحية إصدار الخصومات ومراجعتها

استكمال خطة مخ المبيعات بعد `0625753`، بتاريخ 23 سبتمبر 2026. التنفيذ والترحيل والتحقق محلي فقط؛ لم يحصل نشر أو إرسال لعملاء حقيقيين. اختيار OpenAI/ZahyPi وسقف المنصة 100 دولار يوميًا لم يتغيرا.

## النتيجة

أصبحت صلاحية إصدار الخصومات إعدادًا مستقلًا في صفحتي «مخ ساري» و«إعدادات البوت». يراجع صاحب الصلاحية التفعيل وسقف النسبة ومدة الكود ثم يعتمدها. يسجل النظام من غيّر السياسة والقيم قبل التغيير وبعده، ويحفظ السياسة التي سمحت بإصدار كل كود جديد.

## العيوب التي عولجت

| العيب | الإصلاح |
|---|---|
| الواجهة ترفع السقف إلى 5% رغم أن المحرك يحترم سقفًا أقل | نسبة صحيحة بين 1 و50 في العقد المشترك والواجهة والمحرك؛ اختبار فعلي لحفظ 1% وإصدار 3% |
| API يقبل كسورًا في النسبة والساعات بينما المحرك يرفضها | عقد واحد لأعداد صحيحة، ومدة من 1 إلى 168 ساعة؛ رفض القيم غير الصالحة على الخادم والمتصفح |
| حفظ البوت العام قد يعيد كتابة صلاحية الخصم من نموذج قديم | فصل حالة الخصم وحفظه؛ رفض حقوله في مسار التحديث القديم وفي `updateBotSettings` نفسه |
| نافذتان تستطيعان تغيير تفويض مالي دون كشف التعارض | إصدار متزايد وبصمة تشمل التاجر ومعرف صف الإعدادات والقيم المحفوظة، وفحص تحت قفل SQL |
| لا سجل واضح لمن فوّض الخصم أو غيّر حدوده | سجل دائم قبل/بعد مع هوية المستخدم من الجلسة ووقت UTC وبصمة السياسة السابقة؛ الواجهة تعرض آخر 10 تغييرات |
| كود صادر لا يحمل مرجعًا للسياسة وقت إصداره | حفظ معرف صف الإعدادات والإصدار والسياسة في `issuance_authorization` داخل معاملة إصدار الكود نفسها |
| إنشاء إعدادات افتراضية متزامنة قد يكرر صف السلطة | تهيئة متسلسلة مع تعديلات السياسة، وإعادة فحص الوجود قبل الإدراج؛ الصفوف القديمة المتكررة لا تُدمج بالتخمين |
| وصف الواجهة يعد بخصم تلقائي لمجرد «غالي» | توضيح أن الإصدار يتطلب طلب خصم صريحًا، وأن الاعتراض وحده لا يمنح خصمًا |
| استيراد ناقص لأيقونة في مخ ساري يختبئ خلف تعطيل الأنواع | استيراد `AlertCircle` وإزالة `@ts-nocheck` من الصفحة؛ فحص الأنواع يمر |
| التعليمات المخصصة تُرسل من الواجهة ثم تُحذف ضمنيًا من مدخل API | قبول صريح محدود إلى 10,000 محرف أو null، مع اختبار حفظها مستقلًا عن الخصومات |

## ضمانات التنفيذ

- **الصلاحيات:** القراءة ضمن عضوية التاجر. الكتابة تحتاج `bot_settings.manage`؛ صلاحية مشرف المبيعات وحدها لا تكفي. لا يقبل المدخل هوية تاجر أو مستخدم يختارها المتصفح. التفاصيل الداخلية لأخطاء التخزين لا تُكشف.
- **المراجعة:** `reviewed: true` مع قيم صحيحة وإصدار وبصمة حاليين. تغيير أي حقل يلغي علامة المراجعة. تغيّر السياسة أثناء فتح الصفحة يمنع الحفظ؛ تبقى المسودة إلى أن يختار المستخدم تحميل القيم الحالية.
- **الذرية:** تعديل الإعدادات وزيادة الإصدار وإضافة التدقيق داخل معاملة واحدة. فشل سجل التدقيق يعيد تعديل السياسة أيضًا. إعادة الطلب القديم لا تعيد التفويض، والتغيير المتزامن ينجح لإصدار واحد فقط. الطلب المطابق للقيم الحالية لا يخترع تغييرًا جديدًا.
- **الأقفال:** محرر السياسة يقفل التاجر قبل الإعدادات؛ قارئ الإصدار يأخذ قفلًا مشتركًا على التاجر قبل الإعدادات لتجنب عكس ترتيب أقفال السلطة. لا اتصال بمزوّد داخل معاملة السياسة.
- **مصدر التفويض:** تبقى حقول `bot_settings` الحالية المصدر المستخدم فعلًا في محرك الإصدار. لا جدول سياسة موازٍ منفصل عن المحرك، ولا توسيع صامت للسقف الحالي، ولا إسناد موافقة بشرية لتاريخ قديم مجهول.
- **الإصدار:** يبقى طلب العميل الصريح وملكية المحادثة ومصدر الرسالة وأحدث سياق والتولي وحد الإصدار الدائم شروطًا سابقة. يحفظ الكود ومحاولة الإصدار وتوثيق السلطة معًا. الاختبارات تثبت أن تعطيل السياسة يمنع إصدارًا جديدًا.
- **الإعدادات المتكررة أو الفاسدة:** تُرفض قراءة السياسة وتعديلها وإصدار الخصم بدل اختيار صف عشوائي أو اختراع قيمة بديلة. تحفظ قيم null التاريخية للسقف والمدة دلالتها السابقة 15% و48 ساعة؛ لا تفعّل الخصومات تلقائيًا.
- **الواجهة:** AR/EN، حالات تحميل وفشل وقراءة فقط، لا قفز للرقم عند مسح الحقل، أهداف لمس 44 بكسل، حفظ بلوحة المفاتيح. أزرارها من نوع `button` حتى لا ترسل نموذج إعدادات البوت الأب.

## حدود السياسة الحالية

هذه **صلاحية إصدار كود** وليست اعتمادًا نهائيًا لخصم على فاتورة أو بوابة دفع. التعديل يسري على الأكواد الجديدة. تعطيل الإصدار أو خفض السقف لا يلغي الأكواد السابقة أو يعيد كتابة شروطها؛ تظل صلاحية تلك الأكواد وتوافرها محل فحص عند مشاركتها.

لا يوجد في هذه الدفعة ضمان لهامش الربح: الكود عام لسلة مستقبلية، وتكلفة بعض المنتجات أو خياراتها قد تكون غير موثقة. يتطلب إغلاق هذا الجزء سلة محددة وتكلفة وعملة وضرائب وتوصيل موثقة، وحساب هامش بعد الخصم، وربط الاستعمال بتلك السلة، ومسار تفويض صفقة بعينها عند تجاوز الحدود. لا يعتمد النموذج هذه الصلاحية بناءً على ثقته أو نص العميل.

## الترحيل والنشر

أضيف الترحيل `0074_sales_discount_policy.sql` وطُبق على قاعدتي MySQL محليتين للاختبار. يضيف إصدار السياسة وسجل تغييراتها ولقطة تفويض الإصدار. لا يغير نسب الخصم القديمة أو تفعيلها ولا يحذف الأكواد أو المحاولات.

عند النشر يلزم تطبيق الترحيل وتحديث الويب والعمال معًا. العملاء الذين ما زالوا يرسلون حقول الخصم عبر API القديم يتلقون رفضًا صريحًا ويحتاجون تحديث الصفحة. الحالات القديمة ذات صفوف إعدادات مكررة أو قيم فاسدة تحتاج معالجة إدارية موثقة؛ لا يصح تصحيحها آليًا بالتخمين. لم ينفذ نشر أو ترحيل إنتاجي في هذه الدفعة.
