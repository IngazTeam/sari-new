# إشعار العميل بنتيجة نقل الحجز عبر واتساب

24 سبتمبر 2026، بعد **f7672c66**. التنفيذ محلي بقاعدة MySQL مصطنعة ومزوّد واتساب مصطنع. لم تُرسل رسالة حقيقية ولم يُنفذ نشر إنتاجي.

## النتيجة

نجاح نقل الحجز ينشئ إشعارًا دائمًا داخل معاملة تحديث الحجز والتقويم والتدقيق نفسها. لا يمكن أن يثبت الإسقاط المحلي مع فقد الإشعار بسبب فشل INSERT. موافقة العميل وحدها، أو النقل غير المحسوم، أو إغلاق الطلب قبل التنفيذ، لا تولّد رسالة نجاح.

نص الإشعار عربي ثابت من بيانات الاتفاق المحفوظة، يشمل رقم الحجز والموعد الجديد والسابق وتوقيت الرياض. لا يعتمد على جواب AI ولا يتضمن ادعاء دفع أو خصم أو قدرة على البيع. لا يرسل إشعارات للحجوزات المنقولة قبل هذا الترحيل، ولا يخمن حسابًا بديلًا.

## دورة الإرسال ودليلها

1. يربط الإشعار رسالة الموافقة بالمحادثة والتاجر ورقم العميل ومهمة دخول واتساب التي أنشأتها. يتحقق من حساب المصدر ومزوّده ورقم الحساب والوجهة الخاصة؛ السجلات القديمة التي لا تثبت هذه العلاقة تُحفظ للمراجعة دون إرسال تلقائي.
2. تُجمّد بيانات النص والاتفاق والقناة في snapshot له بصمة. حساب واتساب الأساسي الحالي لا يستبدل حساب الموافقة الأصلي. لا تُحفظ مفاتيح سرية في snapshot أو نتيجة API.
3. ينتظر الإشعار اكتمال مهمة الرد على الموافقة، حتى لا يسبق رسالة قديمة ما زالت قيد التنفيذ. المهمة الفاشلة أو غير المحسومة لا تسمح بالإرسال. الانتظار محدود بحداثة الموافقة.
4. يحجز العامل محاولة dispatching بمفتاح مطالبة قبل الاتصال بالمزوّد، تحت قفل سعة التاجر. العامل الآخر يرى المحاولة نفسها ولا يرسل نسخة ثانية. لا تُحفظ معاملة SQL مفتوحة خلال اتصال واتساب.
5. يعاد فحص الحجز والاتفاق المقبول وبصمته ووقت الموعد وملكية العميل وأحدث رسالة وحساب القناة وحالة النشاط والتولي البشري. نافذة الإرسال المحلية 24 ساعة من رسالة الموافقة؛ لا تحويل تلقائي إلى قالب Meta بعد انتهائها. سحب الإذن الأحدث من الموافقة يحجب الإرسال.
6. مسار واتساب يعيد فحص هذه الشروط بعد حجز سجل التسليم وتحميل الحساب، وقبل provider.send. يلزم مفتاح مطالبة صحيح ومحاولة حديثة ونص ووجهة وحساب مطابقون. مفاتيح booking_notice بلا هذا التفويض مرفوضة.
7. نتيجة الدالة وحدها ليست دليل قبول. تُقرأ هوية حساب المزوّد وسجل whatsapp_message_deliveries ونص الطلب والوجهة والمفتاح ورقم رسالة المزوّد. إيصال غير مطابق لا يثبت الإرسال.
8. عند القبول الموثق يسجل النص في تاريخ المحادثة مرة واحدة بمفتاح خاص بالإشعار. فشل الحفظ يعالج بقراءة الإيصال وإعادة الإسقاط المحلي، دون إعادة اتصال إرسال. تعارض النص أو انتقال المحادثة لعميل آخر لا يسمح بكتابة تاريخ خاطئ.

## الحالات والحدود

| الحالة | السلوك |
|---|---|
| pending | الإشعار محفوظ؛ ينتظر الأهلية واكتمال رد الموافقة. |
| dispatching | محاولة محفوظة قبل الإرسال؛ لا تكررها مطالبة أخرى. |
| accepted + sent | قبل المزوّد الرسالة؛ لا يثبت وصولها أو قراءتها. |
| accepted + delivered/read | حدّث إيصال واتساب حالة الوصول/القراءة. |
| failed | رفض أو فشل موثق؛ لا إعادة إرسال آلية في هذا المسار. |
| unknown | انقطاع/فقد إيصال/حالة ناقصة؛ قراءة وتسوية فقط، بلا إعادة إرسال. |
| suppressed | تغير السياق أو انتهت نافذة الإرسال؛ يحتاج النشاط مراجعة التواصل. |
| manual_review | تعذر إثبات حساب واتساب الأصلي عند إنشاء الإشعار. |

فقد تأكيد commit لا يبيح الاتصال أو تكراره. محاولة انقطع عاملها دون إيصال تبقى غير محسومة. تُقرأ الحالات المستحقة في دفعات محدودة من 20؛ تتحقق المحاولة المتقادمة بعد دقيقتين، ويعاد فحص الإيصالات كل خمس دقائق بحد سبعة أيام. توقف الفحص التلقائي لا يحول الغموض إلى نجاح. فشل تسليم لاحق لا يمحو حقيقة قبول سابق، ولا يطلق إعادة إرسال.

حماية ترتيب الرسائل والتولي والساعة تعطي أولوية لسياق العميل الحالي؛ أي رسالة جديدة بعد الموافقة تحجب الإشعار التلقائي لهذا الطلب. لا يفترض النظام أن ردًا مثل «شكرًا» إذن لاستئناف إرسال قديم. متابعة التواصل في الحالات المحجوبة أو الغامضة تحتاج مراجعة بشرية؛ هذه الدفعة لا تضيف زر إعادة إرسال أو اعتماد يدوي لإيصال مجهول.

## الواجهة

أضيف قسم داخل مراجعة نقل الحجز يعرض حالة الإشعار منفصلة عن نتيجة نقل الموعد، وحالة التسليم، ووقت القبول، والنص، والحاجة إلى مراجعة سجل المحادثة. تحديث اللوحة قراءة فقط ولا يرسل. النسختان العربية والإنجليزية تعرضان حالات الانتظار والفشل والغموض دون إظهار أسرار أو مفاتيح ترجمة خام. نص الرسالة يُعرض كنص؛ فحص XSS والعرض الضيق ضمن التحقق.

## المخطط والنشر

ترحيل **0095_booking_reschedule_notifications** يضيف سجلًا فريدًا لكل تاجر وطلب نقل، مع فهرس لحالات العامل. ليس له FK إلى الحجز أو المحادثة أو طلب النقل يمحو تاريخ المحاولة؛ ملكية التاجر لها FK. يسمح بإشعارات مستقلة لنقل الحجز نفسه لاحقًا. لا backfill ولا تغيير للحجوزات الموجودة.

طُبق وفُحص على قاعدتي الاختبار المحليتين فقط. بصمة SQL: **bf1546cc03b90845cead6216f899715ed419f1528db985fe1b767055dbaf6609**. [تقرير الترحيل](./audits/sales-brain-implementation-2026-09-23/booking-notice-migration.json).

عامل الإشعارات ضمن دورة تشغيل وإيقاف عامل الرسائل؛ يعمل كذلك عند تشغيل عامل inbound الخارجي. الترحيل متطلب استعداد للتشغيل. عند النشر يجب تنسيق المخطط والويب وعامل الرسائل؛ لا تعاد حالة محاولة غامضة إلى pending، ولا تحذف سجلاتها لتجاوز منع التكرار. لم يُنفذ النشر هنا.
