# سجل محاولات مبيعات بيان ومنع تكرار الإرسال

استكمال B033 وB035 وB036 وB037 وB041 وB065 فوق `cd88d9ee`، في 28 سبتمبر 2026.

## المشكلة والنتيجة

كانت الدالتان `enrollTrainee` و`createPaymentLink` تمنعان إعادة POST داخل الاستدعاء الواحد فقط. استدعاؤهما مجددًا بعد انقطاع الرد أو تعطل تتبع النتيجة كان يستطيع إرسال تسجيل أو فاتورة أخرى إلى المزوّد.

أصبح الاستدعاء يتطلب `requestId` ثابتًا للعملية، مشتقًا لاحقًا من الاتفاق المحفوظ عند توصيله بالمحادثة. الطلب بلا هوية صالحة يُرفض قبل الشبكة. يحفظ الجدول الجديد `byaan_sales_operations` هوية الطلب ونوع العملية وبصمة المدخلات وهوية الاتصال والصلاحية ورمز المحاولة. لا يحفظ رقم الهاتف أو الاسم أو سر الاتصال في صف المحاولة؛ تحفظ النتيجة المقروءة مع رابطها ومرجعها لأجل الإعادة.

القيد الفريد `(merchant_id, request_id)` يشمل التسجيل والدفع معًا. تغيير المبلغ أو الدورة أو العميل أو نوع العملية مع إعادة استعمال المعرّف لا يرسل شيئًا ولا يعيد نتيجة الطلب الآخر. يبقى استخدام معرّف جديد عملية مختلفة؛ لا يجوز توليده تلقائيًا لإعادة محاولة عملية مجهولة.

## دورة التنفيذ

1. التحقق من المدخلات وتثبيت نسخة منها قبل أول انتظار.
2. داخل معاملة SQL: تثبيت نشاط التاجر ومالكه واتصال بيان، ثم حجز الطلب أو قراءة محاولته السابقة.
3. تجهيز الاتصال وحل DNS وفحص الصلاحيات الحالية.
4. داخل معاملة ثانية: مقارنة اتصال الإرسال بالاتصال المحجوز وتغيير `preparing` إلى `dispatching` قبل POST. فقد تأكيد هذه المعاملة لا يسمح بالإرسال.
5. قراءة رد المزوّد والتحقق منه وتتبع البلاغ محليًا وفق العقد السابق.
6. حفظ النتيجة وبصمتها. الإعادة ترجع النتيجة المحفوظة بعد فحص الهوية والصلاحيات والبصمة، دون HTTP أو DNS جديد.

لا يبقى قفل قاعدة البيانات مفتوحًا أثناء HTTP. الطلبات المتزامنة للعملية نفسها ترى المحاولة القائمة؛ واحد فقط يستطيع الانتقال إلى الإرسال. لا توجد مهلة تعيد تفعيل `dispatching`، ولا استعادة تلقائية لـ`preparing` بعد تعطل العامل.

| الحالة | ما يحدث عند إعادة الطلب |
| --- | --- |
| `preparing` أو `dispatching` | نتيجة مجهولة للمراجعة، دون استحواذ جديد أو POST |
| `not_sent` | إعادة الفشل المحفوظ قبل الإرسال، دون محاولة جديدة |
| `unknown` | إعادة حالة المراجعة دون POST |
| `reported` | إعادة الإقرار المحفوظ مع `operationId` و`replayed: true` |

إذا تعطل حفظ النتيجة بعد إرسال الطلب، تبقى المحاولة مانعة لإعادة الإرسال. إذا حُفظت النتيجة وضاع تأكيد commit، تستطيع إعادة الطلب قراءتها. إذا تعطل حجز البداية وتراجعت المعاملة فعلًا قبل أي إرسال، تستطيع محاولة لاحقة حجزها. الاتصالات ذات commit المجهول تتلف ولا تعود إلى مجمع الاتصالات.

## سلامة النتيجة وعزل الصلاحيات

ترتبط بصمة النتيجة بهوية المحاولة والنشاط والطلب ونوعه والمدخلات والاتصال. تعديل النتيجة أو رمز المحاولة أو حذف سجل التحويل/تاريخه يمنع إعادة نجاح متناقض. عند وجود `tracking: recorded` يُفحص سجل التحويل وتاريخه وتطابق بياناته مع الطلب قبل الإعادة.

تبديل اتصال بيان أو سره أو نطاقه يمنع استعمال العملية القديمة. تعليق النشاط أو المالك يمنع إعادة النتيجة. تحفظ النتيجة التاريخية بعد الرد حتى لو تغير النشاط أثناء HTTP، مع ظهور فشل التتبع إن وقع. إعادة تفعيل النشاط لا تؤدي لإرسال POST ثانٍ.

هذه بصمات لاكتشاف عدم الاتساق، وليست حماية من مسؤول قاعدة بيانات يستطيع إعادة كتابة الأدلة كلها. لا تمنع حذف بيانات النشاط المصرح به أو استدعاءات خارج هذا المسار في إصدار قديم؛ يلزم اعتماد تشغيلي للإصدار قبل إتاحة مبيعات بيان آليًا.

## الترحيل والتحقق

أضيف `0148_byaan_sales_operations`: جدول إضافي دون backfill أو تعديل بلاغات التحويل القديمة. أُضيف إلى فحص جاهزية المخطط. بوابة الترحيل تختبر قاعدة جديدة، وترقية من 0147، وإعادة DDL قبل تسجيله، وإعادة التشغيل، وقيد الطلب الفريد وقيود الحالات والبصمات.

نجح **312 اختبارًا**: 220 للوحدات والأمن في 15 ملفًا، و92 على MySQL في ثلاثة ملفات، دون فشل أو تخطٍّ. منها 36 حالة SQL جديدة للتزامن والإعادة وفقد commit وفساد النتيجة وتغير الصلاحيات وعزل الأنشطة. نجح فحص الأنواع والمخطط والبناء و7996 استدعاء ترجمة و311 مفتاحًا ديناميكيًا. اجتازت الترحيلات الـ149 مساري الإنشاء والترقية والإعادة. [نتائج التحقق وبصمات المصدر](./audits/sales-brain-implementation-2026-09-23/byaan-sales-operations-verification.json). لم يُعد فحص المتصفح لهذه الدفعة التي لا تغيّر الواجهات.

كل بيانات SQL مصطنعة ومحلية؛ HTTP وDNS للمزوّد محاكيان والشبكة الخارجية محجوبة. لا اختبار دفع أو تسجيل حي ولا رسائل للعملاء. لا تغيير واجهة أو مفتاح ترجمة؛ لا حاجة لترحيل بيانات الترجمة.

## ما لم يُغلق بعد

هذا الحارس يحمي الدالتين القائمتين بمعرّف عملية ثابت. لا توجد استدعاءات إنتاجية جديدة لهما من واتساب في هذه الدفعة. يبقى توصيل المعرّف باتفاق وموافقة وعميل محفوظين، وعرض الحالات المحتاجة للمراجعة، وتسويتها بعقد موثوق مع بيان. لم يُفترض وجود endpoint استعلام أو مفتاح idempotency لدى المزوّد.

لا يعني `reported` شراءً أو قبضًا مثبتًا؛ التسجيل يظل بلاغ تسجيل، والرابط بلاغ دفع معلق. تبقى العملة وعلاقة التسجيل بالفاتورة والتحصيل والاسترداد ومنع الازدواج مع Tap بوابات قبل إدخالها في تعلم المبيعات. حالة المصفوفة **4 مكتملة / 62 جزئية / 5 مفتوحة**؛ لا اعتماد 10/10 أو نشر للإنتاج.
