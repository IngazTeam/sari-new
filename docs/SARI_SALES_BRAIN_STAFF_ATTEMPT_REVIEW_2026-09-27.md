# سجل ردود الموظف والتحقق منها دون إعادة الإرسال

التاريخ: 27 سبتمبر 2026. أساس الدفعة: `827bd23b`. تكمل [تسوية نتائج التوافق](./SARI_SALES_BRAIN_COMPATIBILITY_SETTLEMENT_2026-09-27.md) ضمن [خطة الإصلاح](./SARI_SALES_BRAIN_10_OF_10_PLAN_2026-09-23.md).

## المشكلة والنتيجة

كانت إعادة التحقق من محاولة الرد تمر بمدخلات الإرسال الأصلية. بالنسبة للصوت، يتطلب ذلك التسجيل الموجود في ذاكرة التبويب؛ تحديث الصفحة أو إغلاقها يفقده رغم أن المحاولة ودليل النقل قد حُفظا على الخادم.

أضيف إلى صفحة المحادثات قسم **«سجل ردودي والتحقق من الإرسال»**. يعرض محاولات المستخدم الحالي في المحادثة، مع فصل النص والصوت وتصفح 20 محاولة في الصفحة. زر **«تحقق من النتيجة»** يراجع المحاولة المخزنة بهويتها فقط. لا يطلب النص أو التسجيل، ولا يستدعي الحجز أو رفع الملفات أو المزوّد.

| الحالة | العرض والتصرف |
|---|---|
| نتيجة غير محسومة | يمكن التحقق من الدليل الموجود؛ لا نجاح مفترض أو إرسال جديد |
| قبول إرسال محفوظ | تظهر النتيجة دون زر لإعادة الإرسال؛ قبول النقل لا يثبت التسليم أو القراءة أو البيع |
| قبول محفوظ دون إسقاط رسالة | توضيح أن قبول النقل محفوظ لكن الرسالة لم تُحفظ في المحادثة |
| عقد المحاولة أو بصمتها غير صالح، أو دليلها متعارض | حالة تحتاج إلى مراجعة دون إجراء يفرض النجاح |
| خطأ أثناء التحقق أو استجابة غير صالحة | رسالة عامة، وتعطيل إعادة التحقق حتى تحديث السجل بنجاح |
| اتصال قديم بلا outbox أو تاريخ v1 غير محسوم | تظهر المحاولة وتبقى غير محسومة؛ لا اختراع لدليل نقل |

التاريخ المعروض هو **وقت إنشاء المحاولة**، وليس وقت تسليم المزوّد. نتيجة الحفظ المسجلة تصف الإسقاط السابق؛ حذف رسالة بعد ذلك لا يجعل التحقق يعيد إنشاءها.

## الصلاحيات وربط الدليل

- أضيف مسارا `listStaffAttempts` و`checkStaffAttempt` إلى راوتر المحادثات الرئيسي والموازي بإجراءات مشتركة. يستخرجان التاجر والموظف من الجلسة، ويشترطان صلاحية الرد. لا يقبلان هوية تاجر أو موظف أو محتوى أو رابط ملف من المتصفح.
- يقرأ السجل محاولات الموظف نفسه فقط، حتى إذا كان القارئ مديرًا أو مالكًا. لا يستولي مستخدم مخوّل على محاولة موظف آخر. لا تتغير سياسة العامل الداخلي القائمة؛ واجهة التحقق البشرية تمر بتحقق إضافي من الفاعل.
- تتحقق قاعدة البيانات من نشاط التاجر والمستخدم والعضوية الحالية. بعد القراءة الأولى يعاد فحص الصلاحيات وربط الموظف والمحادثة داخل **معاملة الحفظ نفسها**. سحب الصلاحية أو تغيير هوية المصدر بين الخطوتين يمنع التسوية.
- يُتحقق من عقود المحاولة وبصماتها قبل عرض الحالة. لا يكفي وضع `accepted` في صف SQL للرد المسجل؛ يجب وجود واقعة قبول صالحة تطابق أساس المحاولة والإيصال. نتائج التوافق السابقة تُقرأ وفق عقدها القائم، دون ترقيتها إلى قبول بيعي مقاس.
- يعرض API معرف المحاولة ووقت إنشائها وحالتها ونتيجة الإسقاط فقط؛ لا يعرض نص الرسالة أو التسجيل أو رابط الوسائط أو رقم العميل أو مفاتيح واتساب أو UUID الإرسال.
- التصفح بمؤشر معرف قبل آخر عنصر، لكل نوع على حدة، مع حد ثابت. لا يسمح العميل برفع الحد أو تمرير مؤشرات سالبة أو حقول إضافية. استجابة العرض نفسها مقيدة بعقد يمنع الترتيب غير الصحيح والحقول الزائدة والنتيجة المتناقضة.
- لا تعيد المراجعة تفعيل ملكية الموظف للمحادثة أو تمديد إيقاف الروبوت. لا تدخل ضمن استجابة الإرسال التجارية للنموذج أو تعلّم نتائج المبيعات.

## سلوك الواجهة

التحميل عند فتح القسم، مع حالات تحميل وفراغ وخطأ وتحديث وصفحات أقدم. تحافظ الواجهة على ربط كل استعلام وإجراء بالمحادثة والنوع والمصدر. تغيير المحادثة أو النوع أثناء التحقق لا ينقل نتيجته إلى العرض الجديد. يمنع قفل فوري الضغط المتكرر، ولا يعاد تنفيذ mutation تلقائيًا.

النصوص عربية وإنجليزية بمفاتيح مستقلة، مع أزرار لمس 44 بكسل، وتدفق RTL، وتنقل لوحة المفاتيح، وإعلان النتيجة عبر `role=status`. لا يُحفظ التسجيل أو محتواه في تخزين المتصفح لأجل التحقق. استمرار السجل مصدره الخادم، لا ذاكرة التبويب.

## التحقق

نجحت **2,759 حالة دون فشل أو تخطٍ**: 1,533 للعقود والصلاحيات والأمان و1,226 على MySQL. تتضمن 58 حالة جديدة للعقود ومساري API و82 حالة MySQL جديدة للنص والصوت عبر الحساب المسجل والمجموعات والاتصال القديم. تغطي سحب الصلاحية بين القراءة والحفظ وتغيير المصدر بلقطة متسقة والتنافس وفقد إقرار الحفظ وحذف المحادثة وفساد الدليل والتصفح والعزل، مع ثبات عدد استدعاءات الرفع والنقل.

نجحت **365 رحلة متصفح**: 38 للسجل الجديد و327 للمحادثات والرد النصي والصوتي وتقرير التجربة وأدلة الطلبات السابقة. شمل التحقق العربية والإنجليزية وعروض 320 و375 و430 و1440، وإعادة التحميل دون تسجيل أصلي، والضغط المتكرر، والاستجابة المتأخرة أثناء تبديل المحادثة والنوع، وسحب الصلاحية، وصفحات أقدم، والخطأ والبيانات المتناقضة ولوحة المفاتيح. لا جهاز iPhone أو Safari فعلي.

نجحت الأنواع والبناء وفحص **7,522 استدعاء ترجمة و248 مفتاحًا ديناميكيًا** دون مفاتيح مفقودة أو أخطاء متغيرات. نجحت 9 اختبارات لحارس النشر، وفحص سجل الترحيلات، وقاعدة جديدة حتى 133 ترحيلًا وترقية 0131→0132. ثبتت بصمات **1,985 ملف مصدر** قبل التحقق وبعده وعند حفظ الأدلة.

بدأت محاولة البوابة الأولى قبل اكتمال تهيئة خادم الترحيلات المحلي فرفض الاتصال. أُعيدت بعد تأكيد جاهزيته، دون تعديل اختبار أو عتبة. نتائج الدفعة المرفقة تخص التشغيل المكتمل.

كشف تشغيل الواجهة انتظارًا غير كافٍ بعد سحب الصلاحية: كان الاختبار يفحص العنصر قبل اكتمال تحديث React. ضُبط الانتظار على اختفاء الأزرار وظهور رفض التحميل فعليًا، وعلى ظهور صفحة النتائج المطلوبة بعد التصفح. بقي شرط منع الوصول كما هو، وأُعيد التحقق بعد تعديل أداة الفحص.

## النشر والتراجع والمتبقي

لا ترحيل جديد؛ يبقى المخطط حتى `0132`. لا تغيير في سقف المنصة اليومي 100 دولار أو اختيار مزوّد الذكاء الاصطناعي. يستخدم التحقق عقود التسوية القائمة، ولا يضيف صيغة تخزين جديدة لهذه الدفعة. يحتاج نشر الواجهة والخادم معًا؛ واجهة جديدة أمام خادم قديم ستعرض خطأ تحميل ولا تعود إلى إرسال المحتوى تلقائيًا.

المتبقي الأقرب: سجل نقل دائم للاتصال القديم، ومراجعة إدارية عابرة للمحادثات أو لموظف غادر العمل بصلاحيات وتدقيق مخصصين، وسياسة معالجة الدليل المتعارض والرفض، وتنظيف ملفات الرفع غير المرتبطة. القسم الحالي خاص بمحاولات المستخدم في محادثته المختارة؛ لا يوفر تجاوزًا لملكية المحاولة أو زر نجاح يدويًا.

مصفوفة الخطة تبقى **4 مكتملة / 59 جزئية / 8 مفتوحة**. هذا تحقق هندسي محلي للمسارات المتأثرة، وليس اعتمادًا تجاريًا 10/10 أو اختبار اختراق إنتاجي مستقل. لم يُختبر iPhone فعلي أو مزوّد واتساب حي، ولم تُدفع التغييرات أو تُنشر على الإنتاج.
