# تسوية محاولات Tap المحلية الغامضة

التاريخ: 24 سبتمبر 2026. أساس هذه الدفعة: `5e4d754`. النطاق: الطلب المحلي الذي يملك محاولة محفوظة في `order_checkout_attempts`؛ لا تعميم على الحجوزات والروابط العامة. لم يُنفذ نشر أو تحصيل أو اتصال بمزوّد فعلي أو إرسال لعملاء.

**الخطة مستمرة: 4 بنود مكتملة، 55 جزئية، 12 غير مغلقة.** هذه الدفعة تطور B035 وB037 وB057 وB064 وB065، ولا تمنح اعتماد 10/10. ## المشكلة والنتيجة

قد يقبل Tap إنشاء الجلسة ثم يفقد التطبيق الرد قبل حفظ `order_payments`. سجل المحاولة المسبق يمنع دفعًا جديدًا لكنه كان يترك الموظف دون أداة مطابقة. أصبح للموظف المخول استرجاع عملية محددة من لوحة Tap، ثم تثبيت نتيجتها إذا أثبت الخادم علاقتها بالمحاولة الأصلية.

المسار هو GET واحد إلى عنوان Tap ثابت باستخدام مفتاح التاجر؛ لا ينشئ جلسة، ولا يشحن أو يسترد مبلغًا، ولا يرسل واتساب. توثق Tap الاسترجاع بواسطة charge ID في [Retrieve a Charge](https://developers.tap.company/reference/retrieve-a-charges)، وتعرض حقول هوية العملية والمرجع والعميل والنمط في [Charges](https://developers.tap.company/reference/charges). الاختبارات تستخدم استجابات مصطنعة مطابقة للعقد؛ لم تُثبت استجابة حساب إنتاجي حي.

## التنفيذ ومعايير المطابقة

1. يستمد المسار التاجر والمراجع من الجلسة والعضوية، ويتطلب `orders.manage`. لا يقبل التاجر أو المراجع أو السعر أو الحالة المالية من المتصفح. يقبل معرّف الطلب والمحاولة وcharge وبصمة الدليل ومراجعة صريحة فقط.
2. يقرأ الخادم الطلب ثم المحاولة والرابط والدفع المرتبط تحت أقفال. يشترط ملكية محلية واحدة وهوية مالية متطابقة. لا توجد شبكة أثناء الاحتفاظ بالأقفال. المحاولة `dispatching` تحتاج مرور دقيقتين بحسب ساعة قاعدة البيانات بعد انتظار الأقفال.
3. يُسترجع charge من `/v2/charges/{id}` فقط. يمنع تركيب URL أو مسار من المستخدم، والتحويل إلى نطاق آخر، والردود الأكبر من 256 KiB، والمهلة فوق 10 ثوانٍ. أخطاء النقل لا تعرض بيانات المزوّد أو المفتاح للواجهة.
4. يطابق الخادم معرّف العملية ونوعها، `reference.transaction` و`reference.order` و`metadata.udf1` مع المرجع المحفوظ، والعملة SAR، والمبلغ بدقة الهللة دون تقريب صامت، و`live_mode` مع وضع الحساب.
5. تعاد بناء بصمة الطلب الأصلية من الدافع المسترجع ووصف وسياق الرابط والمبلغ وهوية الطلب وبصمة مفتاح Tap والنمط. تغيير الدافع أو الحساب أو سياق الرابط يمنع المطابقة. ترتيب حقول البصمة القديمة محفوظ ومختبر حتى لا تُرفض المحاولات المنشأة قبل الترحيل.
6. بعد GET يعاد قفل السجل ومقارنة الدليل كاملًا، بما فيه الدفع وحالة الطلب ومراجعة المحاولة. webhook أو إلغاء أو مراجعة متزامنة أثناء الشبكة يُبطل الدليل القديم؛ يجب تحديثه ومراجعته.
7. النجاح يحفظ الدفع المسترجع، وتحويل الحالة، وحالة الطلب، وعدادات الرابط، وذاكرة الشراء والتعلم الموثق، وربط المحاولة، وسجل المراجعة في معاملة SQL واحدة. أُعيد استخدام منطق تحويل دفع Tap نفسه داخل معاملة يملكها المستدعي؛ لا نسخة مستقلة من قواعد التحصيل.
8. يسجل audit المراجع والوقت ورقم المراجعة وcharge والنتيجة والسبب المحدود وبصمة الإثبات. لا يحفظ استجابة Tap الخام أو المفتاح أو بيانات الدافع في audit؛ تذهب حقول الدافع اللازمة إلى سجل الدفع المحلي المعتاد. القراءة في واجهة الطلب لا تعرض هذه البيانات أو بصمة طلب الدفع الأصلية.

## حالات الفشل وحدود الاستعادة

| الحالة | النتيجة |
|---|---|
| CAPTURED مطابق | تثبيت الدفع وذاكرة الشراء مرة واحدة؛ لا ادعاء أن إنشاء الجلسة نفسه تحصيل |
| INITIATED أو AUTHORIZED | يبقى الطلب غير مدفوع ولا يُتعلم نجاح بيع |
| جلسة INITIATED لها URL ووقت إنشاء وصلاحية موثقة غير منتهية | يمكن إعادة استخدام الجلسة نفسها؛ الانتهاء محسوب من وقت إنشائها لدى Tap، ويُقرب لأسفل إلى دقة تخزين SQL |
| جلسة منتهية أو بلا عمر موثوق | لا يمنح الاسترجاع URL قابلاً لإعادة الاستخدام أو مهلة جديدة |
| FAILED/DECLINED/RESTRICTED أو CANCELLED/ABANDONED/VOID متطابق | تُثبت الحالة النهائية؛ إنشاء جلسة أخرى يتطلب طلب checkout صريحًا جديدًا وبقية شروط الأهلية |
| 404 أو مهلة أو خطأ شبكة أو هوية غير مطابقة | مراجعة غير محسومة؛ لا تحرير للحاجز ولا POST بديل |
| UNKNOWN أو TIMEDOUT أو حالة غير معروفة | لا تُستنتج منها صلاحية دفع جديد |
| REFUNDED بلا تحصيل محلي سابق | تبقى للمراجعة؛ لا اختلاق حدث CAPTURED لبناء تاريخ مالي مفقود |
| REFUNDED لدفع محلي captured/refunded | تطبيق الاسترداد المتحقق وآثاره مرة واحدة، دون طلب استرداد جديد من المزوّد |
| CAPTURED متأخر بعد استرداد محفوظ | لا يعيد الدفع إلى captured ولا ذاكرة الشراء إلى نجاح |
| فشل كتابة الدفع أو الطلب أو الذاكرة أو audit | تراجع كامل؛ لا نصف تسوية |
| commit نجح وفُقد تأكيده | يغلق الاتصال غير الموثوق؛ التحديث والمراجعة اللاحقان يقرآن النتيجة دون مضاعفة الأثر |
| POST الأصلي يعود بعد تسوية العملية | لا يضيف دفعًا ثانيًا ولا يستبدل `created` بـ`unknown` |

تغيير المفتاح أو تطبيع Tap لبيانات الدافع على نحو مختلف قد يمنع إعادة بناء البصمة؛ السلوك المقصود هو إبقاء الحالة للمراجعة، لا اعتماد تشابه الهاتف والمبلغ وحدهما. لا يوجد بحث تلقائي عن العملية إذا لم يتوفر charge ID.

## واجهة المراجعة

تعرض تفاصيل الطلب المحاولة والمبلغ والمرجع، ثم حقل charge وزرًا واضحًا للاسترجاع والمطابقة. لا ينشط الزر قبل صحة المعرف والمراجعة الصريحة؛ تغيير المعرف يلغي المراجعة. التعليق أثناء التنفيذ يمنع إعادة الإرسال وتحديث الدليل من الزر العام. بعد فشل المراجعة يجب تحديث السجل قبل محاولة أخرى. تعرض النتيجة غير المحسومة دون تحويلها إلى نجاح، وبعبارة تفرق بين المطابقة والتحصيل.

المحتوى عربي وإنجليزي، والحقول مسماة وقابلة للتنقل بلوحة المفاتيح، والمرجع الطويل يلتف، وعناصر الفعل بارتفاع لا يقل عن 44px. فحص المكونات مستقل عن تسجيل دخول إنتاجي وبيانات العملاء.

## التحقق والنشر

النتائج على نسخة مستقلة من الملفات المجهزة للكوميت، دون أسرار الإنتاج ومع حظر الشبكة الخارجية في الاختبارات:

- **4,036 حالة فريدة ناجحة، دون فشل أو تخطٍّ**. مجموع نتائج المجموعات **4,951** يشمل حالات مكررة بينها.
- Unit: 672، MySQL: 696، Regression: 956، Legacy sales: 229، Budget: 11، Security: 2,387.
- للدفعة الجديدة **55 اختبار تسوية فعلي على MySQL**، و24 فحصاً هجوميًا لعقد الاسترجاع والمدخلات، و11 حالة إضافية لصلاحيات المسار الحقيقي؛ تشمل الاختبارات المشتركة السابقة أثر الدفع والكوبون والذاكرة.
- نجح TypeScript والبناء وDrizzle check. فحص الترجمة: 6,085 استدعاء و220 مفتاحًا ديناميكيًا، بلا مفقود أو أخطاء interpolation أو حالات ديناميكية غير محسومة.
- **202 حالة واجهة ناجحة و26 صورة** للمكونات الفعلية في Chromium مع API مصطنع، بالعربية والإنجليزية بعروض 320 و375 و390 و768 و1440. لا أخطاء JavaScript، ولا تمرير أفقي أو مفاتيح خام في الحالات المفحوصة. راجعت [صورة المراجعة على الهاتف](./audits/sales-brain-implementation-2026-09-23/ui/checkout-reconciliation-375.png)؛ لا اعتماد Safari أو iPhone فعلي.
- **221 ملف مصدر** موثقة بصيغ SHA-256 وGit blob ومطابقة للنسخة المختبرة والفهرس قبل الكوميت. فحوص الأمان محلية سلوكية وتعاقدية وليست شهادة اختبار اختراق إنتاجي مستقل.

الترحيل `0079_checkout_reconciliation` مطبق على قاعدتي MySQL محليتين. طابقت بصمة SQL وسجل الترحيل وعمود الإصدار الافتراضي والقيد الفريد `(attempt_id, revision)` في القاعدتين. بصمة SQL المطبق محلياً بنهايات LF: `7af6a1b5165b8708a694dd0ed54756f17866d839dacbcf88c418295bf8990040`. نسخة Windows المستخرجة من الفهرس تستخدم CRLF لهذا الملف وبصمتها الخام `7d731529edf3f1df6dd89cf21c8cc32f1a5716888bff2e9b68172ab79a955474`؛ المحتوى متطابق بعد توحيد نهايات الأسطر، وهوية Git المفلترة واحدة. لا تعديل لسجل ترحيل مطبق.

قبل تشغيل الإصلاح في الإنتاج يلزم تطبيق الترحيلات حتى 0079 وتحديث الويب والعمال وإيقاف النسخ القديمة، ثم تجربة بحساب اختبار مخصص وتسجيل نتيجة GET الحقيقية بعد تنقيح البيانات. لا حذف للسجلات الغامضة ولا إعادتها إلى فشل أثناء الترقية. يظل اختيار المزوّد المركزي وسقف المنصة اليومي 100 دولار دون تغيير.

المتبقي المتصل بهذه الدفعة: سياسة تحرير استخدام الكوبون بعد إثبات انتهاء جميع الآثار المالية، وتسوية الحجوزات والروابط العامة والدفعات القديمة دون محاولة محفوظة، وربط بقية الموصلات، والتجربة الحية المصرح بها. أرقام الاختبارات لا تقيس زيادة التحويل أو جودة الإقناع لدى النموذج الحي.
